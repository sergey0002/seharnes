## Суть

Журнал фиксирует все правки панели `.doc/web` от 2026-11-03: переход на один сервис, встроенный просмотрщик харнеса, кнопки запуска скриптов, цены провайдеров, стоимость сессий и задач. Операционное описание панели остаётся в [README.md](./README.md), устройство сервиса в [22-panel-service.md](../harnes/state/22-panel-service.md).

## Что изменилось

### 1. Один сервис вместо двух

- Панель и просмотрщик харнеса работают на `http://127.0.0.1:8077`.
- Отдельный Python-сервер на 8090 и `harness-mirror.service` отключены.
- Сервис `copytrust-tools` собран из `php:8.4-cli` с `python3`, `bash`, `pwsh`, `git`. Node, CBM и CodeGraph в сервис не входят.
- Рабочая область монтируется по тому же абсолютному пути, что на хосте. Это нужно для `task-analytics` и `kilo.db`.
- Порт слушает только loopback. Запросы с чужим `Host` или `Origin` отклоняются.

Файлы: [compose.tools.yml](./compose.tools.yml), [Dockerfile.tools](./Dockerfile.tools), [start.sh](./start.sh), [stop.sh](./stop.sh), [service.json](./config/service.json).

### 2. Харнес-миррор внутри панели

Добавлены маршруты:

| Маршрут | Назначение |
|---|---|
| `/harness/` | просмотрщик графа |
| `/harness/graph.json` | граф |
| `/harness/nodes/*.json` | узлы |
| `/harness/api/health` | статус и `writable` |
| `/harness/api/node?id=...` | чтение узла, `PUT` для сохранения |
| `/harness/api/rebuild` | пересборка графа |

Сохранение идёт через `harness_mirror.py set`, затем `build` и `check`. Прямая запись файлов из PHP запрещена. Скрипты и зеркала через сохранение не редактируются. В шапку панели добавлена ссылка `Харнес`.

Файлы: [app/harness.php](./app/harness.php), [router.php](./router.php).

### 3. Кнопки и фоновые задания

- Реестр действий: [actions.json](./config/actions.json), схема [actions.schema.json](./config/actions.schema.json).
- Действия: `analytics_scan`, `harness_build`, `harness_check`, `sync_views`, `task_diff`.
- `POST /jobs` запускает задание, `GET /jobs/status` отдаёт статус и хвост лога, `POST /jobs/cancel` отменяет, `GET /jobs` показывает последние задания.
- AJAX работает без перезагрузки: прогресс по маркерам `PROGRESS`, `[n/m]`, `шаг N из M` или `progress_regex`; без маркеров полоса неопределённая.
- Задания выполняются отсоединённо. На действие один lock, лог до 5 МБ, секреты маскируются, таймаут убивает процесс.
- `build-actions.py` собирает черновик реестра из `skill.json`; скрипты не изменяются.

Файлы: [app/jobs.php](./app/jobs.php), [bin/job-runner.php](./bin/job-runner.php), [bin/build-actions.py](./bin/build-actions.py), [public/assets/app.js](./public/assets/app.js), [public/assets/style.css](./public/assets/style.css).

### 4. Цены и провайдеры

Цены вынесены в [prices.json](./config/prices.json) по провайдерам. Сейчас заполнен `ai-starimg-ru`:

- 30 000 000 внутренних токенов стоят 823.90 RUB;
- 1M внутренних токенов стоит 27.463333 RUB;
- коэффициент модели умножает вход, кэш и выход;
- кэш тарифицируется без скидки, `cached_discount: 1`;
- 44 модели с коэффициентами из каталога `ai.starimg.ru`;
- `codex-sale` и `kilo` описаны без цен: их сессии показываются, стоимость 0, ошибки нет.

Формула:

```text
стоимость = (вход + кэш + выход) * коэффициент * 0.000027463333
```

Примеры после пересчёта:

| Объект | Стоимость |
|---|---:|
| сессия `ses_e610e85adffetyEzpIP9A1Bvob` | 430.30 RUB |
| `gpt-6.1-sol` в этой сессии | 418.2496 RUB |
| `deepseek-v4.1-flash` в этой сессии | 12.0510 RUB |
| задача 2612 | 76.63 RUB |
| задача 2618 | 129.19 RUB |

Провайдер берётся из `session.model.providerID` в `kilo.db`. База открывается только на чтение. Провайдер показывается в таблице сессий, в блоке `Провайдеры` и на странице диалога без задачи. Это провайдер последней модели сессии; в базе есть провайдер каждого сообщения, но панель его не агрегирует.

Файлы: [app/pricing.php](./app/pricing.php), [app/providers.php](./app/providers.php), [config/prices.local.example.json](./config/prices.local.example.json).

### 7. Фильтр диалогов по проекту

- В форму правого меню добавлен select "Проект диалогов". Он фильтрует список диалогов без задачи.
- Источник проекта: `kilo.db`, таблицы `session` и `project`; проект берется по `session.project_id`, подпись из `project.name`, иначе последний сегмент пути `project.worktree`.
- Выбор запоминается в cookie `panel_project` на 180 дней и восстанавливается при следующем открытии панели. Пустое значение удаляет cookie.
- При выборе проекта чекбокс "Диалоги без задач" включается автоматически.
- Название проекта показано в строке диалога и в таблице метрик страницы сессии, поиск по списку учитывает проект.
- Если `kilo.db` недоступен, select показывает только "все", остальные фильтры работают как раньше.

Файлы: [app/lib.php](./app/lib.php), [public/index.php](./public/index.php), [public/assets/app.js](./public/assets/app.js).

## Известные проблемы и ограничения

### П-1: Стоимость это оценка по локальным токенам

Панель считает стоимость по токенам из артефактов `task-analytics` и цене провайдера. Провайдерский лог может группировать запросы иначе, поэтому точная сумма для сессии может отличаться. Для точного совпадения нужен импорт экспорта логов провайдера, сейчас его нет.

### П-2: Пакет токенов задан как 30 000 000

В конфиге стоит `balance.tokens: 30000000`, потому что при 300 000 сессия выходит около 42 973 RUB и не сходится с балансом. Если в кабинете провайдера 300 000, поменяйте `balance.tokens` на `300000`; все цены пересчитаются.

### П-3: Провайдер сессии один

Провайдер берётся из последней модели сессии. Если внутри диалога провайдер менялся, панель покажет последний, а не разбивку по сообщениям.

### П-4: Один экземпляр на проект

Сервис обслуживает один `WORKSPACE_ROOT`. Несколько проектов требуют нескольких экземпляров или отдельного реестра рабочих областей.

### П-5: `php -S` не production

Встроенный сервер работает с воркерами, но задания всё равно запускаются отсоединённо. При росте нагрузки нужен PHP-FPM или Apache.
