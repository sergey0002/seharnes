# Панель документации (.doc/web)

> Архив (2026-11-13): PowerShell-экспорт удалён. Активный механизм `harness_transfer.py`, режимы `harness | harness-docs | project`; канон — `.doc/harnes/state/14-project-migration.md`. Ниже сохранена история старой процедуры.

Сервис `copytrust-tools`: единая панель задач, документации, аналитики диалогов и просмотрщика харнеса. Один PHP-процесс на `127.0.0.1:8077`, без БД и без ИИ. Панель читает JSON/MD из `.doc` и `.cursor/.state`, а изменяющие действия запускает только через разрешённый список скриптов.

## Что показывает

| Вкладка | Источник | Как собрано |
|---|---|---|
| Задачи (правое меню) | `.doc/tasks/*/task.json` | список: id + title + release + счетчики; клик - страница задачи |
| Страница задачи | `task.json` + `task.md` + `diff.files.md` + `reports/*/workflow-context.json` | секции из JSON (как отчет change-report: оглавление + рендер), файлы, находки, дифф, отчеты со свежестью |
| Документация (правое меню) | `.doc/architecture/*.json`, `.doc/architecture/*.md`, `.doc/harnes/**/*.md` | список сгруппирован по источникам: title + путь; клик - документ: секции, файлы, находки, для md - оглавление по `##`/`###` и рендер тела |
| Аналитика диалогов (на странице Задачи) | `.doc/tasks/*/dialogs/`, `.doc/task-analytics/out/` | KPI, графики Chart.js, токены по MCP-серверам и моделям, таблица задач с диалогами; подчиняется фильтрам правого меню |
| Диалоги задачи | `dialogs/index.json` + `dialogs/ses_*.json` | KPI, графики токенов/инструментов/находок, MCP и модели по токенам, таблица сессий; блок сворачиваемый |
| Лента активности | `task.json` -> `tracker.snapshot.comments/changelog` | таймлайн: комментарии и изменения полей Jira с датами и авторами |
| Бизнес-аналитика | `reports/change-report/report-model.json` | проблема, решение, результат, было/стало/дельта, изменения, ссылка на полный HTML `/report/{N}` |
| Диалоги без задачи | `.doc/task-analytics/out/unassigned/ses_*.json` | чекбокс в фильтре, по умолчанию выключен: сессии без привязки к задаче и страница их метрик без ИИ |
| Фильтр по релизу | `metadata.release` из task.json | select в правом меню, серверный через форму + GET |
| Фильтр по ответственному | `tracker.snapshot.assignee`, fallback `\| Assignee \|` из task.md | select с уникальными именами и количеством задач |
| Фильтр диалогов по проекту | `kilo.db`: `session.project_id`, `project.worktree`, `project.name` | select "Проект диалогов" в правом меню; выбор запоминается в cookie `panel_project` на 180 дней |
| Статус и ответственный в списке | `tracker.snapshot.status.name`, `assignee` | бейдж статуса у номера, строка "отв. Имя" в карточке |

Список задач сортируется по свежести: `max(Jira updated, локальный mtime)`.
Jira updated берется из `task.json` -> `tracker.snapshot.updated_at`; для старых
задач без этого поля - из строки `| Updated | dd.mm.yyyy HH:MM UTC |` в `task.md`. Локальная дата - максимум mtime по `task.md`,
`task.json`, `doc.md`, `plan.md`, `diff*.md`, `test.md`, `_dialogs/*`,
`dialogs/index.json`, `stage*/plan.md` и отчетам. В правом меню видно обе даты,
на странице задачи - строки "Jira created", "Jira updated", "Локальное изменение".
Все даты в формате `дд.мм.гггг чч:мм:сс`, Jira-даты помечены `UTC`. Статус в шапке
берется из Jira (`tracker.snapshot.status.name`), для старых задач - из строки
`| State |` в `task.md`. Лента активности и бизнес-аналитика - отдельные блоки.

Страница задачи собирается по той же логике, что отчет change-report:
оглавление секций, рендер `body_markdown`, таблицы файлов, бейджи свежести
источников (`fresh` / `stale` / `missing` / `no-hash` по сверке SHA-256 из
`workflow-context.json` с текущими файлами на диске).

## Новый каркас `/panel/`

С 2026-11-13 у панели два контура. Старые маршруты (`/`, `/index.php?tab=docs`, `/harness/`,
`/harness-admin/`, `/jobs`) работают без изменений, а раздел, перенесённый целиком, получает
свой адрес под `/panel/`:

| Маршрут | Раздел | Состояние |
|---|---|---|
| `/` | отдаёт граф нового каркаса без редиректа (один запрос, работает в предпросмотре) | новый каркас |
| `/harness/` | старый просмотрщик зеркала — образец; сверху зелёная плашка со ссылкой на `/panel/graph` | старый интерфейс |
| `/index.php`, `/tasks`, `/docs`, `/analytics`, `/task/{N}` | старая панель (образец), других путей у неё нет | старый интерфейс |
| прочие адреса | 404 «Страница не найдена» со ссылкой на `/panel/graph` | роутер |

Быстрая проверка, что открыта именно эта панель: `GET /panel/api/health` отдаёт
`{"status":"ok","service":{"profile":"full","writable":true,"lang":"ru","php":"8.4.27"},"data":{"graph":true}}`.

| `/panel` | редирект на `/panel/graph` | новый каркас |

Экран собирается по одному канону: верхнее меню разделов → панель кнопок раздела → рабочая

умолчанию), языки `ru` и `en`, на узком экране левая панель становится выдвижной.

Устройство слоёв, контракт API и правила добавления раздела — в
[27-panel-architecture.md](../harnes/state/27-panel-architecture.md).

## Запуск (WSL)

```bash
cd .doc/web
./install.sh --check
./install.sh --project
./start.sh                    # http://127.0.0.1:8077/
WEB_PANEL_PORT=8090 ./start.sh  # другой порт
./stop.sh
```

`install.sh --project` создаёт `state/`, `ADAPTERS.local.md` и `.env` с `SERVICE_WORKSPACE`, `HOST_UID`, `HOST_GID`, `KILO_DATA_DIR`. Рабочая область монтируется в контейнер по тому же абсолютному пути, что на хосте, поэтому пути Kilo DB и задачи совпадают.

Установщик берёт профиль из `.doc/.rebase-kit.json`, если файл существует;
иначе из `config/service.json`. Допустимы `core` и `full` без учёта регистра.
Некорректный профиль останавливает `--project` до создания файлов. Профиль не
определяется по наличию каталога `task-diff`.

## Как работает

1. `start.sh` поднимает контейнер `copytrust-tools` из `compose.tools.yml` на `127.0.0.1:8077`. Образ `php:8.4-cli` содержит `python3`, `bash`, `pwsh`; CBM, CodeGraph и node в сервис не входят.
   Корень проекта монтируется `rw` по абсолютному пути хоста. Запись ограничена разрешёнными действиями и API харнес-миррора.
2. `router.php` отдаёт страницы, статику, `/harness/` и `/jobs`; неизвестные пути ведут в `public/index.php`.
3. `app/lib.php` читает JSON только внутри `.doc` (проверка `doc_contained`),
   хеширует источники отчетов только внутри корня репо (`repo_contained`).
   Наружу отдаются только тексты из `.doc`, пути кода - без содержимого.
4. `public/index.php` рендерит layout: контент слева, правое меню справа
   (вкладки Задачи / Документация, фильтры проекта, релиза, ответственного, поиск).
5. `body_markdown` рендерится встроенным `md_render` (заголовки, списки,
   таблицы, код, ссылки). Внешние ссылки только `http/https/mailto/#//`,
   остальное выводится текстом.

## Харнес-миррор

Просмотрщик открывается по `/harness/` и читает `.doc/skil_data/mirror`. Адреса `graph.json`, `nodes/`, `api/health`, `api/node` относительные, поэтому работают под префиксом панели.

- `GET /harness/api/health` возвращает `status`, `writable` и статистику графа;
- `GET /harness/api/node?id=...` возвращает узел;
- `PUT /harness/api/node?id=...` сохраняет правило или скил через `harness_mirror.py set`, затем `build` и `check`;
- `POST /harness/api/rebuild` пересобирает граф.

Отдельный Python-сервер на 8090 и юнит `harness-mirror.service` больше не используются.

## Действия, AJAX и прогресс

Кнопки берутся из `config/actions.json`. Локальные дополнения кладутся в `config/actions.local.json`, файл не переносится.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/jobs` | запуск действия, ответ 202 и id |
| `GET` | `/jobs/status?id=` | статус, прогресс, хвост лога |
| `POST` | `/jobs/cancel` | отмена группы процессов |
| `GET` | `/jobs` | последние задания |

Скрипты не изменяются: панель формирует argv и запускает `.py`, `.sh`, `.ps1` как есть. Прогресс берётся из маркеров `PROGRESS 42`, `[70/166]`, `шаг 3 из 10` или `progress_regex` действия. Если маркеров нет, полоса неопределённая, процент не выдумывается. Задания выполняются отсоединённо, лог ограничен 5 МБ, секреты маскируются, на действие один lock.

В Harness Mirror кнопка «Проверить структуру и мусор» запускает только строгую проверку структуры. Найденные пути попадают в лог задания и приводят к ошибке; файлы не удаляются. Это не сравнение с релизным manifest и не полный аудит харнеса.

## Безопасность

- по умолчанию сервис слушает `127.0.0.1`; при работе за обратным прокси (проброс порта, предпросмотр) `Host` бывает внешним и не блокируется;
- встроенный предпросмотр открывает панель в iframe с `sandbox="allow-scripts"` (источник `null`). Поэтому статика и API отдаются с `Access-Control-Allow-Origin: *`, а `OriginGuard` пропускает `Origin: null`; без этого ES-модули не грузятся и страница остаётся на «Загрузка…»;
- `Origin` обязан совпадать с хостом запроса, если заголовок присутствует; чужой `Origin` отклоняется (`origin not allowed`, 403);
- изменяющие запросы требуют `X-Requested-With` и идут только POST или PUT;
- действия только из реестра, пути проверяются на выход за корень;
- запись канона идёт через `harness_mirror.py` с историей и обратным чтением;
- `state/`, `.env`, `ADAPTERS.local.md`, `actions.local.json` не переносятся.

## Цены и провайдеры

Цены лежат в `config/prices.json` и задаются отдельно для каждого провайдера. Сейчас заполнен `ai-starimg-ru`: 300 000 000 внутренних токенов стоят 823.90 RUB, значит 1M внутренних токенов стоит 2.746333 RUB. Коэффициент модели умножает вход, кэш и выход, кэш без скидки (`cached_discount: 1`):

```json
"ai-starimg-ru": {
  "token_price": 0.000027463333,
  "models": {
    "deepseek-v4.1-flash": {"coefficient": 0.1, "input": 0.274633333, "output": 0.274633333, "cache_read": 0.274633333, "cache_write": 0.274633333}
  }
}
```

Формула для ai.starimg.ru: `стоимость = (вход + кэш + выход) * коэффициент * 0.000027463333`. Если провайдер или модель не описаны, стоимость не считается и ошибки нет. Локальные цены кладутся в `config/prices.local.json`, файл не переносится. Шаблон: `prices.local.example.json`.

Если пакет провайдера изменится, поменяйте `balance.tokens` и `balance.rub` в `prices.json`; панель пересчитает цену за 1M и все стоимости.

Провайдер берётся из `session.model.providerID` в `kilo.db` и показывается в таблице сессий, в блоке `Провайдеры` и на странице диалога без задачи. Это провайдер последней модели сессии. Если сессия меняла провайдера внутри диалога, в базе есть провайдер каждого сообщения, но панель показывает провайдер сессии.

В правом меню стоимость задачи выводится отдельным выделенным бейджем под токенами. В списке диалогов без задачи стоимость стоит в строке метрик каждой карточки.

## Раскрывающиеся таблицы

В блоке диалогов строки таблиц `Инструменты` и `MCP` раскрываются по клику. Строка `bash` показывает команды CLI с числом вызовов, токенами и стоимостью, строка MCP-сервера показывает его инструменты отдельными строками. Стоимость инструмента MCP распределяется по числу вызовов. Отдельный дублирующий блок `Bash` убран, команды видны в раскрытой строке `bash`. Повторный клик сворачивает детали. Работает с клавиатуры: `Enter` и `Space` на выбранной строке.

## Аналитика диалогов

Блок "Аналитика диалогов" на странице Задачи и блок "Диалоги и метрики" на странице задачи читают
артефакты `task-analytics`:

- `.doc/tasks/{N}/dialogs/index.json` - сессии задачи, токены, роли;
- `.doc/tasks/{N}/dialogs/ses_*.json` - инструменты, находки, MCP, время;
- `.doc/tasks/{N}/_dialogs/plan-state.json` - статус плана;
- `.doc/task-analytics/out/unassigned/` - сессии без задачи;
- `.doc/task-analytics/out/state/manifest.json` - время последнего прогона.

Аналитика подчиняется фильтрам правого меню. Задачи отбираются по релизу,
ответственному и поиску, диалоги задач и диалоги без задачи дополнительно
фильтруются по проекту. Порядок полей фильтра: проект, релиз, ответственный,
поиск, диалоги без задач.

Таблица "Диалоги без задачи" внизу отчета показывает до 30 последних сессий
без задачи. Ссылка в первой колонке открывает страницу сессии, ссылка "Показать
все в правом меню" включает полный список в боковой панели. Текущая сессия
попадает в таблицу после выполнения задания "Обновить диалоги".

Действие `analytics_scan` относится к существующему профилю `full`. В профиле
`core` панель не показывает его и отклоняет прямой POST к `/jobs` с кодом 403.
Профили Developer и Project и настройка собственного источника аналитики ещё
не реализованы. Ограничение профиля не заменяет аутентификацию панели.

Графики токенов по MCP-серверам, моделям и bash-CLI разбиты на три отдельных
графика: свежий ввод, кэш, исходящие. У каждого своя линейная шкала, поэтому
маленькие значения не теряются рядом с кэшем.

Токены показываются двумя разными итогами:

- «Токены без кэша» - свежий ввод плюс исходящие и reasoning; так считает Kilo;
- «Обработано контекста» - полный промпт каждого запроса вместе с кэшем. Кэш
  перечитывается заново на каждом запросе, поэтому этот итог больше в разы.
  «Средний контекст на запрос» показывает отношение этого итога к числу запросов.

Эти два итога не заменяют друг друга и не суммируются.
 Графики рисует Chart.js с CDN
`cdn.jsdelivr.net`. Если CDN недоступен, вместо
пустого места рисуется упрощённый вид на HTML/CSS: полосы для bar и список с
процентами для doughnut, данные при этом те же. Данные обновляются командой
`python3 .agents/skills/task-router/children/analytics/scripts/task-analytics.py scan --allow-partial`.

Полный HTML бизнес-отчёта открывается по
`/files/tasks/{N}/reports/change-report/report.html`; этот же маршрут отдаёт
относительные картинки отчёта. Старый `/report/{N}` делает 302 на новый путь.
Маршрут `/files/` ограничен каталогом `tasks/{числовой ID}/reports/change-report/`.
Состояние панели, `.doc/skil_data`, скрытые файлы, симлинки и файлы с
неразрешённым расширением через этот маршрут не выдаются. Ограничение пути не
заменяет аутентификацию для изменяющих API.

## Диалоги без задачи

В фильтре правого меню есть чекбокс "Диалоги без задач". По умолчанию он
выключен, поэтому список задач не меняется. Если включить, под задачами
появляются сессии из `.doc/task-analytics/out/unassigned/`: заголовок из первого
сообщения, дата, роль, модель, токены без кэша, число вызовов, активное время и стоимость.
Клик открывает страницу сессии
с детерминированными метриками: токены, запросы, инструменты, MCP, CLI, модели,
находки и предупреждения. Графики и таблицы метрик собираются тем же кодом, что
и блок диалогов задачи. ИИ-отчёт для таких сессий не формируется. Ссылки на
задачи и сессии сохраняют остальные фильтры.

Выпадающий список "Проект диалогов" фильтрует этот список по проекту Kilo. Значение берется
из `session.project_id`, а подпись из `project.name`, иначе из последнего сегмента пути `project.worktree`.
При выборе проекта чекбокс "Диалоги без задач"
включается автоматически. Выбор запоминается в cookie `panel_project` на 180 дней
и восстанавливается при следующем открытии панели. Строка сессии показывает проект
в метриках, поиск по списку тоже учитывает название проекта.

Блок диалогов задачи показывает те же таблицы, но в сводном виде по всем сессиям
задачи: инструменты, MCP, модели и находки. Медиана и p95 у задачи не
показываются, потому что по сессиям они не суммируются.

## Безопасность

- Сервис слушает только `127.0.0.1:8077`; `Host` и `Origin` проверяются на loopback.
- Запись идёт только через разрешённые действия и API харнес-миррора. PHP не пишет произвольные файлы.
- Действия берутся только из `config/actions.json`; пути проверяются на выход за корень.
- `kilo.db` открывается только на чтение через PDO и `PRAGMA query_only`.
- `id` задачи - только цифры (`^\d+$`), имя документа - только
  `^[a-z0-9][a-z0-9-]*$`, ID сессии - только `^ses_[A-Za-z0-9]+$`. Чужие пути
  не читаются.
- `state`, `.env`, `ADAPTERS.local.md`, `actions.local.json`, `prices.local.json` не переносятся. Секреты (`mcp.env`, `config.env`) панелью не читаются и не выводятся.
- Секреты в текстах: панель не чистит секреты из MD - показываются те же
  тексты, что уже лежат в `.doc`. Не класть секреты в документацию.

## Зависимости данных

- Список задач: `tasks/*/task.json` (канон JSONdoc). Задачи без task.json
  в списке не видны. Сейчас: 190 задач с `task.json`.
- Релиз берется из `metadata.release`. У 164 задач релиза нет - они под
  фильтром `no-release`. Релиз 5.7.3 - 6 задач, 5.7.4 - 5 задач.
- Страница задачи дополнительно читает `task.md` (сырой Jira-экспорт),
  `diff.files.md` (плоский список файлов), `reports/*/workflow-context.json`.
- Документация: `architecture/*.json` (файлы с `_` в начале пропускаются),
  `architecture/*.md` и `harnes/**/*.md` (файлы и каталоги с `_` в начале пропускаются).
  Сейчас: 72 документа, все из `.doc/harnes`, каталога `.doc/architecture` в эталоне нет.
- Если манифест архитектуры (`architecture/*.json`) отсутствует, вкладка не пустая:
  она показывает markdown-канон харнеса и подсказывает источники.
- Отчеты со свежестью: сверка `sha256` из workflow-context с файлом на диске
  при каждом открытии страницы. `stale` значит исходник изменился после отчета.

## Перенос с харнесом

Панель - часть харнеса. Код панели переносится вместе с харнесом, но её установка, Docker, compose, supervisor и серверное окружение относятся к отдельной задаче пользователя. Текущие профили: Core, Developer и Project; имена Full и Core ниже исторические, legacy Full отображается в Developer. Перенос выполняет `new-project/scripts/harness_transfer.py`; `clean`, автоматический `git init` и запись `.git/info/exclude` не выполняются.
На целевом проекте панель показывает его собственные `tasks/*/task.json`
и `architecture/*.json`. `state`, `.env`, `ADAPTERS.local.md`,
`actions.local.json`, `prices.local.json` и логи не переносятся.
Канон переноса: `.doc/harnes/state/14-project-migration.md`. Устройство сервиса: [state/22-panel-service.md](../harnes/state/22-panel-service.md).

## Ограничения

- PHP 8.4 в сервисе `copytrust-tools`. Код сохраняет совместимость с PHP 7.1, но рабочий рантайм 8.4.
- `md_render` - упрощенный, не полный CommonMark (достаточно для секций JSONdoc).
- Поиск - подстрока по id+title в правом списке (JS) и серверный через форму.
- Полнотекстовый поиск по телам секций не делается - для этого CBM/Sourcegraph.
- Порт по умолчанию 8077. Основной стенд на 8030 - конфликтов нет.
- Графики требуют доступа браузера к `cdn.jsdelivr.net`; без сети работает
  упрощённый HTML-вид, таблицы и KPI остаются.
- Аналитика на странице Задачи читает все `dialogs/ses_*.json` при каждом открытии, поэтому страница тяжелее страницы задачи.
  Сейчас это 184 сессии и около 0.15 с; при тысячах сессий понадобится кеш.
- Стоимость считается по локальным токенам, а не по экспорту логов провайдера.
  Точная сумма может отличаться, ограничение описано в [changelog.md](./changelog.md).
