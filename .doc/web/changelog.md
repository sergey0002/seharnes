## Суть

Журнал фиксирует все правки панели `.doc/web` от 2026-11-03: переход на один сервис, встроенный просмотрщик харнеса, кнопки запуска скриптов, цены провайдеров, стоимость сессий и задач. Операционное описание панели остаётся в [README.md](./README.md), устройство сервиса в [22-panel-service.md](../harnes/state/22-panel-service.md).

## Что изменилось

### 0d. Граф приведён к старому просмотрщику: файловое дерево, карточки, мгновенная панель (2026-11-13)

- Левая панель — одно дерево по реальной структуре файлов (`.agents/skills/code/bug-cause/SKILL.md`),
  а не отдельные списки по типам. Служебный сегмент `children` вырезан как в эталоне; тип файла
  виден по цветной плашке `S/R/P/C/D/M`, справа — карточка-подсказка (summary), у файла с
  несколькими узлами (`.cursor/mcp.json`) строка раскрывается как папка. «Копии» включаются
  чекбоксом, тогда в дереве появляются `.codex`, `.kilo`, `.cursor`.
- Канвас переписан на SVG-карточки, как в старом просмотрщике: колонки по типам
  (rule → skill → mcp → script → doc → config), упорядочивание barycenter по связям, цветная
  полоса и глиф типа, название, путь, строка `тип · среда · анализ`, дуги-связи с цветом по
  типу и подсказкой, подсветка соседей при наведении, панорамирование, зум колесом,
  «уместить». Длинные типы делятся на колонки по 26 карточек, поэтому карточки читаемы
  (240×58 при масштабе 1), а не превращаются в точки.
- Режим фокуса «только это и связи»: входящие слева, узел в центре, исходящие справа; снятие
  по Esc или по плашке фокуса.
- Правая панель реагирует мгновенно: выбранная строка и карточка подсвечиваются сразу, в шапке
  идёт полоса загрузки, а в теле — каркас с уже известными полями (id, путь, тип). Ответы
  кэшируются по узлу, устаревшие запросы отменяются, повторный выбор не делает запроса.
- Низ правой панели — «Связи и JSON» как в эталоне: списки исходящих и входящих связей с
  переходами по клику плюс JSON узла с размером, скрытием и копированием. Сырой дамп JSON
  вместо связей убран.
- `GET /panel/api/graph/view` отдаёт `file`, `summary` (обрезанное описание) и `analysis`:
  дереву и карточкам этого хватает, второй запрос на узел не нужен.

### 0c. «Контроль харнеса» переехал в новый каркас, дерево графа — как в старом просмотрщике (2026-11-13)

- Новый раздел `/panel/harness`: источник обновления и квитанция установки, действия
  (предпросмотр и применение обновления из Git, пересборка графа, проверки, синхронизация
  зеркал) и три скана — канон/мусор, битые ссылки, документация и JSON. Раскладка та же, что
  у графа: тулбар, левая панель, контент, правая панель (итог скана + отчёт JSON), нижний док.
  Бэкенд — `Domain\Harness\{HarnessStatus,HarnessAudit}` и `HarnessController`; сканы запускают
  тот же `audit_harness.py`, поэтому правила канона не дублируются.
- Пункт меню «Контроль харнеса» больше не ведёт в старую админку: `/harness-admin/` остаётся
  только как образец. Старые разделы «Задачи» и «Аналитика» помечены точкой «ещё на старом UI».
- Дерево файлов в графе повторяет старый просмотрщик: плашка типа с буквой (S/R/P/C/D/M) и
  цветом вида элемента, понятные подписи файлов (`SKILL.md` → «Скил», `README.md` → «Описание»),
  число связей у строки, жирные папки со счётчиком, фиолетовые папки-маршрутизаторы.
- Выбор узла раскрывает его путь в дереве (`revealSelection`), состояние держится в
  `localStorage` (`panel.graphTree.closed`), адрес получает `#node=<id>` — ссылку на элемент
  можно сохранить, а переход по ней выбирает узел без перезагрузки.
- Тулбар не разъезжается: группа с поиском не сжимается, кнопки переносятся на вторую строку,
  высота строки тулбара в сетке стала `minmax(--toolbar-h, auto)`. Проверено на 1600/1440/1280/1100/980/860.
- Нативные `select`/`option` наследуют тему (`color-scheme: inherit` плюс явные цвета опций):
  в тёмной теме список больше не выглядит светлым с бледными подписями.

### 0b. Корень отдаёт панель напрямую, без 302 (2026-11-13)

- `GET /` больше не редиректит на `/panel/graph`, а рендерит ту же страницу: путь запроса
  подменяется на `/panel/graph` до маршрутизации. Причина: в iframe-предпросмотре 302 иногда
  оставляет пустой экран, и панель «не видно», хотя сервер отвечает.
- Проверено в браузере: `/` отдаёт 200, дерево графа строится, страница работает и внутри
  iframe (эмуляция предпросмотра — 885 узлов в дереве).
- Скрипт восстановления после холодного старта песочницы: `bash /home/user/panel-up.sh`
  (ставит `php-cli`, если его нет, и запускает `php -S 0.0.0.0:8077`).

### 0b. Граф как в старом просмотрщике: дерево файлов и редактор (2026-11-13)

- Левая панель графа стала **деревом файлов**: группы по типам, вложенные папки из пути,
  цветная подсветка типа, счётчики, свёрнутые папки запоминаются в `localStorage`.
  Фильтры переехали в левую панель: поиск, «только связанные», «без связей», «копии».
- Правая панель показывает файл узла: путь, размер, содержимое. Если файл канонический и
  внутри репозитория — редактор: «Редактировать», «Сохранить» (Ctrl+S), «Отменить»,
  «Перечитать». Причина запрета («копия», «вне репозитория», «больше 2 МиБ») выводится
  в карточке.
- новый эндпоинт `POST /panel/api/graph/node` (`{id, content}`): запись идёт через
  `harness_mirror.py set --file`, то есть канонический файл и граф обновляет тот же движок.
  Право записи решает `Domain\Graph\EditPolicy`; POST требует `Origin` как у хоста и
  `X-Requested-With`.
- Починены кнопки действий на графе («Пересобрать граф», «Проверить граф», «Структура и
  мусор», «Синхронизировать зеркала»): обработчик `[data-run-action]` висел на доке, а сами
  кнопки живут в панели раздела — теперь делегирование на документе.
- Панель кнопок раздела больше не «склеивает» счётчики и поиск: элементы не сжимаются,
  при нехватке места панель прокручивается по горизонтали.

### 0b. Один вход в панель: корень ведёт в `/panel/` (2026-11-13)

- `GET /` больше не отдаёт старый интерфейс, а отвечает `302 → /panel/graph`: превью и закладка
  «панель» открывают общий дизайн. Старая панель не удалена — её страницы живут по своим
  адресам (`/index.php?tab=tasks`, `/index.php?tab=docs`, `/analytics`, `/harness-admin/`,
  `/harness/`, `/jobs`), а пункт меню «Задачи» в новом каркасе ведёт на `/index.php?tab=tasks`.
- В шапке старой панели появилась кнопка «Открыть новый интерфейс →» (`public/index.php`,
  `.new-panel-link` в `public/assets/style.css`).
- Старый просмотрщик миррора `/harness/` показывает плашку «Это старый просмотрщик… →
  Открыть общий граф». Плашка вставляется сервером (`harness_serve_viewer_index`), а не в шаблон
  харнеса: шаблон уезжает в другие проекты и ссылки на наш маршрут в нём быть не должно.
- Функциональность просмотрщика (API `/harness/api/*`, запись узла `PUT`) сохранена полностью.

### 0b. Каркас `/panel/`: слои, темы, две локали, узкий экран (2026-11-13)

- Появился новый каркас панели рядом со старым: `/panel/graph`, `/panel/docs`,
  `/panel/docs/{id}`, API `/panel/api/*`. Старые маршруты не изменились, весь функционал
  документов и графа доступен из нового интерфейса.
- Слои: `src/Core` (роутер, запрос, ответ, контейнер, представление), `src/Support`
  (markdown, пути, текстовый поиск без mbstring, локализация), `src/Domain`
  (документы, граф, задания), `src/Http` (контроллеры, `OriginGuard`), `src/View`
  (layout + partials + pages). Домен больше не рендерит HTML: секции документов и блоки
  узлов отдаются как данные, разметку собирает представление. Старые функции документации
  в `app/lib.php` (`doc_sources`, `get_arch_doc`, `list_arch_docs`, `valid_doc_id`,
  `md_toc`, `md_*`) стали тонкими обёртками над `Domain\Doc` — второй реализации нет.
- Оформление вынесено в токены `assets/css/tokens.css`; темы `light`/`dark`/`system`
  ставятся до первой отрисовки, выбор хранится в `localStorage['panel.theme']`.
- Локализация: словари `resources/lang/{ru,en}.json`, cookie `panel_lang`; смена языка
  перезагружает страницу, чтобы сервер и клиент говорили на одном языке.
- Клиент — ES-модули без сборки и без `node_modules`: `core/{boot,store,api,theme,i18n,dom,dock,splitter,drawer}.js`,
  `pages/{docs,graph}.js`. Граф рисуется на canvas, чтобы 1000+ узлов не превращались в DOM.
- Нижний док: терминал действий, инспектор JSON, живой лог. Автопрокрутка держится за низ,
  пока пользователь не отлистал вывод вверх (не срывает чтение лога задания).
- Узкий экран: левая панель становится выдвижным ящиком (`core/drawer.js`), кнопки разделов
  и дока показывают только иконки, `grid-template-columns: minmax(0, 1fr)` убирает
  горизонтальную прокрутку страницы.
- Тесты: `tests/php/run.php` (27 юнит-тестов слоёв), `tests/test_panel_shell.py`
  (14 проверок каркаса, фрагментов, API, старых роутов, ящика на узком экране).

### 0a. Исправления 2026-11-13: origin за прокси и пустая вкладка документации

- Проверка `Origin` больше не требует loopback-хоста. При работе за обратным прокси (проброс порта,
  предпросмотр) `Host` и `Origin` — внешние, и все изменяющие кнопки панели и просмотрщика графа
  отвечали `403 origin not allowed`. Теперь `Origin` обязан совпадать с хостом запроса; не-GET
  по-прежнему требует `X-Requested-With`. Правка: `app/jobs.php` (`jobs_origin_allowed`) и
  `app/harness.php` (запасная реализация). Тест: `tests/test_origin_policy.py`.
- Вкладка «Документация» читала только `.doc/architecture/*.json`, которых в эталоне нет
  (каталог в `.gitignore`, генератора JSON нет), поэтому список был пуст. Теперь источники —
  `architecture/*.json`, `architecture/*.md` и `harnes/**/*.md`, в списке они сгруппированы,
  открываются крошки и путь файла, md рендерится с оглавлением по `##`/`###` и якорями.
  Правка: `app/lib.php` (`doc_sources`, `arch_doc_files`, `get_arch_doc`), `public/index.php`.
  Тест: `tests/test_docs_tab.py`.
- Скрипт `harness-core/scripts/audit_harness.py` получил нормативный документ
  `docs/scripts/audit_harness.py.md` и объявлен в `skill.json.resources.scripts`: строгий гейт
  `structure` больше не ругается `S03`/`S06`.


### 1. Один сервис вместо двух

- Панель и просмотрщик харнеса работают на `http://127.0.0.1:8077`.
- Отдельный Python-сервер на 8090 и `harness-mirror.service` отключены.
- Сервис `copytrust-tools` собран из `php:8.4-cli` с `python3`, `bash`, `pwsh`, `git`. Node, CBM и CodeGraph в сервис не входят.
- Рабочая область монтируется по тому же абсолютному пути, что на хосте. Это нужно для `task-analytics` и `kilo.db`.
- Порт слушает loopback. Запросы с чужим `Origin` отклоняются; `Host` не ограничен loopback, чтобы панель работала за обратным прокси (уточнено 2026-11-13).

### 4. Цены и провайдеры

Цены вынесены в [prices.json](./config/prices.json) по провайдерам. Сейчас заполнен `ai-starimg-ru`:

- 30 000 000 внутренних токенов стоят 823.90 RUB;
- 1M внутренних токенов стоит 27.463333 RUB;
- коэффициент модели умножает вход, кэш и выход;
- кэш тарифицируется без скидки, `cached_discount: 1`;
- 44 модели с коэффициентами из каталога `ai.starimg.ru`;
- `codex-sale` и `kilo` описаны без цен: их сессии показываются, стоимость 0, ошибки нет.

Формула:

```text
стоимость = (вход + кэш + выход) * коэффициент * 0.000027463333
```

Примеры после пересчёта:

| Объект | Стоимость |
|---|---:|
| сессия `ses_e610e85adffetyEzpIP9A1Bvob` | 430.30 RUB |
| `gpt-6.1-sol` в этой сессии | 418.2496 RUB |
| `deepseek-v4.1-flash` в этой сессии | 12.0510 RUB |
| задача 2612 | 76.63 RUB |
| задача 2618 | 129.19 RUB |

Провайдер берётся из `session.model.providerID` в `kilo.db`. База открывается только на чтение. Провайдер показывается в таблице сессий, в блоке `Провайдеры` и на странице диалога без задачи. Это провайдер последней модели сессии; в базе есть провайдер каждого сообщения, но панель его не агрегирует.

Файлы: [app/pricing.php](./app/pricing.php), [app/providers.php](./app/providers.php), [config/prices.local.example.json](./config/prices.local.example.json).

## Известные проблемы и ограничения

### П-1: Стоимость это оценка по локальным токенам

Панель считает стоимость по токенам из артефактов `task-analytics` и цене провайдера. Провайдерский лог может группировать запросы иначе, поэтому точная сумма для сессии может отличаться. Для точного совпадения нужен импорт экспорта логов провайдера, сейчас его нет.

### П-2: Пакет токенов задан как 30 000 000

В конфиге стоит `balance.tokens: 30000000`, потому что при 300 000 сессия выходит около 42 973 RUB и не сходится с балансом. Если в кабинете провайдера 300 000, поменяйте `balance.tokens` на `300000`; все цены пересчитаются.

### П-3: Провайдер сессии один

Провайдер берётся из последней модели сессии. Если внутри диалога провайдер менялся, панель покажет последний, а не разбивку по сообщениям.

### П-4: Один экземпляр на проект

Сервис обслуживает один `WORKSPACE_ROOT`. Несколько проектов требуют нескольких экземпляров или отдельного реестра рабочих областей.

### П-5: `php -S` не production

Встроенный сервер работает с воркерами, но задания всё равно запускаются отсоединённо. При росте нагрузки нужен PHP-FPM или Apache.
