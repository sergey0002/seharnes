## Суть

MCP-сервер описывается двумя файлами: правилом вызова и документом эксплуатации.
Целевая раскладка: все правила MCP лежат в `.cursor/rules/mcp/`, имя файла равно
ключу сервера в `.cursor/mcp.json`, главное правило `mcp.mdc` остается в корне
правил и ссылается на каждый файл с пометкой о назначении. Документ остается один
на сервер в `.doc/harnes/mcp/{server}.md`.

Отдельно определяется судьба правил, которые относятся к одному скилу. Правило,
которое запускает скил, остается в корне правил. Правило, которое является шагом
внутри уже выбранного скила, переезжает в `references/` этого скила. Внутри папки
скила файл `.mdc` не является правилом ни для одной среды.

Документ сверен с официальной документацией Cursor, Kilo Code и Antigravity.
Ограничения каждой среды и обязательные генераторы перечислены в разделе 5.

## 1. Нормативные правила

| ID | Правило | Уровень |
|---|---|---|
| R01 | Один сервер равен одному правилу и одному документу | ОБЯЗАТЕЛЬНО |
| R02 | Правило MCP лежит в `.cursor/rules/mcp/{server}.mdc` | ОБЯЗАТЕЛЬНО |
| R03 | `{server}` точно совпадает с ключом сервера в `.cursor/mcp.json` | ОБЯЗАТЕЛЬНО |
| R04 | Главное правило `.cursor/rules/mcp.mdc` содержит ссылку на каждый файл и пометку о назначении | ОБЯЗАТЕЛЬНО |
| R05 | Правило хранит вызов: когда брать, инструменты, аргументы, ошибки, проверку | ОБЯЗАТЕЛЬНО |
| R06 | Документ `.doc/harnes/mcp/{server}.md` хранит установку, перенос, несколько проектов, параметры и управление | ОБЯЗАТЕЛЬНО |
| R07 | Правило и документ не дублируют друг друга, только ссылаются | ЗАПРЕЩЕНО |
| R08 | Секреты хранятся только в env-файлах, в правиле и документе остаются имена переменных | ЗАПРЕЩЕНО |
| R09 | Отключенный сервер сохраняет правило и документ с причиной и заменой | ОБЯЗАТЕЛЬНО |
| R10 | Новый сервер добавляется в `mcp.json`, правило, документ, главную карту и `state/04-mcp.md` в одном проходе | ОБЯЗАТЕЛЬНО |
| R11 | После изменения правил или конфигурации выполняется синхронизация сред и parity | ОБЯЗАТЕЛЬНО |
| R12 | Правило, относящееся к одному скилу, не кладется в папку скила как `.mdc` | ЗАПРЕЩЕНО |
| R13 | Шаг внутри скила оформляется как `references/{name}.md` и ссылка из `SKILL.md` | ОБЯЗАТЕЛЬНО |
| R14 | Правило-триггер, по которому агент выбирает скил, остается в корне `.cursor/rules/` | ОБЯЗАТЕЛЬНО |
| R15 | Для Antigravity генерируются плоские `.agents/rules/*.md` с `trigger`, а не `.mdc` с `alwaysApply` | ОБЯЗАТЕЛЬНО |
| R16 | Antigravity сканирует правила и скилы на один уровень, вложенность только через `rules.json` или `skills.json` | ОБЯЗАТЕЛЬНО |

## 2. Структура канона

Целевое состояние:

```
.cursor/
└── rules/
    ├── mcp.mdc                     главная карта, ссылки на все серверы
    ├── mcp/
    │   ├── codebase-memory-mcp.mdc
    │   ├── codegraph.mdc
    │   ├── serena.mdc
    │   ├── mysql.mdc
    │   ├── git.mdc
    │   ├── jira-task.mdc
    │   ├── leantime.mdc
    │   ├── context7.mdc
    │   ├── playwright.mdc
    │   ├── phpstan-mcp.mdc
    │   ├── php-deps-mcp.mdc
    │   ├── semgrep.mdc
    │   ├── xmlriver.mdc
    │   ├── xmlriver-ws.mdc
    │   ├── jdocmunch.mdc
    │   ├── sourcegraph.mdc
    │   ├── xdebug.mdc
    │   ├── deepwiki.mdc
    │   └── bitbucket-task.mdc
    ├── prepare-plan.mdc            триггер скила, остается в корне
    └── ...
```

Правило:

1. Папка `mcp/` содержит только правила серверов.
2. Главное правило `mcp.mdc` лежит в корне, иначе оно теряет роль карты.
3. Файлы внутри `mcp/` не имеют префикса `mcp-`: имя равно ключу сервера.
4. Старые имена `mcp-{server}.mdc` в корне после миграции запрещены.
5. Документы MCP остаются в `.doc/harnes/mcp/`, имя равно ключу сервера.

Папка называется именно `.cursor/rules/mcp/`, а не `.cursor/mcp/`. Cursor
обнаруживает правила только внутри `.cursor/rules`, а `.cursor/mcp.json` и
`.cursor/mcp.env` остаются конфигурацией серверов и к правилам не относятся.

Пример главной карты:

```markdown
| Сервер | Назначение | Правило | Документ |
|---|---|---|---|
| `serena` | символы, ссылки, диагностика PHP | [правило](./mcp/serena.mdc) | [документ](../../.doc/harnes/mcp/serena.md) |
```

## 3. Содержание правила сервера

Обязательные разделы:

```markdown
# MCP: {server}

## Когда
Когда вызывать, в каком порядке относительно других MCP, когда не вызывать.

## Инструменты
Таблица: инструмент, параметры, что возвращает, зачем.

## Ошибки и границы
Типичные ошибки, ограничения, что делать.

## Проверка
Команда smoke-проверки сервера.

## Связи
Главная карта, документ, скилы, которые вызывают сервер.
```

Требования:

1. Перечисляются все инструменты сервера, доступные в текущей конфигурации.
2. Для каждого инструмента указываются обязательные и необязательные аргументы.
3. Указывается, что инструмент возвращает и когда его брать.
4. Указываются инструменты, которые отключены или требуют подтверждения.
5. Пути и команды даются от корня проекта.
6. Секреты не печатаются.

Документ сервера следует шаблону [mcp/README.md](./README.md) и требованиям
[component-docs.md](../component-docs.md), раздел 5.

## 4. Где применять серверы

Таблица описывает рабочее место сервера в цикле задачи. Порядок вызова задан в
[`.cursor/rules/mcp.mdc`](../../.cursor/rules/mcp.mdc), здесь назначение и границы.

| Сервер | Где применять | Для чего | Когда не брать |
|---|---|---|---|
| `jdocmunch` | `task-doc`, `project-doc`, `doc-verify`, `prepare-plan` P0 | найти и прочитать раздел `.doc/` без обхода каталога | поиск по коду, точные литералы, не-Markdown |
| `codebase-memory-mcp` | `prepare-plan`, `task-doc`, `doc-verify`, `task-code-review` | структура кода, вызовы, blast radius, влияние правки | документация, сырые данные |
| `codegraph` | `prepare-plan`, архитектурный анализ, `doc-verify` | исходник, вызывающие, blast radius, тесты | сообщества, god nodes и shortest path |
| `php-deps-mcp` | `prepare-plan`, рефакторинг PHP | зависимости классов, граф вызовов, нарушения | JS, Vue, документация |
| `serena` | `code-editing`, `prepare-plan`, `task-code-review` | объявление, ссылки, диагностика, точечная правка PHP | документация, массовый поиск, JS-символы |
| `mysql` | задачи схемы и данных, проверка стенда | таблицы, колонки, выборки | запись без явного разрешения |
| `context7` | реализация с внешней библиотекой | версия библиотеки, API, примеры | код проекта, внутренние классы |
| `playwright` | `test-task`, `browser-verify` | UI-ветка без метода Cest, визуальная проверка | замена Codeception, ручной сценарий без теста |
| `phpstan-mcp` | перед коммитом рисковых PHP-правок | статический анализ типов и ошибок | вместо тестов поведения |
| `semgrep` | security-чувствительные правки | поиск небезопасных конструкций | замена ревью и тестов |
| `git` | `gototask`, `task-diff`, `git-task-blame` | история, diff, blame, ветки | мутации без скила и подтверждения |
| `jira-task` | только `gototask`, `task-intake` | экспорт `task.md`, список задач релиза | прямой вызов агентом |
| `leantime` | локальный проектный менеджер | проекты, тикеты, трудозатраты | замена Jira в задачах CopyTrust |
| `xmlriver` | `xmlriver`, `serp-study`, `serpanalise-report` | выдача Google и Яндекс, кеш, баланс | обход лимитов, нецелевые задачи |
| `xmlriver-ws` | `xmlriver` | частотность Wordstat, динамика, ассоциации | выдача SERP |
| `sourcegraph` | не применять | отключен, legacy полнотекст | любые задачи |
| `xdebug` | не применять | отключен, runtime-отладка PHP | любые задачи |
| `deepwiki` | не применять | отключен, внешняя документация | любые задачи |
| `bitbucket-task` | не применять | отключен, legacy трекер | любые задачи |

Правила выбора:

1. Сначала документация, потом код, потом символы, потом данные.
2. Граф не заменяет чтение файла, а указывает, что читать.
3. Точную правку делает Serena, не граф.
4. MCP не вызывается "на всякий случай". Сначала проверяется, дает ли локальный
   файл или тест тот же ответ дешевле.
5. Для каждого сервера есть smoke-команда в правиле и документе.

## 5. Совместимость сред

| Среда | Где читает правила | Вложенные папки | Формат | Что это значит |
|---|---|---|---|---|
| Cursor | `.cursor/rules/` | да, официально | `.mdc` | папка `mcp/` работает как есть |
| Kilo | `.kilo/rules/` плюс `instructions` в `kilo.jsonc` | да, если путь указан в `instructions` | `.md` | нужен рекурсивный генератор и точные пути |
| Antigravity | `.agents/rules/*.md` | нет, только первый уровень, если не задан `.agents/rules.json` | `.md` с `trigger` | нужен плоский вид, папка `mcp/` не читается |
| Gemini | не генерируется, legacy `.gemini/` удален | не применимо | `.md` | рабочей считать только `.agents/rules` |
| Claude Code | нет каталога правил, используются `CLAUDE.md` | не применимо | `.md` | правила MCP для Claude не генерируются |
| DeepSeek Harness | нет движка правил, `DSH-RULES.md` собирается из `.cursor/rules` | не применимо | `DSH-RULES.md` | нужен рекурсивный генератор, иначе правила MCP выпадут из индекса |
| Codex CLI | `.codex/rules/` по конвенции проекта, не автообнаружение | да, если путь упомянут в `AGENTS.md` | `.md` | нужен рекурсивный генератор и упоминание в `AGENTS.md` |

Источники:

- Cursor: `cursor.com/docs/context/rules`, раздел Project rules, пример
  `.cursor/rules/frontend/components.mdc`.
- Kilo: `kilo.ai/docs/customize/custom-rules`, правила подключаются массивом
  `instructions`, поддерживаются пути и глоб-шаблоны.
- Antigravity: `antigravity.google/docs/rules`, каталог `.agents/rules/`,
  плоское сканирование, обязательный `trigger`, вложенные папки только через
  `.agents/rules.json`.

### 5.1 Целевые представления

| Среда | Куда генерируется | Раскладка |
|---|---|---|
| Cursor | `.cursor/rules/mcp/{server}.mdc` | вложенная, канон |
| Codex | `.codex/rules/mcp/{server}.md` | вложенная, путь в `AGENTS.md` |
| Kilo | `.kilo/rules/mcp/{server}.md` | вложенная, точные пути в `instructions` |
| Antigravity | `.agents/rules/mcp-{server}.md` | плоская, `trigger: model_decision`, `description` |
| DeepSeek Harness | `DSH-RULES.md`, `DSH-BOOTSTRAP.md` | плоский текст, on-demand таблица с путями |
| Claude Code | не генерируется | нет каталога правил |

Плоский вид Antigravity обязателен: официальная документация прямо говорит, что
файлы во вложенных папках игнорируются, а сканирование идет на один уровень.
Имя `mcp-{server}.md` сохраняет однозначность в плоском каталоге.

Это касается не только MCP. Сейчас все 36 правил лежат в `.agents/rules` как
`.mdc` с `alwaysApply`. Antigravity читает только `.md` с обязательным `trigger`,
поэтому текущий вид для нее недействителен. M9 обязан сгенерировать плоские `.md`
для всех правил, а не только для 19 MCP.

DeepSeek Harness не читает правила как файлы. `generate-dsh-config.py` инлайнит
always-правила в `DSH-RULES.md` и строит таблицу on-demand правил с путями.
После переноса в `mcp/` генератор обязан обходить правила рекурсивно и писать
относительный путь, иначе 19 MCP-правил исчезнут из DSH-индекса, а smoke останется
зеленым.

## 6. Правила, относящиеся к скилу

### 6.1 Два вида правил

| Вид | Назначение | Где живет |
|---|---|---|
| Триггер | по описанию выбирает скил, задает маршрут и границы | `.cursor/rules/{name}.mdc` |
| Шаг скила | выполняется после того, как скил уже выбран | `.agents/skills/{name}/references/{step}.md` |

### 6.2 Почему нельзя просто перенести правило в скил

Скил в Cursor, Kilo и Antigravity обнаруживается по `SKILL.md` и `description`.
Файл `.mdc` внутри папки скила не является правилом: клиенты его не читают, а
человек может решить, что правило работает. Поэтому перенос правила в скил
допустим только как `references/*.md` и только со ссылкой из `SKILL.md`.

### 6.3 Текущие кандидаты

| Правило | Вид | Решение |
|---|---|---|
| `comment-triage.mdc` | шаг `gototask` после apply | перенесено в `gototask/references/comment-triage.md`, ссылка из `gototask/SKILL.md` |
| `yadisk-screenshot.mdc` | триггер отдельного скила | оставить в корне или удалить после проверки, что `description` скила покрывает триггеры |
| `test-task.mdc` | триггер оркестратора | оставить в корне |
| `test-priority.mdc` | общий приоритет тестов | оставить в корне |
| `prepare-plan.mdc` | триггер скила | оставить в корне |
| `project-doc.mdc` | триггер скила | оставить в корне |
| `task-doc.mdc` | триггер скила | оставить в корне |
| `doc-verify.mdc` | триггер скила с globs | оставить в корне |
| `bitbucket-tasks`, `code-editing`, `batch-calls`, `text-style`, `doc-rules`, `harness-improvement`, `business-rules`, `cbm-index-before-push` | общие правила | оставить в корне |

`comment-triage` вызывается только из `gototask`, поэтому перенос безопасен.
Перед переносом проверяется, что других вызовов нет:

```bash
rg -n 'comment-triage' .cursor .doc --glob '!**/.data/**'
```

### 6.4 Что меняется при переносе шага

1. Файл становится `references/{name}.md`, без frontmatter правила.
2. `SKILL.md` ссылается на файл и описывает, когда его читать.
3. Правило удаляется из `.cursor/rules/`.
4. Путь удаляется из `component_registry.json`.
5. Строка удаляется из `state/03-rules.md`.
6. Зеркала пересобираются синком.

## 7. Порядок миграции

Миграция выполняется одной фазой M9 плана
[harnesmigrations.md](../../plan/harnesmigrations.md). Порядок:

1. Обновить `generate-agent-configs.py`: рекурсивный обход правил, сохранение
   относительного пути, создание каталогов, очистка сирот по относительному пути.
2. Обновить `verify_parity.py`: сравнение правил по относительному пути, а не по
   stem, иначе вложенные правила выпадут из проверки.
3. Добавить генератор правил Antigravity: плоские `.md`, `trigger:
   model_decision`, `description` из frontmatter.
4. Перенести 19 правил `mcp-*.mdc` в `.cursor/rules/mcp/{server}.mdc` с
   переименованием под ключи сервера.
5. Обновить ссылки в `mcp.mdc`, документах, реестре и state-доках.
6. Перенести `comment-triage` в `gototask/references/`.
7. Пересобрать зеркала и проверить все среды.

Проверки:

```bash
find .cursor/rules/mcp -name '*.mdc' | wc -l
rg -n 'mcp-[a-z-]+\.mdc' .cursor/rules/mcp.mdc
bash .agents/skills/harness-router/children/environment-sync/scripts/sync-agent-views.sh
python3 .cursor/scripts/harness/verify_parity.py \
  --canonical .agents/skills --manifest .doc/skil_data/harness-core/parity-report.json --check
python3 .agents/skills/harness-router/children/improvement/scripts/validate_rules.py \
  --rules-dir .cursor/rules --skills-dir .agents/skills
node .agents/skills/harness-router/children/mcp-audit/scripts/test-mcp-servers.mjs
```

Ожидание: 19 файлов в `mcp/`, старых `mcp-*.mdc` в корне нет, ссылки разрешаются,
parity зеленый, в Kilo 19 путей в `instructions`, в Antigravity 19 плоских `.md`
с `trigger`.

## 8. Откат

1. Вернуть правила из `mcp/` в корень с прежними именами.
2. Вернуть `comment-triage.mdc` в `.cursor/rules/`.
3. Вернуть генераторы и `verify_parity.py`.
4. Пересобрать зеркала.
5. Проверить, что Kilo и Antigravity снова видят прежний набор.

Откат обязателен одной операцией. Частичный откат, когда канон уже в папке, а
генератор еще старый, запрещен: правила молча исчезнут из Kilo и Antigravity.

## Известные проблемы и ограничения

### П-1: Antigravity не читает вложенные правила

- Симптом: после переноса в `mcp/` правила MCP пропадают в Antigravity.
- Причина: официально сканируется только первый уровень `.agents/rules/*.md`.
- Ограничение: для Antigravity генерируется плоский вид, вложенность остается
  только в каноне Cursor.
- Файлы: `.cursor/rules/mcp/`, `.agents/rules/`

### П-2: Antigravity требует `trigger`, а не `alwaysApply`

- Симптом: правило с Cursor-frontmatter молча отбрасывается.
- Причина: обязательный ключ `trigger: always_on | model_decision | glob | manual`.
- Ограничение: касается всех 36 правил, не только MCP. Генератор Antigravity
  переводит `alwaysApply` и `description` в `trigger` и `description`, а `.mdc`
  переименовывает в `.md`.
- Файлы: `.agents/skills/harness-router/children/environment-sync/scripts/generate-agent-configs.py`, `.agents/rules/`

### П-2a: Antigravity сканирует на один уровень

- Симптом: `children/<child>/SKILL.md` и `rules/security/api-keys.md` не находятся.
- Причина: сканирование идет на один уровень, глубже только через `skills.json`
  или `rules.json`.
- Ограничение: дети маршрутизируются родителем; прямой автопоиск не обещать.
- Файлы: `.agents/skills/`, `.agents/rules/`

### П-3: Parity сравнивает правила по stem и не видит вложенность

- Симптом: вложенные правила не попадают в проверку, расхождение скрыто.
- Причина: `_rule_files` использует `iterdir()`.
- Ограничение: до M9 parity не является доказательством для вложенных правил.
- Файлы: `.cursor/scripts/harness/verify_parity.py`

### П-4: Правило внутри скила не работает как правило

- Симптом: перенесли `.mdc` в папку скила, поведение пропало.
- Причина: клиенты читают правила только из своих каталогов правил.
- Ограничение: шаг скила оформляется как `references/*.md` и вызывается из
  `SKILL.md`.
- Файлы: `.agents/skills/`

### П-5: DSH не видит вложенные правила

- Симптом: после переноса в `mcp/` в `DSH-RULES.md` нет 19 MCP-правил.
- Причина: `generate-dsh-config.py` обходит `.cursor/rules` без рекурсии.
- Ограничение: до правки генератора DSH-индекс не считается доказательством.
- Файлы: `.agents/skills/harness-router/children/environment-sync/scripts/generate-dsh-config.py`, `DSH-RULES.md`
