## Суть

Предварительное машинное описание части правил: [skill-format.yaml](../../.agents/skills/harness-router/children/harness-core/assets/policies/skill-format.yaml). В строгом режиме проверка скилов использует ограничения каталогов и frontmatter из этого файла вместе с доверенными встроенными ограничениями. Остальные правила и обычный режим пока используют константы валидатора.

Скил это папка с обязательным `SKILL.md`, обязательным `README.md` и машинным
манифестом `skill.json`. Структура папки, поля frontmatter, правила путей,
дочерние скилы и проверки описаны здесь. Документ нормативный: если скил ему не
соответствует, это дефект скила, а не свобода автора.

Формат собран из пересечения четырех источников: Agent Skills specification,
документация Cursor, документация Kilo Code и документация Antigravity. Ничего
сверх стандарта не добавляется, кроме `skill.json` и `children/`, которые клиенты
игнорируют как обычные дополнительные файлы и папки.

Пошаговая установка нового скила с проверкой всех сред и переноса:
[component-install.md](./component-install.md), раздел 2.

## 1. Нормативные слова

| Слово | Значение |
|---|---|
| ОБЯЗАТЕЛЬНО | без этого скил недействителен, проверка дает ошибку |
| ЗАПРЕЩЕНО | нарушение ломает переносимость или клиент, проверка дает ошибку |
| СЛЕДУЕТ | отклонение допустимо только с записью в `## Известные проблемы и ограничения` |
| МОЖНО | необязательный элемент, проверка не требует |

Все пути в этом документе даны от корня проекта, если не сказано иное.

## 2. Структура папки

```
.agents/skills/{name}/
├── SKILL.md              ОБЯЗАТЕЛЬНО, инструкция для агента
├── README.md             ОБЯЗАТЕЛЬНО, краткое описание без ссылок
├── skill.json            ОБЯЗАТЕЛЬНО, манифест структуры
├── scripts/              МОЖНО, только собственные исполняемые файлы
├── docs/                 МОЖНО, документы скриптов и MCP
├── references/           МОЖНО, документы для чтения по требованию
├── assets/               МОЖНО, шаблоны, схемы, статические данные
├── tests/                МОЖНО, тесты скила
└── children/             МОЖНО, дочерние скилы
    └── {child}/
        ├── SKILL.md
        ├── README.md
        ├── skill.json
        ├── scripts/
        ├── docs/
        ├── references/
        ├── assets/
        ├── tests/
        └── children/
```

Правила структуры:

| ID | Правило | Уровень |
|---|---|---|
| S01 | Папка скила содержит ровно один `SKILL.md` в корне | ОБЯЗАТЕЛЬНО |
| S02 | Папка скила содержит ровно один `README.md` в корне | ОБЯЗАТЕЛЬНО |
| S03 | Папка скила содержит ровно один `skill.json` в корне | ОБЯЗАТЕЛЬНО |
| S04 | Имя папки равно полю `name` и состоит только из `a-z`, `0-9` и дефиса | ОБЯЗАТЕЛЬНО |
| S05 | `SKILL.md` не лежит глубже папки скила или папки дочернего скила | ОБЯЗАТЕЛЬНО |
| S06 | Каталоги верхнего уровня: `scripts`, `docs`, `references`, `assets`, `tests`, `children` | ОБЯЗАТЕЛЬНО |
| S07 | Другие каталоги верхнего уровня запрещены | ЗАПРЕЩЕНО |
| S08 | Сгенерированное состояние, кеши и данные проекта внутри папки скила запрещены | ЗАПРЕЩЕНО |
| S09 | Симлинки внутри папки скила запрещены | ЗАПРЕЩЕНО |
| S11 | Данные и состояние скила хранятся в `.doc/skil_data/{skill}/`; каталог `data/` внутри скила запрещен | ОБЯЗАТЕЛЬНО |
| S10 | Пустые каталоги не создаются | СЛЕДУЕТ |

Каталог `docs/` хранит документы скриптов в `docs/scripts/` и MCP в `docs/mcp/`.
Эти файлы объявляются в `resources.references` манифеста.
Документация скила остается в `README.md`. Исторические имена
`templates/`, `agents/`, `.data/` считаются нарушением S06 и S08.

Данные скила не лежат в его папке. Рабочие данные, результаты, кеши и venv
хранятся в `.doc/skil_data/{skill}/`. Например, данные `yadisk-screenshot` лежат в
`.doc/skil_data/yadisk-screenshot`, данные `task-doc` в `.doc/skil_data/task-doc`.
Статические шаблоны и схемы, нужные только скилу, остаются в `assets/`.

## 3. Роли файлов

| Файл или каталог | Назначение | Кто читает |
|---|---|---|
| `SKILL.md` | шаги, вход, выход, ограничения | клиент и агент |
| `README.md` | зачем скил и как он работает, без ссылок | человек |
| `skill.json` | машинный манифест состава и зависимостей | валидатор и синхронизация |
| `scripts/` | исполняемые файлы самого скила | агент по команде из `SKILL.md` |
| `docs/scripts/` | документация скриптов скила, имя повторяет файл скрипта | агент перед вызовом скрипта |
| `docs/mcp/` | эксплуатация, перенос и аудит MCP скила | агент при настройке или диагностике сервера |
| `references/` | подробности, которые грузятся по требованию | агент по ссылке из `SKILL.md` |
| `assets/` | шаблоны, схемы, статические данные | агент и скрипты |
| `tests/` | тесты скила | разработчик и CI |
| `children/` | дочерние скилы, маршрутизируемые родителем | родительский скил |

`README.md` и `skill.json` клиенты не читают. Это файлы харнеса, а не части
протокола скилов.

## 4. SKILL.md

### 4.1 Frontmatter

ОБЯЗАТЕЛЬНЫ только два поля:

| Поле | Тип | Ограничение |
|---|---|---|
| `name` | строка | `^[a-z0-9]+(?:-[a-z0-9]+)*$`, равно имени папки |
| `description` | строка | непустая строка: что делает и когда применять |

МОЖНО использовать только поля стандарта:

| Поле | Тип | Ограничение |
|---|---|---|
| `license` | строка | имя лицензии или файл лицензии |
| `compatibility` | строка | требования среды |
| `metadata` | объект | только строковые ключи и строковые значения |
| `allowed-tools` | строка | экспериментальное поле, использовать не следует |
| `argument-hint` | строка | подсказка аргументов для импортированных multi-client скилов; остальные клиенты ее игнорируют |

Правила frontmatter:

| ID | Правило | Уровень |
|---|---|---|
| F01 |`name` совпадает с папкой | ОБЯЗАТЕЛЬНО |
| F02 | `description` содержит назначение и триггеры, по которым агент выбирает скил | ОБЯЗАТЕЛЬНО |
| F03 | Поля вне таблицы 4.1 запрещены | ЗАПРЕЩЕНО |
| F04 | `whenToUse`, `globs`, `alwaysApply`, `icon`, `color`, `paths`, `disable-model-invocation` в каноне запрещены | ЗАПРЕЩЕНО |
| F05 | `metadata` не содержит вложенных объектов, массивов, чисел и булевых значений | ОБЯЗАТЕЛЬНО |
| F06 | `description` написано в третьем лице и не содержит ссылок | ОБЯЗАТЕЛЬНО |
| F07 | `argument-hint` допускается только в импортированном скиле, для нового скила запрещен | СЛЕДУЕТ |

Поля `paths`, `disable-model-invocation`, `icon` и `color` относятся только к
Cursor. Если они понадобятся, они добавляются в Cursor-адаптер, а не в канон.
`argument-hint` допускается только в импортированном скиле, у которого есть
оригинальный multi-client текст. Для нового скила это поле не использовать.

### 4.1.1 Язык

Язык `SKILL.md` не фиксирован. Русский обязателен для README, карточек,
документов `.doc`, планов и ответов агента по
[text-style.mdc](../../.cursor/rules/text-style.mdc). Импортированный скил
сохраняет язык оригинала: английский текст Ponytail остается английским.

### 4.2 Тело

Порядок разделов:

```
## Когда применять
## Вход
## Шаги
## Выход
## Ограничения
```

Длина `SKILL.md` не ограничена. Объём держится за счёт выноса подробностей
в `references/` (B04) и запрета пересказа `README.md` (B09).

| ID | Правило | Уровень |
|---|---|---|
| B03 | Разделы идут в порядке из 4.2 | ОБЯЗАТЕЛЬНО |
| B04 | Подробные таблицы, длинные примеры и справочники вынесены в `references/` | СЛЕДУЕТ |
| B05 | В `SKILL.md` нет ссылок на `.codex`, `.kilo`, `.agents`, `.antigravity`, `.gemini`, `.dsh` | ЗАПРЕЩЕНО |
| B06 | В `SKILL.md` нет абсолютных путей и `..` | ЗАПРЕЩЕНО |
| B07 | Команды запускаются из корня проекта и содержат полный путь `.agents/skills/{name}/...` | ОБЯЗАТЕЛЬНО |
| B08 | В тексте ссылки на файлы скила даются относительно корня скила: `scripts/x.py`, `references/y.md` | ОБЯЗАТЕЛЬНО |
| B09 | `SKILL.md` не пересказывает `README.md` | СЛЕДУЕТ |

### 4.3 Ссылки на файлы

Два разных соглашения, их нельзя смешивать:

| Где | Форма | Пример |
|---|---|---|
| Текст и markdown-ссылки | от корня скила | `[правила](references/rules.md)` |
| Блок команды | от корня проекта | `python3 .agents/skills/harness-router/children/mirror/scripts/harness_mirror.py check` |

Относительный вызов `python3 scripts/harness_mirror.py` запрещен: агент работает
из корня проекта и такой путь не разрешается.

## 5. README.md

`README.md` нужен человеку, который открыл папку скила и не читал `SKILL.md`.
Документ короткий, без ссылок и без пошаговой инструкции.

Обязательные разделы:

```
# {name}

Назначение.
{2-4 предложения: зачем скил и какую работу закрывает}

Как работает.
{3-6 предложений: вход, основные действия, результат}

Что нужно.
{условия: доступ, стенд, конфигурация, сторонние инструменты}

Чего не делает.
{границы: что скил не делает и когда его не применять}
```

| ID | Правило | Уровень |
|---|---|---|
| R02 | В `README.md` нет markdown-ссылок, URL и `[[wikilinks]]` | ЗАПРЕЩЕНО |
| R03 | В `README.md` нет разделов `## Связи`, `## См. также`, `## Ссылки` | ЗАПРЕЩЕНО |
| R04 | `README.md` не содержит шагов, флагов и команд запуска | ЗАПРЕЩЕНО |
| R05 | `README.md` написан по-русски, без длинных тире, французских кавычек и эмодзи | ОБЯЗАТЕЛЬНО |
| R06 | `README.md` есть у каждого корневого и каждого дочернего скила | ОБЯЗАТЕЛЬНО |

Исключений нет. Если скилу нужна подробная инструкция, она живет в `SKILL.md` и
`references/`, а не в `README.md`.

## 6. skill.json

Манифест описывает состав папки и внешние зависимости. Единственный источник
правды о структуре скила для валидатора и генератора документации.

### 6.1 Схема

```json
{
  "schema": 1,
  "name": "test-task",
  "kind": "orchestrator",
  "entry": "SKILL.md",
  "readme": "README.md",
  "resources": {
    "scripts": ["scripts/task-test.sh"],
    "references": ["references/branches.md"],
    "assets": []
  },
  "tests": ["tests/test_task_test.py"],
  "children": [],
  "dependencies": {
    "skills": [
      {"name": "browser-verify", "required": true, "reason": "запуск браузерной проверки"}
    ],
    "project": [
      {"path": ".agents/skills/task-router/children/testing-router/children/test-task/scripts/gates.py", "owner": "qa", "required": true, "reason": "гейты готовности"}
    ]
  },
  "generated": []
}
```

### 6.2 Поля

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `schema` | число | да | всегда `1` |
| `name` | строка | да | равно `name` из `SKILL.md` и имени папки |
| `kind` | строка | да | `leaf` или `orchestrator` |
| `entry` | строка | да | всегда `SKILL.md` |
| `readme` | строка | да | всегда `README.md` |
| `resources.scripts` | массив строк | да | пути от корня скила, файлы существуют |
| `resources.references` | массив строк | да | пути от корня скила, файлы существуют |
| `resources.assets` | массив строк | да | пути от корня скила, файлы существуют |
| `tests` | массив строк | да | пути от корня скила, файлы существуют |
| `children` | массив строк | да | пути от корня скила, каждая папка это скил |
| `dependencies.skills` | массив объектов | да | имя, обязательность, причина |
| `dependencies.project` | массив объектов | да | путь, владелец, обязательность, причина |
| `generated` | массив строк | да | пути вне скила, обычно пусто |

Правила манифеста:

| ID | Правило | Уровень |
|---|---|---|
| M01 | Массив сортируется по алфавиту | СЛЕДУЕТ |
| M02 | Неизвестные ключи запрещены | ЗАПРЕЩЕНО |
| M03 | Пустые строки в массивах запрещены | ЗАПРЕЩЕНО |
| M04 | Пути ресурсов не выходят за папку скила | ОБЯЗАТЕЛЬНО |
| M05 | `dependencies.skills[].name` не равен имени самого скила | ЗАПРЕЩЕНО |
| M06 | `dependencies.skills` ссылается только на существующие корневые скилы | ОБЯЗАТЕЛЬНО |
| M07 | `dependencies.project[].path` существует в проекте | ОБЯЗАТЕЛЬНО |
| M08 | `dependencies.project[].owner` заполнен и называет контур-владелец | ОБЯЗАТЕЛЬНО |
| M09 | `generated` не указывает внутрь папки скила | ЗАПРЕЩЕНО |
| M10 | `kind = leaf` не содержит дочерних скилов | ОБЯЗАТЕЛЬНО |
| M11 | `kind = orchestrator` содержит хотя бы одного ребенка или зависимость скила | ОБЯЗАТЕЛЬНО |
| M12 | Манифест не содержит значений секретов, токенов и паролей | ЗАПРЕЩЕНО |

### 6.3 Зависимости

`dependencies.skills` описывает вызов другого скила, а не импорт его файлов.
Потребитель не имеет права запускать скрипт из чужой папки `scripts/`.

`required: false` означает, что скил работает без зависимости в урезанном режиме.
Урезанный режим ОБЯЗАТЕЛЬНО описан в `SKILL.md`, раздел `## Ограничения`.

`dependencies.project` описывает общий скрипт или инструмент проекта. Такой
скрипт не копируется в скил, но объявляется в каждом потребителе.

## 7. Скрипты и владение

| ID | Правило | Уровень |
|---|---|---|
| P01 | Скрипт, который использует ровно один скил, лежит в `scripts/` этого скила | ОБЯЗАТЕЛЬНО |
| P02 | Скрипт, который используют два и более скила, лежит в общей проектной области и объявлен в `dependencies.project` каждого потребителя | ОБЯЗАТЕЛЬНО |
| P03 | Запуск скрипта из `scripts/` другого скила запрещен | ЗАПРЕЩЕНО |
| P04 | Ссылка на зеркало среды из канона запрещена | ЗАПРЕЩЕНО |
| P05 | Каждый файл в `scripts/` упомянут в `SKILL.md` или в `skill.json` | ОБЯЗАТЕЛЬНО |
| P06 | Каждый упомянутый скрипт существует | ОБЯЗАТЕЛЬНО |
| P07 | Исполняемые файлы лежат только в `scripts/`, тесты только в `tests/` | ОБЯЗАТЕЛЬНО |
| P08 | Общая проектная область: `.tools/scripts/`, `.agents/skills/documentation-router/children/{project-doc,doc-verify}/scripts/`, `.agents/skills/task-router/children/testing-router/children/test-task/scripts/`, `.agents/skills/task-router/children/testing-router/children/browser-verify/scripts/`, `.doc/skil_data/harness-core/`, `.agents/skills/task-router/children/analytics/scripts/`, `.agents/skills/yadisk-screenshot/scripts/` | ОБЯЗАТЕЛЬНО |

Если скрипт нужен двум скилам, но они не должны зависеть друг от друга, скрипт
переносится в `.tools/scripts/` или в общий проектный контур с префиксом назначения. Дублирование файла
запрещено.

### 7.1 Правила, относящиеся к скилу

| ID | Правило | Уровень |
|---|---|---|
| X01 | Правило-триггер, по которому агент выбирает скил, остается в `.cursor/rules/{name}.mdc` | ОБЯЗАТЕЛЬНО |
| X02 | Шаг внутри уже выбранного скила оформляется как `references/{name}.md` | ОБЯЗАТЕЛЬНО |
| X03 | Файл `.mdc` внутри папки скила запрещен: клиенты не читают его как правило | ЗАПРЕЩЕНО |
| X04 | Перенесенный шаг упомянут в `SKILL.md` и удален из `.cursor/rules/`, реестра и `state/03-rules.md` | ОБЯЗАТЕЛЬНО |
| X05 | Правила MCP лежат в `.cursor/rules/mcp/{server}.mdc`, имя равно ключу сервера | ОБЯЗАТЕЛЬНО |

Различие простое: триггер работает до выбора скила, шаг работает после. Правило,
которое запускает скил, нельзя прятать в папку скила, иначе оно перестанет
срабатывать. Шаг, который нужен только этому скилу, наоборот, не должен занимать
место в общем каталоге правил.

Полное правило размещения MCP и совместимость сред:
[rules-placement.md](./archive/mcp/rules-placement.md).

### 7.2 Адаптерные скилы DeepSeek Harness

Скил `.dsh/skills/dsh-router` не входит в 25 корневых скилов канона. Это
адаптерный скил среды, но структура у него та же.

| ID | Правило | Уровень |
|---|---|---|
| A01 | Адаптерный скил имеет `SKILL.md`, `README.md` и `skill.json` | ОБЯЗАТЕЛЬНО |
| A02 | `README.md` описывает назначение и работу без ссылок | ОБЯЗАТЕЛЬНО |
| A03 | `skill.json` указывает `kind`, `resources`, `dependencies.project` для `.dsh/adapters` и `.dsh/scripts` | ОБЯЗАТЕЛЬНО |
| A04 | Поле `whenToUse` разрешено только в DSH-адаптере | СЛЕДУЕТ |
| A05 | Карточка адаптерного скила живет в DSH-документации, а не в `.doc/harnes/skills/` | ОБЯЗАТЕЛЬНО |
| A06 | Перенос адаптерного скила проверяет `copy-dsh-kit.ps1 -Check` | ОБЯЗАТЕЛЬНО |

Исключение по `whenToUse` не распространяется на канон. Если DSH-роутер будет
перенесен в `.agents/skills`, поле удаляется, а маршрутизация переходит в
`description` и таблицу `## Маршрутизация`.

## 8. Дочерние скилы

Дочерний скил это обычный скил внутри `children/`. Он не является отдельным
пунктом корневого каталога и не должен им быть.

| ID | Правило | Уровень |
|---|---|---|
| C01 | Дочерний скил лежит в `children/{child}/` и имеет полную структуру из раздела 2 | ОБЯЗАТЕЛЬНО |
| C02 | Имя дочернего скила уникально среди всех корневых и дочерних скилов | ОБЯЗАТЕЛЬНО |
| C03 | Родитель содержит раздел `## Маршрутизация` с таблицей `Запрос -> Дочерний скил` | ОБЯЗАТЕЛЬНО |
| C04 | Триггеры дочерних скилов продублированы в `description` родителя | ОБЯЗАТЕЛЬНО |
| C05 | Циклы между родителем и детьми запрещены | ЗАПРЕЩЕНО |
| C06 | Глубина вложенности не ограничена, но каждый родитель на пути обязан маршрутизировать ребенка | ОБЯЗАТЕЛЬНО |
| C07 | `children` в `skill.json` точно совпадает с папками `children/` | ОБЯЗАТЕЛЬНО |
| C08 | Дочерний скил имеет свой `README.md` и `skill.json` | ОБЯЗАТЕЛЬНО |
| C09 | Родитель собирает все триггеры потомков в `## Маршрутизация`; в `description` идет компактный набор в пределах лимита 1024 | ОБЯЗАТЕЛЬНО |
| C10 | Родитель обязан направлять запрос к ребенку через `## Маршрутизация`; автообнаружение клиента не считается маршрутизацией | ОБЯЗАТЕЛЬНО |
| C11 | В таблице маршрутизации перечислены все триггеры всех потомков, включая внуков | ОБЯЗАТЕЛЬНО |

Поведение сред:

| Среда | Находит вложенный `SKILL.md` | Следствие |
|---|---|---|
| Cursor | да, рекурсивно | дочерний виден и как отдельный скил, и через родителя |
| Kilo | нет, только `skills/{name}/SKILL.md` | дочерний доступен только через родителя |
| Antigravity | рекурсия не описана | считать, что нет; доступен через родителя |
| Claude Code | рекурсия не описана | считать, что нет; доступен через родителя |

Независимо от автообнаружения клиента родитель всегда собирает все триггеры
дочерних скилов в таблицу `## Маршрутизация`. В `description` остается компактный
набор ключевых фраз в пределах лимита 1024; полный перечень хранится в таблице.
Клиент может не видеть вложенный скил, но родитель обязан выбрать его по тексту.

## 9. Совместимость сред

| Что читает среда | Cursor | Kilo | Antigravity | Claude Code |
|---|---|---|---|---|
| `SKILL.md` | да | да | да | да |
| `name` и `description` | да | да | да | да |
| `scripts`, `references`, `assets` | да | да | да | да |
| `README.md` | игнорирует | игнорирует | игнорирует | игнорирует |
| `skill.json` | игнорирует | игнорирует | игнорирует | игнорирует |
| `children/` | рекурсивно | нет | не описано | не описано |
| `tests/` | игнорирует | игнорирует | игнорирует | игнорирует |

DeepSeek Harness не читает папку скилов как каталог правил. Канонические скилы
он читает через tool `skill(name)`, адаптерный роутер лежит в
`.dsh/skills/dsh-router/`. README и `skill.json` DSH игнорирует, они нужны
харнесу и проверкам переноса.

Формат не использует возможности одной среды, которых нет у остальных.

### 9.1 Где среды ищут скилы

| Корень | Cursor | Kilo | Antigravity | DSH | Codex | Claude Code |
|---|---|---|---|---|---|---|
| `.agents/skills` | да | нет | нет | нет | нет | нет |
| `.agents/skills` | да | да, по умолчанию | да, по умолчанию | да | не подтверждено | нет |
| `.kilo/skills` | нет | да | нет | нет | нет | нет |
| `.codex/skills` | да, совместимость | нет | нет | нет | да | нет |
| `.claude/skills` | да, совместимость | да при совместимости | нет | нет | нет | да |
| `.antigravity/skills` | нет | нет | нет | нет | нет | нет |
| `.gemini/skills` | нет | нет | нет, путь не документирован | нет | нет | нет |

Выводы:

1. `.agents/skills` это единственный общий корень Cursor, Kilo, Antigravity и DSH.
2. Codex требует `.codex/skills`, Claude Code требует `.claude/skills`. Это
   совместимые копии, а не общий канон.
3. Cursor читает `.codex/skills` и `.claude/skills`, поэтому даже при каноне в
   `.agents/skills` он увидит копию Codex. Полностью убрать дубль нельзя, пока
   Codex не читает `.agents/skills` напрямую.
4. Antigravity сканирует скилы на один уровень. `children/<child>/SKILL.md` не
   находится без родителя или `.agents/skills.json`.
5. Antigravity не читает `.mdc` и `alwaysApply` в правилах. Для нее нужен плоский
   `.agents/rules/*.md` с `trigger`.

Канон скилов: `.agents/skills`. Копии `.cursor/skills` и `.kilo/skills` не
создаются. Для Codex остается `.codex/skills`, для Claude Code при необходимости
`.claude/skills`. Cursor дополнительно читает `.codex/skills`, поэтому видит две
копии; полностью убрать ее можно только если Codex начнет читать `.agents/skills`.
Правила остаются в `.cursor/rules`: общего корня правил у сред нет.

Документ вводится в действие с 2026-11-02.

   `harness-selfcheck.sh`.

   период.
6. Перенос файлов не меняет поведение. Содержимое скриптов не правится, `sha256`

   остается доступен через `references/` и ссылку из `SKILL.md`. Правило-триггер
   остается в корне, иначе меняется момент его срабатывания.

## Известные проблемы и ограничения

### П-1: Разные правила обнаружения вложенных скилов

- Симптом: дочерний скил виден в Cursor и не виден в Kilo.
- Причина: Cursor обходит дерево рекурсивно, Kilo читает только первый уровень.
- Ограничение: дочерний скил всегда маршрутизируется родителем, автообнаружение
  не считается гарантией.
- Файлы: `.agents/skills/*/children/`

### П-2: Кириллица в именах файлов

- Симптом: имя скила или ресурса с кириллицей ломает проверку имени.
- Причина: стандарт разрешает только `a-z`, `0-9` и дефис.
- Ограничение: имена файлов и папок скила только латиница.
- Файлы: `.agents/skills/`

### П-3: Дубли корней обнаружения

- Симптом: один и тот же скил виден несколько раз.
- Причина: Cursor читает `.agents/skills` и `.codex/skills`; Kilo читает только
  `.agents/skills`. Канон `.cursor/skills` и копия `.kilo/skills` удалены.
- Ограничение: два видимых экземпляра в Cursor остаются из-за копии Codex.
- Файлы: `.agents/skills/`, `.codex/skills/`

---

### П-4: Внешний аудитор рекомендует удалить README

- Симптом: `skill-auditor` v3.1 выдает `README-IN-SKILL` и советует убрать README из папки скила.
- Причина: рекомендация взята из общих гайдов Anthropic, где README не является частью пакета скила.
- Ограничение: харнес требует README правилами S02, R06 и D01. Рекомендация внешнего аудитора не применяется, отклонение фиксируется здесь.
- Файлы: `.agents/skills/*/README.md`
