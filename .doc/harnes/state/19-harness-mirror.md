## Суть

Скил `harness-mirror` описывает харнес как данные: один JSON на один файл правила, скила, конфига или скрипта. Скрипт делает структуру, хеши, обратимость и связи по литералам, агент дописывает смысл. Из узлов собирается граф и статический просмотрщик, который отдаёт уже существующая панель.

План и нормативный формат лежат в [references/mirror-plan.md](../../../.agents/skills/harness-router/children/mirror/references/mirror-plan.md) и [references/mirror-format.md](../../../.agents/skills/harness-router/children/mirror/references/mirror-format.md). Скил переносим: в `SKILL.md` и `references/` нет названий продукта, номеров задач, локальных адресов и портов.

## 1a. Границы области

В индекс попадает только харнес: правила, скилы, скрипты, MCP-конфиги и их серверы.
Документация, задачи и продуктовый код не входят.

Механика в `scripts/harness_mirror.py`:

| Что | Где | Поведение |
|---|---|---|
| Область путей | `INDEX_PREFIXES`, `DEFAULT_PATHS` | только `.cursor/`, `.codex/`, `.kilo/`, `.agents/`, `.dsh/`; legacy `.antigravity` и `.gemini` удалены; `.doc/` не обходится |
| Связи | `detect_relations` | цель вне префиксов харнеса не создаёт связь |
| Полный скан | `cmd_scan` | записи кеша вне префиксов удаляются вместе с узлами |
| Повторный скан | `cmd_scan` | старые связи на `.doc` и другие не-харнес пути вырезаются из блоков и `global_relations` |
| Проверка | `cmd_check` | ошибка `relation leaves harness scope`, если связь вышла за харнес |
| Вне текущего набора | `cmd_scan` | файл харнеса, не попавший в текущий скан (зеркала, `.dsh`), обновляется, если изменились байты |

Границы определены в [01-canon-envs.md](./01-canon-envs.md), раздел "Границы харнеса".
Практический итог: документация меняется свободно, граф, скилы и проверки харнеса от
этого не зависят.

### Канон по поддереву

`.cursor/rules`, `.tools/scripts` и `.agents/skills` дают канонические узлы без суффикса среды. `.cursor/skills` это симлинк на `.agents/skills`, поэтому оба пути дают один `node_id`, а кеш хранит запись `.agents/skills`. Копии в `.codex`, `.kilo`, `.antigravity`, `.gemini`, `.dsh` и `.agents/rules` остаются зеркалами с суффиксом `@среда`.

### MCP-узлы

MCP-серверы это синтетические узлы `mcp:{name}`. Скрипт читает из `.cursor/mcp.json`
только имена, транспорт и команду, значения переменных не сохраняются. Узлы делает
`build`, файлов в `nodes/` у них нет, поэтому они живут только в `graph.json` и в
просмотрщике. `get`, `review` и `audit` по `mcp:` отвечают `node not found`: смысл
сервера хранится в правиле `.cursor/rules/mcp-{name}.mdc` и в
документе `.doc/harnes/mcp/{name}.md`, а не в узле индекса. Связи правил и скилов
на серверы идут с `target_type: mcp` и разрешены вне области файлов.

## 2. Формат v2.2

Один узел на файл. Склейка блоков по `order` возвращает файл байт в байт, включая BOM, CRLF и хвостовые переводы.

Отличия от черновика:

- `origin` у связи: `auto` ставит скрипт, `agent` ставит агент, и только у `agent` обязателен `anchor_text`;
- `transferable` в `meta`: false у локального adapter-файла;
- `final_newline` в `reconstruction_meta`;
- убран `repo_relative_path`, он дублировал `source_file_path`;
- убрано время разбора из узла, оно в `cache.map`.

## 3. Команды

| Команда | Назначение |
|---|---|
| `scan` | разбор файлов, узлы и кеш; по умолчанию только канон |
| `scan --include-mirrors --include-dsh` | добавить среды и DeepSeek Harness |
| `prompt --node ID` | задание агенту, без текста блоков |
| `apply --node ID --json FILE` | влить анализ, проверить якоря и типы |
| `get --node ID` | узел и его ребра |
| `get --node ID --slim` | подписи, триггеры, источники и рёбра без блоков |
| `bundle --skill NAME` | скил целиком: файлы, триггеры, источники, рёбра, неразрешённые связи |
| `audit --node ID` или `--skill NAME` | компактный отчёт аудита с покрытием и вердиктом |
| `lint` | проверки всего канона с уровнями error, warn, info |
| `review --all` | обзор всех скилов и правил |
| `review --skill NAME` или `--node ID` | пакет смыслового аудита по элементу |
| `set --node ID --block bNNN --content FILE` | заменить блок канона с проверкой обратимости |
| `set --node ID --file --content FILE` | заменить файл целиком, только скил или правило |
| `build` | `graph.json` и просмотрщик |
| `serve --port 8090` | отдельный просмотрщик, в текущем сервисе не используется |
| `check` | инварианты и обратимость |

Коды выхода: 0 успех, 1 проверяемое отрицание, 2 ошибка аргументов или окружения. `--root` не обязателен: корень ищется от расположения скрипта, затем от cwd. Это позволяет запускать скрипт из копии в любой среде.

## 3b. Консольный интерфейс агента

Граф целиком не читается: `graph.json` около 1.6 МБ. Для аудита есть шесть команд, они печатают компактный JSON и берут данные из узлов и графа.

| Команда | Назначение | Размер на скил `gototask` |
|---|---|---|
| `get --node ID --slim` | подписи, триггеры, источники, рёбра без блоков | 15 КБ |
| `bundle --skill NAME` | все файлы скила, триггеры, источники, уникальные рёбра, неразрешённые связи | 20 КБ |
| `audit --node ID` или `--skill NAME` | покрытие, рёбра, неразрешённые связи, предупреждения, заметки, вердикт | 19 КБ |
| `get --node ID` | полный текст блоками, когда нужен сам файл | 16 КБ в среднем |
| `lint` | находки по всему канону с уровнями важности | сводка и список |
| `review --all` | обзор всех скилов и правил одной таблицей | 15 КБ |

В `audit` два уровня замечаний: `warnings` влияют на `verdict` (незаполненный анализ, пустой `summary`, неразрешённые связи), `notes` только информируют (нет триггера, нет источников правды, нет входящих или исходящих связей). Поле `coverage` показывает, сколько файлов цели заполнено. Рёбра уникальны по паре и типу, `blocks` хранит число блоков, `anchors` до одного фрагмента в аудите и до пяти в графе.

Подробный разбор полей и пример ответа: [README скила](../../../.agents/skills/harness-router/children/mirror/README.md), раздел "Интерфейс для агента".

## 3c. Смысловой аудит

Структурные проверки мало что говорят о качестве харнеса. Для смыслового аудита добавлены две команды.

`lint` проверяет весь канон: циклы делегирования, самоссылки, изолированные узлы, скрипты без упоминаний, одинаковые подписи, наличие `SKILL.md`, битые связи, пустые `summary` и `details`, отсутствие триггера и источников правды. Находки делятся на `error`, `warn`, `info`, поэтому агент сначала смотрит на смысловые кандидаты.

`review --all` отдаёт компактный список всех скилов и правил. `review --skill` и `review --node` отдают пакет по одному элементу: дайджест разделов с заголовком и первой строкой, триггеры, источники, рёбра с якорями, замечания `lint` и вопросы для проверки смысла. Полный текст запрашивается только при сомнении через `get --node`.

Текущий прогон `lint`: 153 находки, из них 3 смысловых. Три цикла делегирования: `test-task` и `browser-verify`, `test-task` и `prepare-task-test`, `prepare-plan` и `test-task`. Самоссылки скилов больше не создаются: автолинк на собственный узел отбрасывается при разборе и чистится сканом. Остальное покрытие: 39 изолированных узлов, 42 скила и правила без источников правды, 36 без триггера, 33 скрипта без упоминаний.

Порядок смыслового аудита: [README скила](../../../.agents/skills/harness-router/children/mirror/README.md), раздел "Смысловой аудит".

## 3a. Правка и просмотр

Правка идёт по цепочке: файл в редакторе панели, `PUT /api/node` с `raw_file`, проверка типа и канона, запись атомарно с восстановлением переводов строк и BOM, повторный разбор на блоки, прошлая версия в `nodes/.history/`, затем пересобираются узел, кеш и граф. Если новый текст не делится на блоки байт в байт, исходник восстанавливается.

Писать можно только в канон, и только скилы и правила. Скрипты, конфиги и зеркала отвечают отказом: их меняют генераторы и синхронизация проекта.

Просмотр: слева дерево без зеркал. Папка скила содержит вложенные папки и файлы, клик по папке сворачивает её. Строка файла идёт слева направо: метка типа, имя файла, русская подпись. Подпись это `summary` от агента, иначе первое предложение `description` из frontmatter, иначе первый заголовок. Метки: S скил, R правило, P скрипт, C конфиг, D документ, M MCP. Правила и MCP-серверы идут отдельными списками ниже. Строка файла показывает метку типа, имя файла, число связей и русскую подпись. Поиск, фильтр типа и чекбокс `только без связей` сужают и дерево, и граф, состояние передаётся адресом `?filter=`, `?iso=1`, `?linked=1`. Клик по файлу включает фокус: в графе остаются выбранный узел и его прямые связи. Раскладка фокуса идёт слева направо, входящие, узел, исходящие, поэтому линии не проходят через карточки. Снять фокус можно кнопкой в заголовке или `Esc`. Ширины левой и правой колонки тянутся мышкой и запоминаются в браузере.

Центр без фокуса показывает связи по типам: колонки по типу файла, порядок карточек считается по связям, иерархии папок в центре нет. Связи одной пары и одного типа свёрнуты в одну линию со счётчиком, наведение показывает тип, имена концов и фрагмент-якорь. По умолчанию показан только канон, зеркала включаются галочкой.

Под кнопками редактора идёт навигация по заголовкам файла, ниже JSON узла из индекса: только чтение, без записи в файл, с размером в килобайтах и копированием.

Просмотр и правка идут через `/harness/` сервиса `copytrust-tools` на
`127.0.0.1:8077`. Отдельного `serve` на `8090` и юнита `harness-mirror.service`
больше нет. Сохранение вызывает `harness_mirror.py set`, затем `build` и `check`;
история остаётся в `nodes/.history`. Запуск сервиса:
`bash .doc/web/start.sh`. Устройство сервиса:
[22-panel-service.md](./22-panel-service.md).

## 4. Зеркала и дубли

- канон скилов `.agents/skills`, канон правил и MCP `.cursor/`;
- у зеркала `canonical: false`, `projection_of` на канон, `node_id` с суффиксом `@kilo`, `@antigravity` и так далее;
- при совпадении содержимого без учёта переводов строк зеркало наследует описание, жизненный цикл, источники правды и анализ канона, повторный разбор моделью не нужен;
- `build` ставит ребро `mirrors` и состояние `equal` или `drift`;
- `set` пишет только в канон, копии пересобирает существующий `sync-agent-views.sh`;
- свой механизм переноса скил не создаёт, `verify_parity.py` и синк остаются за проектом.

Сравнение для `drift` идёт по хешу с нормализацией окончаний строк, как в паритете проекта. Иначе CRLF в каноне давал бы ложное расхождение.

## 7. Ограничения

- Связи только по явным упоминаниям.
- Разбиение скриптов эвристическое, вложенные функции остаются в блоке родителя.
- Смысловой слой пустой, пока агент не выполнил `prompt` и `apply`.
- Правка идёт только в канон, зеркала пересобирает `sync-agent-views.sh`. API записи принимает только loopback `Origin`.
- Просмотрщик строит раскладку по типам, для сотен узлов это список колонок, а не силовая физика.
