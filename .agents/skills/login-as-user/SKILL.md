# Login As User — вход под клиентом через админку

Воспроизводит официальный механизм имперсонейта (кнопка «Логин» в профиле
клиента админки), не пароль клиента и не отдельный тестовый вход. Работает
только на dev-стенде.

1. [`.doc/qa/fragments.md`](../../../.doc/qa/fragments.md) — фрагмент

## Шаг 0.1 — Проверка окружения (обязательно перед первым действием)

Имперсонейт даёт полный доступ к аккаунту клиента (сессия, документы,
платежи). Только dev/test-стенд:

```
⚠️ Подтверди окружение перед входом под клиентом:
- Целевой URL: [домен из запроса/контекста]
- Это dev-стенд (.tools/docker-test), не прод? (да/нет)
```

Если нет явного подтверждения, что это dev-стенд — не выполнять, спросить.

---

## Шаг 1 — Определи целевого клиента

- Если пользователь дал `clientId` — использовать напрямую.
- Если дал email/логин/ФИО — найти через список клиентов админки
  (`admin/m_router.php?q=client/list`, поиск по фильтру) и подтвердить
  найденного клиента пользователю перед входом (`ФИО, email, id`), если
  найдено больше одного совпадения — спросить, какой.

---

## Шаг 2 — Выбери контекст выполнения

### Контекст A — внутри Codeception-теста (Cest)

Готовый фрагмент, ничего писать вручную:

```php
$I->loginAsClientById($clientId);
// далее $I уже на /account/edit под этим клиентом
```

Клиент с этим `clientId` должен уже существовать в БД (фикстура теста
`haveInDatabase('ct_client', [...])` или `haveInDbDefaultClient()` для id=1) —
метод только выполняет вход, не создаёт клиента.

### Контекст B — интерактивная проверка через Playwright MCP

Реальная кнопка «Логин» в `admin/templates/profile/edit/profile-info.tpl`
(`@click="loginByClient"`, класс `btn blue`) открывает результат в новом
окне (`window.open('/account/edit', '_blank')`). Инструмент `browser_tabs`
сейчас в `disabledTools` (`.cursor/mcp.json`) — вместо клика по кнопке и
переключения вкладок выполни тот же запрос, что делает кнопка, через
`browser_evaluate`, без открытия второго окна:

1. Залогинься в админку (`browser_navigate` на `/admin/`, форма логина
   администратора — реальные dev-креды окружения, не тестовая фикстура)
2. `browser_navigate` на `/admin/m_router.php?q=client/edit/{clientId}` —
   убедиться, что клиент открылся (снапшот, сверить ФИО/email с шагом 1)
3. `browser_evaluate`:
   ```js
   () => {
     const xhr = new XMLHttpRequest();
     xhr.open('POST', '/admin/m_router.php?q=client/login-by-client', false);
     xhr.setRequestHeader('Content-Type', 'application/x-www-form-urlencoded');
     xhr.send('clientId=' + CLIENT_ID);
     return xhr.status;
   }
   ```
   (подставить реальный `clientId`; ожидаемый статус 200)
4. `browser_navigate` на `/account/edit` — та же вкладка, без переключения
5. `browser_snapshot` — подтвердить, что открылся личный кабинет клиента
   (не форма логина — иначе имперсонейт не сработал)

## Шаг 3 — Подтверждение результата

Перед тем как продолжать любую проверку/репро бага под клиентом — убедиться,
что личный кабинет реально принадлежит нужному клиенту (email/ФИО на странице
профиля совпадает с найденным на Шаге 1), не только что страница загрузилась.

## Hard rules

- Никогда не выполнять на проде — только dev/test-стенд, подтверждённый на Шаге 0.1
- Не хранить и не логировать реальный пароль клиента — механизм имперсонейта
  его не требует
- Не кликать по кнопке «Логин» через Playwright MCP пока `browser_tabs`
  выключен в `mcp.json` — использовать `browser_evaluate` (Шаг 2, контекст B)
- Не создавать клиента с нужным `clientId` самостоятельно без запроса —
  если клиента с таким id нет, сообщить и спросить, создавать фикстуру или
  это ошибка в переданном id
