## Плохой текст, так писать нельзя

```
Реализован механизм отмены заказа на удаление ОИС — клиент может отменить неоплаченный заказ, а чужой клиент не может.

Ключевое: rollback скрытого платежа в OrderXhrController.
```

Здесь канцелярит, длинное тире, оборот "может, а не может" и имя класса без нужды.

## Нормальный отчёт

Пользователь: напиши отчет для жиры 2070.

```
Текст для Jira:

Сделал отдельный заказ на удаление объекта. Заказ хранит номер ОИС и владельца. После оплаты сайт передает запрос на удаление в сервис депонирования. Клиент может отменить свой неоплаченный заказ; отмена чужого заказа запрещена.

релиз 5.7.3
```

Если выкладка на д8 подтверждена, перед релизом допустима фраза `Залил на д8.`.
Названный стенд сам по себе не подтверждает выкладку.

Дальше отдельным списком пути из `scripts/collect-shots.py`. В текст для Jira их не вставлять.

## Нормальный отчет с найденной проблемой

Пользователь: напиши отчет для жиры 2077, на d8 нашли проблему с уведомлениями.

```
Текст для Jira:

После оплаты заказ уходил в работу и ждал запрос (хук) от сервиса депонирования на адрес `https://www.d8.copytrust.ru/TaskFinished.php` о завершении задачи. Если запрос не приходил, заказ оставался в работе.

Проблема на д8: сервис депонирования продлевает объекты, но хук о завершении не всегда доходит до сайта на `https://www.d8.copytrust.ru/TaskFinished.php`. Смотрел по логам: 3 ноября запрос пришел по 2 задачам из 5, 6 ноября не пришел ни по одной из 3. Где теряется запрос, по логам сайта не установлено.

Теперь после оплаты заказ уходит в работу, задача уходит в сервис депонирования, а заказ ждет запрос (хук) на адрес `https://www.d8.copytrust.ru/TaskFinished.php`: сервис сообщает, что задача выполнена. Если запрос не пришел за 5 минут, сайт сам запрашивает у сервиса депонирования срок хранения объекта. При совпадении срока объект считается продленным, а заказ закрывается со статусом выполнен, когда подтверждены все объекты. При расхождении сайт повторяет проверку; если после 30 минут срок по-прежнему не подтвержден, сайт фиксирует ошибку. Если сервис недоступен и прочитать срок нельзя, сайт продолжает ждать и повторяет запрос.

Если часть объектов обработана, а часть получила фатальную ошибку (объект нельзя обработать), заказ закрывается со статусом выполнен частично, а деньги возвращаются на лицевой счет равной долей от суммы заказа за каждый неудавшийся объект. Если фатальная ошибка по всем объектам, заказ отменяется с полным возвратом. При остальных ошибках заказ получает статус ошибка без возврата. Причина и время ответа пишутся в комментарий к заказу.

релиз 5.7.3
```

Проблема идет между "раньше" и "теперь". В ней нет имен функций и цитат кода: только что происходит, когда и что с этим делает сайт.

Адрес, даты, количество задач и интервалы принадлежат этому примеру. Для другой
задачи бери значения из ее источников. Не называй отсутствие входящего хука
доказательством того, что внешний сервис его не отправлял.
