# Ядро задач

Родительский скил для источников задач. Каждый трекер живет в отдельном дочернем скиле, общие правила источников и отчетов лежат здесь.

## Когда применять

- Нужно подключить или перенести адаптер трекера.
- Нужно понять, откуда берется задача и как формируется идентификатор.
- Нужно изменить экспорт, чтение или аналитику задач.

## Вход

- Описание источника задач и его доступов.
- Формат `task_id`: Jira, локальный `0_N` или Kaiten.
- Требования к отчету и данным.

## Шаги

1. Определить источник задачи по `references/sources.md`.
2. Выбрать дочерний скил: `children/jira`, `children/kaiten`, `children/analytics`, `children/testing-router`, `children/reporting-router` или `documentation-router`.
3. Проверить, что код адаптера и MCP-конфиг принадлежат этому скилу.
4. Для отчета в трекер использовать отдельный скил `task-report`.

## Маршрутизация

| Запрос | Дочерний скил |
|---|---|
| Jira, экспорт задачи и MCP jira-task | `jira` |
| Метрики и аналитика задач | `analytics` |
| Kaiten, контракт адаптера | `kaiten` |
| Перейти к задаче, переключить ветку | `gototask` |
| Собрать diff задачи | `task-diff` |
| Задокументировать задачу | `documentation-router/children/task-doc` |
| Завести задачу из Jira | `task-intake` |
| Проверить код задачи | `task-code-review` |
| HTML-отчет по изменениям | `reporting-router/children/task-change-report` |
| Короткий отчет в трекер | `reporting-router/children/task-report` |
| Подготовить браузерный тест | `testing-router/children/prepare-task-test` |
| Проверить задачу тестами | `testing-router/children/test-task` |
| Кто менял код и в каких задачах | `git-task-blame` |

## Выход

- Адаптер трекера с кодом, документацией и MCP.
- Понятный источник задачи и правило идентификатора.
- Аналитика и отчеты без дублирования экспорта.

## Ограничения

- `task-report` не владеет экспортом задач.
- `kaiten` пока docs-only: кода и MCP нет.
- `analytics` считает метрики задач, а не аудит харнеса.
- Секреты остаются в env, не в скилах.
