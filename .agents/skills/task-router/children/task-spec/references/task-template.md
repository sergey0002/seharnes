# Шаблон документа задачи

Документ пишется для программиста, который не видел переписку. Он должен понять
задачу без вопросов и без доступа к чату.

## Структура

```markdown
# {Название задачи}

<!-- meta
type: task
status: draft
source: conversation
draft_id: {id}
created: {YYYY-MM-DD}
-->

## 1. Цель и ценность

Одно предложение: какую проблему пользователя или бизнеса решает задача и какой
результат считается успехом.

## 2. Контекст и текущее поведение

Где сейчас возникает проблема: экран, роль, сценарий, файл, класс, маршрут или
таблица. Что происходит сейчас и чем это плохо. Факты без пересказа переписки.

## 3. Требования

### R1. {Короткое имя}

- Актор: кто выполняет действие.
- Предусловие: что уже должно быть настроено или открыто.
- Действие: что именно делает пользователь или система.
- Результат: что видно, сохраняется или меняется после действия.
- Источник: R-0001, A-0001.

### R2. {Короткое имя}

...

## 4. Декомпозиция

Заполняется, только если задача распадается на независимые части.

| Часть | Границы | Требования | Результат |
|---|---|---|---|
| 1 | ... | R1, R2 | ... |

## 5. Критерии приемки

| ID | Проверяемое условие | Ожидаемый результат |
|---|---|---|
| AC1 | ... | ... |

Критерий приемки проверяем: у него есть конкретное действие и наблюдаемый
результат. Формулировки "работает корректно" и "ошибок нет" не считаются.

## 6. Вложения

| ID | Файл | Что показывает |
|---|---|---|
| A-0001 | [001-screen.png](attachments/001-screen.png) | ... |

## 7. Вне области

Что задача явно не меняет. Сюда попадает все, что пользователь назвал, но
решение отложил, и все смежные сценарии, которые нельзя трогать.

## 8. Открытые вопросы и принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| ... | ... | ... |

Если вопрос блокирует реализацию, он задан пользователю до публикации. Остальные
вопросы имеют выбранное значение по умолчанию.

## 9. Источники требований

| ID | Тип | Где |
|---|---|---|
| R-0001 | замечание | notes.md |
| A-0001 | скриншот | attachments/001-screen.png |
```

## Проверка однозначности

Перед сохранением проверить каждый пункт:

- [ ] Название задачи называет объект и результат, а не тему разговора.
- [ ] Цель понятна без чтения требований.
- [ ] Каждое требование имеет актора, предусловие, действие и наблюдаемый
      результат.
- [ ] Каждое требование ссылается на исходное замечание или вложение.
- [ ] Каждое замечание пользователя закрыто требованием, критерием приемки или
      разделом "Вне области".
- [ ] Каждый скриншот связан относительной ссылкой и объяснен.
- [ ] Нет требований, которые можно понять двумя способами.
- [ ] Нет неподтвержденных имен файлов, классов, маршрутов и таблиц.
- [ ] Критерии приемки проверяемы без догадок.
- [ ] Открытые вопросы не оставлены без решения и не выданы за требования.

## Запрещенные формулировки

| Плохо | Почему | Как надо |
|---|---|---|
| Улучшить страницу | нет объекта и результата | На странице заказа скрыть блок "Оплата", если заказ отменен |
| Исправить баг с оплатой | нет сценария | При оплате картой с истекшим сроком показывать ошибку "Срок карты истек" и не создавать платеж |
| Сделать как надо | нет критерия | Кнопка "Сохранить" активна только при заполненных полях "Имя" и "Телефон" |
| При необходимости добавить лог | нет условия | При ошибке оплаты писать в лог номер заказа и код ответа платежного шлюза |
