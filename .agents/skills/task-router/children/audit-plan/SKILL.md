# audit-plan

Проверяет и сразу исправляет план. План пишет `prepare-plan`, проверяет и
дополняет этот скил. На выходе один артефакт `plan.md`, готовый к исполнению, с
видимыми метками аудиторских правок. Отдельного файла аудита и хешей нет.

## Когда применять

- пользователь говорит `проведи аудит плана`, `аудит плана`, `audit the plan`,
  `проверь план перед реализацией`;
- автор плана просит независимую проверку перед `status: ready`;
- план уже правили, и нужен новый проход;
- нужен второй или третий аудитор после первого прохода.

Не применять для написания первого плана, реализации, тестов, документации
задачи и code review.

## Вход

| Что | Обязательность | Как получить |
|---|---|---|
| Текущий план | обязательно | `plan.md` или `stage{N}/plan.md` в папке задачи |
| Бриф задачи | обязательно | `task.md`, свежий экспорт при устаревании |
| Исходники из патчей | обязательно | пути из раздела `## Правки по файлам`, читаются целиком |
| Критерии | обязательно | `references/criteria.md` |
| Порядок прохода и формат меток | обязательно | `references/workflow.md` |
| Журнал прошлых проходов | если есть | секция `## Аудит плана` в самом плане |

Хеши плана и источников не нужны. Версия плана это поле `plan_rev` в meta и
номер последнего прохода в журнале.

## Шаги

1. **Открыть проход.** Прочитать план целиком и журнал `## Аудит плана`.
   Назначить следующий номер: `A1`, `A2` и далее. Записать дату и имя аудитора.
2. **Проверить версию.** Сравнить `plan_rev` в meta с `plan_rev` последней
   строки журнала. Если версия выросла, прошлый вердикт устарел, нужен полный
   проход. Если план правили без роста версии, вердикт `blocked`.
3. **Пересобрать доказательства.** Пройти `references/workflow.md`: радиус,
   связанные задачи, история строк, чтение файлов по политике размера.
4. **Пройти критерии C1-C6.** Для каждого критерия взять метод и инструменты из
   `references/criteria.md` (разделы "Метод проверки по критериям" и "Набор
   инструментов по уровню риска"). Получить `pass`, `fail` или `blocked` с
   доказательством из чтения.
5. **Исправить план на месте.** Каждую правку вносить прямо в `plan.md`: патчи,
   сценарии, таблицы, источники. Перед правкой поставить видимую метку прохода
   по формату из `references/workflow.md`.
6. **Обновить журнал.** Добавить строку в `## Аудит плана`: номер, дата, аудитор,
   версия плана до правок, что изменено, вердикт.
7. **Выставить статус.** `pass` дает `audit_status: passed` и `status: ready`.
   `fail` оставляет `failed` и `draft`. `blocked` оставляет `blocked` и `draft`.
8. **Не решать за пользователя.** Если находку нельзя закрыть без смены рамок
   задачи, продуктового решения или нового требования, пометить ее `blocked` в
   журнале и не выдавать `ready`.
9. **Передать результат.** Один обновленный `plan.md` и короткий отчет в чат:
   номер прохода, что исправлено, что осталось, вердикт.

## Выход

- обновленный `plan.md` с исправлениями, метками проходов и журналом
  `## Аудит плана`;
- `audit_status`, `status`, `plan_rev`, `audit_passes` и `last_audit` в meta,
  согласованные с последним проходом;
- сообщение в чат: проход, число правок, открытые находки, вердикт.

Других файлов скил не создает.

## Ограничения

- Править можно только `plan.md`. Продуктовый код, шаблоны, тесты и канон
  харнеса не меняются.
- Аудит не пишет отдельный `plan-audit.md`, не считает `plan_hash` и не ведет
  таблицу хешей источников.
- Автор плана не может быть аудитором своего плана. Само-ревью не считается
  независимым.
- Проходы выполняются последовательно. Два аудитора одновременно один план не
  правят.
- Метки прошлых проходов не удаляются и не переписываются. Новый проход
  добавляет свою метку и новую строку журнала.
- Если план изменили после прохода и подняли `plan_rev`, нужен новый проход.
- Без отдельного работника или при недоступном брифе вердикт `blocked`,
  `ready` не ставится.
- Максимум две автоматические итерации на одну нерешенную находку, затем
  `needs_design_review`.

Формат меток, журнала и порядок прохода: `references/workflow.md`.
Критерии: `references/criteria.md`. Связи: `references/skill-links.md`.
