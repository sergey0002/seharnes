## Суть
Полный аудит архитектурной документации: находит активные файлы проекта без упоминания в доках (90 дней), устаревшие документы (>60 дней без updated), сломанные внутренние ссылки, документы без meta-блока, изолированные документы (никто не ссылается, кроме index.md), и топ-20 активных файлов за 30 дней как кандидатов на документирование. Уважает `.gitignore` через `git ls-files` и strict-фильтр (исключает vendor, node_modules, плагины).

## Когда запускать
- При начале работы с документацией проекта (bootstrap).
- Периодически (недельно) для контроля качества доков.
- По команде пользователя «проанализируй аудит» — агент читает вывод и предлагает исправления.
- Перед крупным релизом для выявления пробелов.

## Аргументы
| Аргумент | Алиас | Тип | Обязателен | По умолчанию | Что делает |
|---|---|---|---|---|---|
| -RelPath | | string | нет | | Относительный путь для проверки конкретного файла/папки |
| -AllBasenamesInProject | | hashtable | нет | | Хеш-таблица basename→пути для проверки коллизий имен |

## Коды выхода
Скрипт не возвращает явные коды выхода (всегда 0). Результат — текстовый отчёт в stdout.

## Что читает и что пишет
**Читает:**
- `.doc/architecture/*.md` — все архитектурные документы (кроме `_map/`, `_*`)
- `git log --since=... --name-only` — активные файлы за 90 и 30 дней
- `.gitignore` / `git ls-files` — для фильтрации исключённых путей

**Пишет:**
- Ничего (только stdout). Отчёт предназначен для чтения агентом/человеком.

## Побочные эффекты
- Нет побочных эффектов (read-only).

## Окружение и зависимости
- Требует `git` (для истории активности и проверки ссылок).
- Использует `_lib.ps1` из той же папки: `Get-ProjectFiles`, `ConvertTo-FullPath`, `Test-StrictExcluded`, `Get-DocCodeRefs`, `Normalize-RelativePath`, `Read-TextFile`.

## Ограничения
- Работает только с backtick-путями в архитектуре (`code.php`); не видит упоминания в простом тексте.
- Проверка basename с коллизиями может дать ложные срабатывания, если в проекте несколько файлов с одинаковым именем.
- `git` должен быть доступен и репозиторий не должен быть shallow.
- Не проверяет внешние ссылки (http://, https://).
- Строгий фильтр (`Test-StrictExcluded`) исключает известные паттерны шума.

## Связи
- Вызывается: агент по команде «проанализируй аудит», вручную
- Зависит от: `map-project.ps1` (структура), `_lib.ps1` (утилиты)
- Результат используется: агент создаёт план документирования, заводит задачи на отсутствующие docs
