## ШАБЛОН doc.md

Использовать при создании нового файла (если doc.md не существует) и при правке
живого doc.md без `task.json`.
Формат строго по [`doc_rules.md`](../../../../.doc/harnes/doc_rules.md): meta-блок,
потом `## Суть`, затем тематические секции, затем `## Связи`,
`## Известные проблемы и ограничения`, `## История изменений`.

Если у задачи есть `task.json`, `doc.md` генерируется из модели (`jsondoc.py render`)
и имеет собственный набор секций: `## Краткое описание`, `## Затронутые файлы`,
`## Подводные камни`, `## Решения`, `## Файлы`, `## Связанные задачи`, `## История`.
Его нельзя приводить к формату ниже и нельзя переименовывать секции руками:
правь модель через `jsondoc.py apply`, затем `jsondoc.py render`. `validate-docs.ps1`
проверяет такой файл по контракту generated view (маркер + ссылки), а не по
архитектурному шаблону.

Правила шаблона:

- `type` только из списка `doc_rules`: `architecture | rules | api | model | flow | config | index`.
  Для doc.md используй `flow` (это документ хода работ, не архитектура).
  Значения `task` и `task-doc` невалидны, валидатор выдаст предупреждение.
- Заголовки без эмодзи и без нумерации: ровно `## Суть`, `## Связи`,
  `## Известные проблемы и ограничения`, `## История изменений`.
- Порядок секций обязательный, `## Суть` идет первой после meta.
- В `## Известные проблемы и ограничения` записи в формате `### П-N: Название`.
- В `## История изменений` формат `- YYYY-MM-DD: что изменилось и почему, задача #N`.

Соответствие старым заголовкам (для живых doc.md без `task.json` при правке):

| Было | Стало |
|---|---|
| `## 📌 Краткое описание` | `## Суть` |
| `## 🗺️ Архитектурный контекст` | `## Связи` |
| `## ⚠️ Подводные камни` | `## Известные проблемы и ограничения` |
| `## 🔀 Принятые решения` | `## Решения и обоснования` (тематическая секция) |
| `## 📁 Затронутые файлы`, `## 📝 Заметки пользователя`, `## ✅ Статус`, `## 🔗 Связанные задачи` | тематические секции без эмодзи |
| `## 📅 История изменений` | `## История изменений` |

Не меняй заголовки в чужом документе без задачи: при первом касании приведи
к стандарту и отметь это в `## История изменений`.

```markdown
# Задача {TASK_ID}: {НАЗВАНИЕ}

<!-- meta
type: flow
status: actual
updated: {YYYY-MM-DD}
related: [task.md, plan.md, ../../../../.doc/architecture/{файл}.md]
tags: [task, {домен}]
-->

---

## Суть

3-5 предложений: что за задача, зачем, в каком состоянии. Читается первым.
```
