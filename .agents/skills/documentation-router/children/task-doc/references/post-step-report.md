## Post-step: task-change-report

После B4 и успешного B4.5 вызови `task-change-report` из skills текущей среды,
если пользователь не исключил HTML. При "только документацию"/"без HTML" завершись
одной строкой с путём `doc.md` и статусом индекса, без HTML и Jira.
Не составляй модель и Jira-текст самостоятельно: HTML-skill владеет моделью,
рендерингом и вызовом `task-report`. Обратный вызов task-doc запрещён.

Передай task ID, scope/стадию, ветку/commit, пути свежих task/diff/doc/test artifacts,
доказательства реализации, результаты Reuse/Impact Gate и B3, решения пользователя,
статус индекса, ограничения, разрешение на обновление HTML и результаты уже
выполненных шагов. Это контекст агента, не параметры renderer.
Переиспользуй в пределах цепочки только проверенные неизменённые источники;
при смене scope/commit или содержимого перепроверь затронутые факты. Экономия
чтений не отменяет B0-B4.5, MCP gates, evidence и полный шаблон документации.

Если diff устарел или его свежесть неизвестна, сначала нужен `task-diff` с
разрешением пользователя (согласие на post-push цепочку уже покрывает этот шаг).
Не создавай документацию с утверждением об актуальном scope по старому diff.

HTML-skill проверяет свежесть существующего отчёта, не только наличие файла.
Если обновление не разрешено, предложи: "Документация обновлена. Предлагаю обновить
HTML-отчёт с текстом для Jira. Напишите да, если сделать." Согласие на всю цепочку
после push уже разрешает обновление, повторно не спрашивай.
Новый отчёт входит в post-step документирования; существующий не перезаписывать
без согласия. Ошибка HTML не откатывает документацию, но итог остаётся неполным.
Дочерние skills возвращают результат без отдельных финальных сообщений в чат.
