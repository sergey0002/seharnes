## Суть

Содержит малые примитивы ОС для будущего supervisor: запуск отдельного процесса, остановка процесса и проверка локального пути. Политики переноса и права записи здесь нет.

## Когда запускать

Из supervisor или тестов, которым нужен один и тот же запуск процесса на POSIX и Windows. Как самостоятельный CLI не используется.

## Аргументы

Библиотечный модуль без CLI.

| Функция | Значение |
|---|---|
| `spawn_detached(command, cwd, stdout_path, stderr_path, env=None)` | Запускает процесс в новой сессии и возвращает pid. |
| `terminate(pid, timeout=5.0)` | Останавливает процесс или группу процессов с ограниченным ожиданием. |
| `path_is_local(path)` | Отклоняет UNC и сетевой диск Windows; на POSIX возвращает `True`. |

## Коды выхода

Не применимы: модуль вызывается как библиотека. Ошибки аргументов и путей поднимают `ValueError`.

## Что читает и что пишет

Читает метаданные каталогов и открывает файлы stdout/stderr. Пишет только переданные файлы вывода и не меняет управляемые файлы харнеса.

## Побочные эффекты

Создаёт процесс и два файла лога с правами `0600`. `terminate` отправляет сигнал или вызывает фиксированный `taskkill` на Windows.

## Окружение и зависимости

Python 3 стандартной библиотеки. Windows-ветка использует `ctypes` и `taskkill`; POSIX-ветка использует `os.killpg`.

## Примеры

```python
from platform_ops import spawn_detached
pid = spawn_detached(["php", "-S", "127.0.0.1:8077"], root, out, err)
```

## Ограничения

Примитивы не проверяют доверие к команде, не читают план и не разрешают apply. `spawn_detached` не создаёт Target и не проверяет свободное место. Проверка пути основана на `lstat` и не защищает от конкурентной замены предка. Windows-ветка не покрыта тестами в этом окружении.

## Связи

Будущий supervisor обновления и `install.ps1`/`install.sh`. Не связан с `transfer_*` бизнес-логикой.
