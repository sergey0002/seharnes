## Суть

Сравнивает выбранные файлы commit локального bare Git-хранилища с проектом. Результат — JSON-предпросмотр, не разрешение на запись.

## Когда запускать

Для диагностики выбранных путей в подготовленном локальном хранилище; это не мастер миграции.

## Аргументы

| Аргумент | Значение |
|---|---|
| `--repo` | Доверенное локальное bare-хранилище. |
| `--commit` | Полный идентификатор commit. |
| `--base-commit` | Необязательный полный ID исторического commit для сравнения; не является подтверждённым receipt. |
| `--use-receipt` | Вместо `--base-commit`: прочитать экспериментальный receipt Target из `.doc/web/state/transfer/receipt.json`; требует `--root`. |
| `--target` | Существующий или будущий каталог проекта. |
| `--path` | Относительный путь; повторяется для каждого файла. |
| `--root` | Вместо `--path`: обнаружить отслеживаемые файлы под заданным корнем Git; можно повторять. |
| `--local` | Выбранный путь, принадлежащий проекту; можно повторять. |
| `--use-local-policy` | Прочитать `.doc/harnes/state/canon-paths.local.yaml` Target; требует `--root` и `--base-commit` или `--use-receipt`. |
| `--max-file-bytes` | Максимальный размер файла, по умолчанию 8 МиБ. |

## Коды выхода

`0` — предпросмотр построен; `2` — ошибка аргументов или проверки.

## Что читает и что пишет

Читает Git-объекты и выбранные файлы Target. Пишет JSON в stdout; Target не создаёт и не изменяет.

## Побочные эффекты

Запускает локальный Git для чтения объектов. Checkout, hooks и код релиза не запускаются.

## Окружение и зависимости

Python 3 и Git в PATH; библиотеки `transfer_git`, `transfer_inventory`, `transfer_plan` и `transfer_diff` входят в этот скил. Для известных сигнатур используется установленный доверенный скрипт Mirror, не код из Git-кандидата.

## Примеры

```sh
python3 .agents/skills/harness-router/children/new-project/scripts/git-preview.py --repo /tmp/store.git --commit FULL_COMMIT_ID --target /tmp/project --path .agents/skills/example/SKILL.md
```

## Ограничения

Пути либо корни задаются вручную. Исторический commit, если указан, не доказывает состояние установленного харнеса и не заменяет receipt. `--root` ищет файлы в Git и Target только под выбранными корнями; защищённые пути выводятся отдельно и не читаются. Это path-based сканирование не защищено от всех конкурентных замен и не разрешает запись. Скрипт не получает репозиторий, не проверяет доверие к commit и не проверяет полноту поставки. Проверка содержимого применяет только известные сигнатуры Mirror и не гарантирует обнаружение всех секретов. Права Git и ОС ещё не приведены к общей модели. Результат нельзя применять автоматически.

Файл только в Target без подтверждённого владельца помечается `unexpected_unclassified`, а не автоматически пользовательским. Явно переданный через `--local` путь показывается как локальный.
`directory_summary` рекурсивно считает выбранные файлы по каталогам, наличие в источнике и Target, предложенные статусы и действия и число требующих review. Это предложения, а не выполненные операции; защищённые пути не входят в счётчики, размеры пока не собираются.
Если локальный путь присутствует и в историческом commit, он остаётся локальным: прежний хеш показывается отдельно и не считается доказательством принадлежности поставке.
Имена с отдельными маркерами `secret`, `token`, `password` и `credential` также считаются защищёнными. Это консервативный фильтр имён: он может пропустить секрет в файле с обычным именем или пометить безвредный файл.

При `--use-local-policy` допустимы только `schema_version: 1` и список `custom_components` с полями `kind`, `name`, `path`, `owner`, `docs_layout_key`. Записи вне выбранных корней, пересекающиеся друг с другом или с файлами выбранной базы, отклоняются. Файлы под допустимыми записями отмечаются локальными; совпадение с новым Git-файлом остаётся конфликтом. Исторический commit не является receipt: отсутствие в нём пути не доказывает, что путь не принадлежит поставке. Проверка работает только в предпросмотре и не разрешает применение изменений. Полный загрузчик policy bundle ещё не реализован.

Экспериментальный receipt — JSON с `schema_version`, `release_url`, `commit`, `profile`, `files`; каждый элемент `files` содержит `installed_hash` (SHA-256), `mode`, `role: "owned"`, `decision`. Поддерживаются решения `installed`, `adopted`, `merged`, `replaced`. Это ещё не receipt, создаваемый транзакцией переноса: источник и содержимое не аутентифицируются, `release_url` не выводится, результат помечается `receipt_unverified` и не применим. Невалидный receipt останавливает предпросмотр, пути из него нельзя объявить локальными.
