# copy-project

Перенос приложения, а не харнеса. Скрипт создаёт копию Git-снимка в новой папке
и готовит отчёт о том, что ещё нужно для запуска. Агент проверяет отчёт вручную
и не объявляет перенос готовым, пока обязательные параметры не заполнены.

## Когда применять

- нужно получить чистую копию проекта в другой папке;
- нужна рабочая Git-копия с историей, ветками, remotes и `git status`;
- нужно исключить `.agents`, `.cursor`, `.codex`, `.kilo`, `.dsh`, `.serena` и
  другие файлы и каталоги харнеса;
- нужно понять, какие локальные конфиги и переменные нужны для запуска;
- нельзя копировать секреты и рабочую базу автоматически.

Не применять для переноса kit харнеса: это задача `new-project`.
`.dsh` в текущем репозитории находится в локальном `.git/info/exclude` и не
попадает в `git ls-files`; скрипт также исключает его, если другой проект
отслеживает этот каталог.

## Вход

- абсолютный путь Source, который является Git-репозиторием;
- абсолютный путь Target, которого ещё нет;
- решение: включать ли незакоммиченные tracked-изменения.

## Шаги

1. Проверить состояние Source: `git status --porcelain`, `git rev-parse HEAD`,
   `git ls-files --others --exclude-standard`, наличие `.gitmodules`,
   атрибуты LFS, символические ссылки в индексируемом наборе и то, что `.git`
   является каталогом, а не файлом.
2. Выполнить перенос:

```bash
bash .agents/skills/harness-router/children/copy-project/scripts/copy-project.sh \
  --source /path/to/source \
  --target /path/to/target
```

Незакоммиченные tracked-изменения включаются только явно:

```bash
bash .agents/skills/harness-router/children/copy-project/scripts/copy-project.sh \
  --source /path/to/source \
  --target /path/to/target \
  --include-tracked-changes
```

Скрипт копирует tracked-файлы, затем `.git`, удаляет в копии `worktrees/` и
lock-файлы, проверяет читаемость репозитория и записывает счётчики Git в отчёт.

3. Открыть `STARTUP-REQUIRED.md` в Target и пройти чек-лист
   `assets/startup-checklist.md`.
4. Заполнить переменные окружения из шаблона или из хранилища секретов. Значения
   в отчёт и в Git не записывать.
5. Установить зависимости по найденным lock-файлам.
6. Выбрать режим базы: внешняя база, миграции проекта или явный дамп.
7. Запустить приложение и пройти smoke-проверку.
8. Отметить в отчёте незакрытые пункты. Статус `ready` допустим только когда
   обязательные параметры заполнены и проверка пройдена.

Ручной чек-лист: `assets/startup-checklist.md`. Подробное устройство, правила
исключений и разделы отчёта: `references/how-it-works.md`.

## Выход

- Target с каталогом `.git` (история, ветки, remotes, индекс) и без harness;
- `STARTUP-REQUIRED.md` со списком найденных файлов, переменных и шагов;
- число исключённых путей харнеса, секретных env-файлов и неперенесённых
  незатреканных файлов;
- параметры Git: размер `.git`, число удалённых worktree-регистраций и число
  незакоммиченных изменений в Target.

## Подводные камни

- До 2026-11-10 `.git` не копировался, и `git status` в Target падал с
  `not a git repository`. Теперь `.git` копируется целиком.
- Worktree-регистрации источника указывают на его абсолютные пути. Скрипт удаляет
  `.git/worktrees` в копии, иначе `git worktree remove` из копии мог задеть
  worktree источника.
- Lock-файлы `.git` (`index.lock`, `HEAD.lock`, `config.lock`) из источника
  удаляются, иначе копия остаётся заблокированной.
- Если harness или секретные env были tracked, в копии они видны как удалённые:
  индекс перенесён, а рабочие файлы исключены. В обычном проекте, где harness и
  `.env` в ignore, `git status` чистый.
- `.git/config` может содержать remotes с токенами, hooks и reflog. Копия
  наследует их; не публиковать копию без очистки.
- Незапушенные коммиты остаются в копии: `git status` покажет `ahead N`, как в
  источнике.
- `.git` может быть большим. Размер выводится в отчёте; для CopyTrust это 387M.
- `.git`-файл (linked worktree, submodule) не поддерживается и даёт код 3.
- `STARTUP-REQUIRED.md` добавляется в `.git/info/exclude` копии, чтобы отчёт не
  попадал в `git status`.

## Ограничения

- Секреты из рабочих файлов не копируются и не печатаются. История `.git`
  копируется как есть, секреты из истории не вычищаются.
- База данных не дампится и не импортируется.
- Submodules, Git LFS, символические ссылки и `.git`-файл дают код 3.
- Скрипт не устанавливает зависимости и не запускает приложение.
- Source не изменяется: индекс, `.gitignore`, `.git` и рабочие файлы остаются
  как были.

## История изменений

- 2026-11-10: `.git` снова копируется; удаляются worktree-регистрации и
  lock-файлы; в отчёт добавлены размер `.git` и состояние Git. Причина: копия
  CopyTrust2 осталась без репозитория, `git status` падал.
