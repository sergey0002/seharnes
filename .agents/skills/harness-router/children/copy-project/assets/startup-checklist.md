# Чек-лист запуска после переноса

Проверять по порядку. Пункт считается закрытым только при явном результате.

## 1. Git-состояние

- [ ] Записан коммит и ветка из STARTUP-REQUIRED.md.
- [ ] Если переносились tracked-изменения, их список совпадает с ожидаемым.
- [ ] `.git` есть, `git -C <target> status` выполняется.
- [ ] Ветка и коммит в Target совпадают с отчётом.
- [ ] В `.git/worktrees` нет регистраций, указывающих на исходный репозиторий.
- [ ] `git status` показывает только удаления исключённых harness/env или
  незакоммиченные tracked-изменения.
- [ ] Remotes в `.git/config` проверены; токены в URL не публикуются.
- [ ] В Target нет harness-каталогов и `AGENTS.md`.

## 2. Окружение

- [ ] Найден шаблон окружения: `.env.example`, `.env.dist` или `.env.sample`.
- [ ] Если шаблона нет, список переменных собран из кода и подтверждён чтением конфигурации.
- [ ] Каждая обязательная переменная заполнена оператором или из хранилища секретов.
- [ ] Значения не попали в Git, отчёт и логи.
- [ ] Файл окружения подключён приложением: проверено имя и путь, которые читает код.

## 3. Зависимости

- [ ] Для каждого lock-файла выполнена штатная установка.
- [ ] Версия языка и платформы совпадает с требованиями проекта.
- [ ] Расширения, бинарники и сервисы, которых нет в репозитории, установлены.

## 4. База данных

- [ ] Выбран режим: внешняя база, миграции проекта или явный дамп.
- [ ] Параметры подключения проверены без печати пароля.
- [ ] Схема соответствует коду: миграции применены или дамп восстановлен.
- [ ] Данные production не использованы без разрешения.

## 5. Файлы вне Git

- [ ] Проверены каталоги загрузок, кэша и сгенерированных файлов, если код их ожидает.
- [ ] Отсутствие таких файлов не ломает старт; иначе они перечислены в отчёте.

## 6. Запуск

- [ ] Приложение стартует без ошибок конфигурации.
- [ ] Основная страница или health-проверка отвечает ожидаемым кодом.
- [ ] Критичный пользовательский сценарий проходит.
- [ ] В логах нет ошибок, связанных с отсутствующей конфигурацией.

## 7. Итог

- [ ] Незакрытые пункты перечислены в отчёте.
- [ ] Статус `ready` выставлен только при закрытых обязательных пунктах.
