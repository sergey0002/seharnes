## Суть

`harness-mirror` строит цифровое зеркало агентского харнеса: один JSON на один файл правил, скила, конфига или скрипта, плюс граф связей и статический просмотрщик. Скрипт отвечает за структуру, хеши, обратимость и связи по литералам. Агент дописывает только смысл: описание, жизненный цикл, источники правды и связи, которых нет в тексте явно.

Скилл переносим: канонический каталог, каталог данных и адрес панели задаются аргументами и локальным adapter-файлом. Ядро не знает про CopyTrust, Jira, PHP, конкретные порты и конкретные IDE. Тестирование проходит в Kilo Code, остальные среды проверяются паритетом.

План заменяет исходный текст `Идея.txt`. Нормативный формат узла и схемы лежит в [mirror-format.md](./mirror-format.md).

> Обновление 2026-11-02: данные перенесены в `.cursor/.state/harness-mirror`,
> план, формат и идея лежат в `references/`, каталог `.doc/harnes_plan` больше не используется.
> Скрытый `.state` не копируется в зеркала и не участвует в проверке паритета.

## Что берем из исходной идеи

Оставляем:

- один узел на файл, а не один большой реестр;
- граф связей и просмотр одним кликом;
- гибридный разбор: Python делает структуру, модель делает смысл;
- кеш по хешу, неизмененные файлы не разбираются повторно;
- индекс проекта, чтобы связи ссылались на реальные пути, а не на выдуманные;
- инспектор узла и копирование `node_id` для агента.

Убираем:

- отдельное дерево `.harness-viz/data` как седьмую копию харнеса;
- возврат `raw_content` от модели;
- разбор каждого зеркала отдельной моделью;
- угадывание путей по похожему имени;
- запись в исходник из браузера;
- обязательный сервер, CDN и внешние библиотеки;
- правку зеркал как самостоятельных источников.

Добавляем:

- зеркала как узлы проекций с ребрами `mirrors` и `synced_by`;
- автоматическое обнаружение расхождения зеркала с каноном по `content_sha256`;
- правила переносимости в `SKILL.md` и adapter-файл проекта;
- гейты валидации вместо доверия к тексту модели;
- тест в Kilo Code как обязательный, не опциональный.

## Решения

| ID | Решение | Обоснование |
|---|---|---|
| D1 | Имя скилла `harness-mirror` | имя выбрано пользователем, отражает зеркало харнеса; черновик `harness-map` переименовывается |
| D2 | Канон `.cursor`, данные `.doc/harnes_plan`, просмотрщик статический | совпадает с текущей структурой проекта и с решением "один JSON на файл" |
| D3 | Один JSON на файл, `node_id` канона без суффикса, зеркала всегда `@{environment}` | уникальность идентификатора и группировка проекций одновременно |
| D4 | Модель не вызывается скриптом и не возвращает текст | стоимость, обратимость, отсутствие сети в ядре |
| D5 | Зеркала наследуют анализ канона по `content_sha256` | одинаковый текст не оплачивается шесть раз |
| D6 | Запись только в канон, зеркала пересобирает `sync-agent-views.sh` | иначе синхронизация затирает правку |
| D7 | Только Python stdlib, bash как обертка, без MCP, сети и БД | переносимость и минимум зависимостей |
| D8 | Просмотрщик без CDN, на чистом HTML и SVG | работает офлайн в любой среде |
| D9 | Область сканирования - белый список каталогов харнеса, файлы секретов исключены | иначе в граф попадут `node_modules`, продуктовый код и значения переменных |

## Границы

Не делаем в этом скилле:

- не правим продуктовый код и не описываем бизнес-логику проекта;
- не заменяем `verify_parity.py` и `sync-agent-views.sh`;
- не пишем в зеркала;
- не запускаем модель автоматически;
- не поднимаем отдельный сервер;
- не добавляем зависимость от Cursor MCP, Jira, PHP или базы;
- не коммитим и не пушим.

4. Коды выхода: 0 успех, 1 проверяемое отрицание, 2 ошибка аргументов или валидации.
5. `--help` на каждом подкоманде, подробности в stderr, короткий JSON в stdout.
6. Атомарная запись: временный файл, затем `os.replace`, блокировка от параллельного запуска.
7. Запуск без `cwd` проекта и без `.cursor` в окружении.

Готово, когда скрипт запускается из `/tmp` по абсолютному пути с `--root` и дает тот же результат, что из корня проекта.

## Переносимость

Скилл должен работать в Cursor, Kilo Code, Codex, Antigravity, Gemini и Agents без правки файлов.

Обязательные правила:

1. В `SKILL.md` и `references/` нет названий продукта, номеров задач, локальных URL, портов и имен классов.
2. Проектные значения только в `ADAPTERS.local.md`. Файл помечен `transferable: false` и не переносится в другой проект.
3. Канонический каталог берется из adapter-файла или определяется по известным префиксам. Если канона нет, скрипт завершается с кодом 2 и понятным сообщением.
4. Все пути принимаются через `--root` и `--data`. cwd не является источником правды.
5. Только Python 3 stdlib. Bash обертка не обязательна. PowerShell не требуется.
6. Нет сети, MCP, базы и модели внутри скрипта.
7. Кодировка UTF-8, переводы строк в JSON и Markdown только LF.
8. Фронтенд без CDN, без внешних шрифтов и без телеметрии.
9. Среда определяется по префиксу пути, не по содержимому файла.
10. Зеркала читаются, но не пишутся. `mirrors` и `synced_by` ставятся автоматически.
11. DSH не считается копией `.cursor`. У него свои узлы среды `dsh`, связь `patches_target`.
12. Ошибки и неполное покрытие печатаются всегда, даже в коротком выводе.

Проверка переносимости:

- запустить скрипт из копии в `.kilo/skills/harness-mirror`;
- запустить из `/tmp` с `--root` на этот проект;
- прогнать на временном мини-проекте с другим именем канона и без `.cursor`.

| Расхождение зеркал | паритет failed | правка только канона, затем sync, затем паритет |
| Выдуманные связи | `target_path` вне индекса | `resolution` и проверка индекса, без похожих путей |
| Стоимость модели | массовый enrich | только `pending`, только по одному узлу, зеркала наследуют канон |
| Конкурентная запись | два агента пишут узел | блокировка и атомарная замена |
| Ложная доступность скилла | файл есть, среда не видит | runtime_registration и тест из `.kilo` |
| Секрет в узле | в JSON попал ключ или пароль | белый список, исключение `*.env`, проверка на известные шаблоны секретов |
| Дубли компонента | рядом `harness-map` и `harness-mirror` | P0 переименование, затем проверка grep по старому имени |
