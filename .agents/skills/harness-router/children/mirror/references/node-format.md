# Формат узла харнеса v2.2

Один JSON описывает ровно один файл на диске. Машинная схема: `../assets/harness-node.schema.json`.

## Два вида

- декларативный узел для `.md`, `.mdc`, `.txt`, `.yml`, `.yaml`;
- исполняемый узел для `.sh`, `.py`, `.js`, `.ts`.

Общее: `meta`, `lifecycle`, `reconstruction_meta`, `global_relations`, `analysis`, список блоков.

## Байтовые инварианты

1. Файл читается как байты, хеш считается по байтам.
2. Склейка блоков по возрастанию `order` даёт исходные байты: BOM, CRLF, смешанные окончания, хвостовые переводы, комментарии.
3. Нормализация, обрезка и переформатирование запрещены.
4. Нет UTF-8, значит узла нет, код выхода 2.
5. Пути только относительные от корня проекта, разделитель `/`.
6. Одинаковый вход даёт одинаковые байты JSON.

## meta

| Поле | Смысл |
|---|---|
| `node_id` | `{type}:{slug}`, у зеркала суффикс `@{environment}` |
| `name` | имя из родительской папки для обобщённых файлов, иначе имя без расширения |
| `type` | `skill`, `rule`, `script`, `config`, `doc`; синтетические узлы `mcp` живут только в графе, файла у них нет |
| `environment` | `cursor`, `codex`, `kilo`, `antigravity`, `gemini`, `agents`, `dsh`, `project` |
| `source_file_path` | путь от корня, без абсолютных путей |
| `canonical` | true для `.cursor/`, `.agents/skills/` и файлов вне известных сред |
| `projection_of` | `node_id` канона у зеркала, иначе null |
| `transferable` | false только у локального adapter-файла |
| `content_sha256` | хеш байтов |
| `parser_version`, `schema_version` | версии разбора и схемы |
| `description` | одно или два предложения; берётся из frontmatter `description`, если агент не задал своё |
| `symlink_target` | цель симлинка, поле необязательное |

## reconstruction_meta

`total_blocks`, `line_ending` (`\n`, `\r\n`, `mixed`), `bom`, `final_newline`. У декларативного узла дополнительно `has_frontmatter`.

## Блоки

Обязательные поля: `block_id`, `order`, `raw_content` или `raw_code`, `relations`.

- декларативный: `block_type` (`frontmatter`, `preamble`, `section`), `header_text`, `header_level`;
- исполняемый: `line_range` в формате `start-end`, `name_or_purpose`.

Правила разбиения:

- frontmatter идёт первым блоком, `header_text: null`;
- текст до первого заголовка это `preamble`;
- заголовок начинает секцию и включает текст до следующего заголовка;
- скрипт делится на шебанг, инициализацию, функции верхнего уровня, разбор аргументов, точку входа;
- вложенные функции остаются в блоке родителя;
- `block_id` стабилен: `b000`, `b001` по порядку.

## Связи

Типы: `invokes_tool`, `delegates_to`, `constrained_by`, `governed_by`, `enforces_gate`, `reads_context`, `next_stage_pipeline`, `patches_target`, `mirrors`, `synced_by`.

Обязательные поля: `target_name`, `target_type`, `relation_type`, `origin`, `resolution`.

- `origin: agent` ставит агент, `anchor_text` обязателен и обязан быть точной подстрокой блока.
- `origin: auto` ставит скрипт: структурные связи, `mirrors`, `synced_by`. Якорь не обязателен.
- `target_type: mcp` указывает на синтетический узел сервера, файла у него нет.
- Упоминание сервера засчитывается, когда рядом есть отдельный токен `MCP`, либо имя само содержит `mcp`, либо оно записано как `mcp__имя`. Слова, совпадающие с обычными командами, без такого признака не считаются.
- Автоматические связи пересчитываются при разборе; сохраняются только связи с `origin: agent`.
- `resolution`: `resolved`, `ambiguous`, `unresolved`, `missing`, `external`;
  `resolved` один кандидат, `ambiguous` несколько с `candidates`, `unresolved` пустой путь,
  `missing` цель была в индексе, но файл исчез, путь и `target_node_id` сохраняются,
  `external` цель вне проекта.
- Выдумывать путь запрещено. Похожее имя не повод подставить путь.

## sources_of_truth

Массив `{name, path, scope}`. Стандарты и контракты, которым файл подчиняется. `path` равен null, если стандарт упомянут без ссылки.

## analysis

`{"status": "pending" | "filled", "model": null | "agent" | "<model>", "summary": "", "details": ""}`. `summary` это одна короткая строка для заголовка карточки, до 90 символов. `details` это два-четыре предложения для подробной карточки, до 600 символов. Оба поля заполняет агент при `apply`, язык русский, только факты. Пустые поля не ломают формат: граф берёт `summary` из первого предложения `description`, затем из первого заголовка, а `details` из `description`.

Время разбора в узле не хранится, оно в `cache.map`. Иначе повторный разбор даёт другой JSON и ломает сравнение версий.

## Идентификаторы

Канон: `skill:task-doc`. Зеркало: `skill:task-doc@kilo`, `projection_of = skill:task-doc`. Два узла одной среды с одинаковым `slug` это ошибка проекта, решается переименованием файла. У файлов внутри скила `slug` начинается с имени скила, поэтому `references/index.md` в двух скилах даёт разные `node_id`.

Скилы каноничны в `.agents/skills/`. `.cursor/skills` это симлинк на тот же каталог, поэтому оба пути дают один `node_id`, а в кеше остаётся `.agents/skills/`.

## Зеркала

- у зеркала `canonical: false` и заполнен `projection_of`;
- если `content_sha256` совпадает с каноном, зеркало наследует описание, жизненный цикл, источники правды и анализ, повторный разбор не нужен;
- при расхождении хешей граф показывает `state: drift`;
- legacy-копии `mcp-servers/` в зеркалах адаптированы под среду (`projection_of: null`), поэтому drift для них не считается;
- `set` пишет только в канон, зеркало пересобирает штатная синхронизация проекта.

## Кеш

Отдельный `cache.map`: `sha256`, `node_id`, `parser_version`, `schema_version`, `parsed_at`. Хеш, версия разбора и версия схемы совпали, разбор пропускается. Рост `parser_version` или `schema_version` делает переразбор обязательным.

## Ограничения

- Полного текста вне блоков нет.
- Связь описывает только явное упоминание.
- Секреты не разбираются: имена файлов и значения токенов проверяются до разбора.
