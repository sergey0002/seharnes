# Просмотр через существующую панель

Карта не поднимает свой сервер. Она кладёт готовый `index.html` и `graph.json` в каталог данных и отдаётся тем же статическим сервером, что и остальная документация проекта.

## Требования к серверу

Достаточно любого из двух вариантов:

1. Панель проекта на PHP со встроенным сервером, которая уже умеет отдавать файлы из каталога документации по прямому маршруту.
2. Любой статический сервер с корнем в каталоге документации.

Ни базы, ни записи, ни выполнения команд сервер не требует. Карта полностью статична.

## Маршрут

Если панель отдаёт содержимое каталога документации по маршруту вида `/files/{путь}`, адрес карты:

```
{VIEWER_URL} = /files/{DATA_DIR без ведущей точки}/{index.html}
```

`graph.json` и `nodes/*.json` лежат рядом, поэтому просмотрщик читает их относительными путями и не знает о портах и префиксах.

Проверка после сборки:

1. открыть `index.html`;
2. слева появился список узлов, сверху счётчики;
3. клик по узлу показывает карточку, блоки и связи;
4. `graph.json` в сетевой панели браузера отдаётся с кодом 200.

Если счётчики пустые, `graph.json` не найден: проверь, что `VIEWER_URL` и каталог данных совпадают.

## Режим записи

`build` даёт статический просмотр. Для правки запускается `serve`, он отдаёт тот же `index.html` и добавляет API:

| Метод и путь | Назначение |
|---|---|
| `GET /api/health` | состояние и признак записи |
| `GET /api/node?id=ID` | узел |
| `PUT /api/node?id=ID` | `raw_file` заменяет файл целиком, `block_id` плюс `raw_content` меняет блок, пересборка и обновление графа |
| `POST /api/rebuild` | пересборка графа |

Сервер слушает `127.0.0.1` и пишет только в канон. Правка другого узла возвращает отказ. Целый файл разрешено писать только для скилов и правил, остальные типы отвечают отказом `editable types are rule, skill`.

Статический маршрут панели остаётся только на чтение: из браузера, открытого через него, кнопка сохранения сообщает, что запись недоступна.

## Почему статическая панель только читает

Изменение исходников из браузера требует записи на диск, проверки прав и защиты от подмены пути. Панель проекта этого не делает и не должна: она отдаёт документацию и работает с корнем только на чтение.

Поэтому правка идёт через агента:

1. агент берёт узел командой `get`;
2. меняет блок командой `set` с проверкой обратимости;
3. пересобирает граф командой `build`.

Браузер показывает результат. Кнопка в карточке копирует готовую команду, чтобы агент не собирал её вручную.

## Безопасность

- Каталог данных лежит внутри каталога документации и не содержит секретов. Значения из окружения и файлов секретов в узлы не попадают по построению: разбор читает только текстовые файлы харнеса.
- Просмотрщик не выполняет код из узлов. Все поля экранируются перед вставкой в разметку.
- Внешние ссылки в карточке не открываются автоматически.
- Сервер не отдаёт файлы вне каталога документации. Маршрут прямого чтения обязан проверять, что реальный путь начинается с корня каталога.

## Если панели нет

`build` оставляет рядом `index.html`, `graph.json` и `nodes/`. Достаточно открыть каталог данных любым статическим сервером:

```bash
python3 -m http.server 8090 --directory <DATA_DIR>
```

Адрес: `http://127.0.0.1:8090/index.html`. Функциональность та же, потому что просмотрщик не зависит от панели.

## Ограничения

- Правка из интерфейса доступна только для канонических скилов и правил.
- Нет серверного поиска: фильтр работает по списку в браузере.
- Нет истории версий в интерфейсе: старые узлы лежат в `nodes/.history/` и читаются агентом.
- Нет совместного редактирования: одновременная правка двух агентов упрётся в последнюю запись, проверка обратимости поймает повреждение, но не конфликт.
