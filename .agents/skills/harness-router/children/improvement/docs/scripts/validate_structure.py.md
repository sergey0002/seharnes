## Суть
Проверяет раскладку харнеса по манифесту `.doc/harnes/state/canon-paths.yaml`: запрещенные пулы скриптов, документ на каждый скрипт, описание каталогов `.tools`, пути команд MCP, документы отключенных серверов, устаревшие пути в правилах и документах, каталоги данных скилов и место результатов тестов. С аргументом `--junk` выводит лишние файлы, пустые каталоги и данные, лежащие не в своих каталогах.

Проверки S10-S12 читают ссылки `.doc/skil_data/...` в правилах и скилах:

| Код | Что проверяет | Куда переносить |
|---|---|---|
| S10 | первый каталог после `.doc/skil_data/` не совпадает ни с одним скилом | `.doc/skil_data/{skill}/` |
| S11 | в каталоге данных скила лежат временные файлы | `.doc/temp/` |
| S12 | в каталоге данных скила лежат результаты тестов | `.doc/tasks/{task}/test-runs/` |

Границы раскладки задает секция `layout` в `canon-paths.yaml`: `skill_data`, `task_tests`, `test_path_markers`.
Парсер читает также вложенные разделы `scripts` и `docs`. Он поддерживает ограниченный формат файла: строки в двойных кавычках и списки строк. Неизвестные ключи, дубли, неподдерживаемый синтаксис и небезопасные пути дают ошибку вместо молчаливого отката к значениям по умолчанию. Отсутствующий файл пока использует встроенный layout; не все считанные поля используются всеми проверками.
Общий reader ограничивает размер политики и отклоняет ссылки, hardlink-алиасы и обнаруженные изменения файла во время чтения. Это не заменяет проверку доверия и защиту от всех гонок на уровне файловой системы.

## Когда запускать
Перед коммитом правок харнеса, при переносе скриптов и документов, при разборе расхождений между каноном и зеркалами. Скрипт вызывается из `harness_cli.py doctor` как гейт `structure`.

## Аргументы
| Аргумент | Алиас | Тип | Обязателен | По умолчанию | Что делает |
|---|---|---|---|---|---|
| `--root DIR` | | string | нет | `.` | корень проекта |
| `--json` | | flag | нет | | вывести отчет в JSON |
| `--warn-only` | | flag | нет | | не возвращать код 1 при ошибках |
| `--junk` | | flag | нет | | показать лишние файлы и каталоги |
| `--fail-on-junk` | | flag | нет | | вернуть код 1, если найден хлам |
| `--require-policy` | | flag | нет | | проверить наличие YAML, отсутствие ссылок в его пути, версию, метаданные manifest и его собственную запись `path_manifest` |

## Коды выхода
| Код | Значение | Действие вызывающего |
|---|---|---|
| 0 | ошибок раскладки нет | продолжить работу |
| 1 | есть ошибки раскладки или хлам при `--fail-on-junk` | разобрать `ERROR` и `JUNK` и повторить |

## Что читает и что пишет
Читает `.doc/harnes/state/canon-paths.yaml`, `.cursor/mcp.json`, `skill.json` скилов, документы `docs/scripts`, `docs/mcp`, `state/26-tools.md` и активные правила. Использует `doc_script.py` для вычисления владельца документа. Пишет только stdout или JSON, файлы не меняет.

## Побочные эффекты
- Файлы не изменяет.
- Читает дерево `.agents/skills`, `.tools`, `.cursor/rules`, `.cursor/mcp-stack` и `.doc/harnes/state`.
- Сеть не использует.

## Окружение и зависимости
Python 3.10 или новее, стандартная библиотека. Импортирует `doc_script.py` из скила `doc-script`. Внешние пакеты не нужны.

## Примеры
```bash
python3 .agents/skills/harness-router/children/improvement/scripts/validate_structure.py
python3 .agents/skills/harness-router/children/improvement/scripts/validate_structure.py --junk
python3 .agents/skills/harness-router/children/improvement/scripts/validate_structure.py --json --junk
```

## Ограничения
Проверяет раскладку и наличие документов, но не смысл документов. Исторические документы с `status: outdated` и файлы с датой в имени пропускает. Ссылки между документами не проверяет. Хлам показывает только при `--junk` и по умолчанию не влияет на код выхода.
