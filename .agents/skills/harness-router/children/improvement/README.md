# harness-improvement

Назначение.
Единственная безопасная точка правки самого харнеса: скилов, правил, скриптов,
конфигурации MCP, адаптеров и рабочих цепочек.

Как работает.
Сначала собирает историю компонента и ставит диагноз. Затем выбирает минимальную
переносимую правку, вносит ее только в канон, прогоняет целевые тесты, синхронизирует
зеркала и проверяет паритет и visibility-контракт правил. Любое изменение сопровождает
документацией компонента и отдельным местом хранения данных. Отличает наблюдение
от разрешения на изменение и не считает собственный diff доказательством результата.

Что нужно.
Канонический каталог харнеса, реестр компонентов, валидаторы, команда
синхронизации и parity, а также история правок компонента.

Чего не делает.
Не правит продуктовый код, не обходит правила проекта и не меняет харнес без
подтвержденной причины. Не оставляет правку без документации и не хранит данные
компонента в его папке.
