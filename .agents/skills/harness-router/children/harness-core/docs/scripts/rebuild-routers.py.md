## Суть
Пересобирает файлы `SKILL.md` всех роутеров (директорий с суффиксом `-router`) из канонического дерева скилов в `.agents/skills`. Роутер содержит только маршрутизацию: таблицу дочерних скилов с полными путями от корня проекта, описанием ответственности и триггерами. Скрипт читает `skill.json` (children, triggers) и `SKILL.md` (frontmatter description) каждого скила, строит плоский список всех потомков с уровнями вложенности и рендерит итоговый `SKILL.md` роутера.

## Когда запускать
- После добавления, удаления или переименования дочерних скилов в любом роутере.
- После изменения `skill.json` (children, triggers) или `description` в `SKILL.md` дочерних скилов.
- При переносе харнеса в новый проект (`new-project` режим migrate/update) — чтобы зеркала роутеров соответствовали новому дереву.
- В CI/проверках парности (`--check`) — чтобы убедиться, что роутеры в актуальном состоянии.

Если не запустить: роутеры будут ссылаться на несуществующие или устаревшие дочерние скилы, agenteй не смогут найти нужный скил по таблице маршрутизации.

## Аргументы
| Аргумент | Алиас | Тип | Обязателен | По умолчанию | Что делает |
|---|---|---|---|---|---|
| --root |  | string | нет | . | Корень проекта (ожидается `.agents/skills` внутри) |
| --check |  | flag | нет |  | Только проверить, не писать. Exit 1 если есть расхождения |
| --write |  | flag | нет |  | Записать изменения в `SKILL.md` роутеров |
| --json |  | flag | нет |  | Вывод результата в JSON (routers, changed, errors, status) |

## Коды выхода
| Код | Значение | Действие вызывающего |
|---|---|---|
| 0 | Все роутеры актуальны (в режиме --check) или успешно обновлены (в режиме --write) | Продолжить |
| 1 | Найдены расхождения (в --check) или ошибки чтения/парсинга | Исправить дерево скилов или запустить с --write |

## Что читает и что пишет
**Читает:**
- `.agents/skills/**/skill.json` — children, triggers
- `.agents/skills/**/SKILL.md` — frontmatter `name`, `description`
- Жёстко заданные описания роутеров в `ROUTER_DESCRIPTIONS` (для harness-router, task-router, testing-router, reporting-router, documentation-router)

**Пишет:**
- `.agents/skills/*-router/SKILL.md` — полностью перезаписывается сгенерированным содержимым между маркерами `<!-- BEGIN ROUTER: generated by rebuild-routers.py -->` и `<!-- END ROUTER -->`

## Побочные эффекты
- file writes (перезапись SKILL.md роутеров)
- stdout: сводка `routers=N changed=M errors=K` или JSON

## Окружение и зависимости
- Python 3.8+
- Стандартная библиотека: `argparse`, `json`, `re`, `pathlib`
- Нет внешних зависимостей

## Примеры
```bash
# Проверить актуальность всех роутеров
python3 .agents/skills/harness-router/children/harness-core/scripts/rebuild-routers.py --root . --check

# Обновить все роутеры
python3 .agents/skills/harness-router/children/harness-router/children/harness-core/scripts/rebuild-routers.py --root . --write

# JSON-вывод для CI
python3 .agents/skills/harness-router/children/harness-core/scripts/rebuild-routers.py --root . --check --json
```

## Ограничения
- Не создаёт новых скилов и не удаляет существующие — только обновляет таблицу маршрутизации внутри уже существующих роутеров.
- Жёстко завязан на структуре: роутер = директория с суффиксом `-router`, внутри `skill.json` и `SKILL.md`.
- `triggers` в `skill.json` могут быть списком строк или извлекаются из `description` в `SKILL.md` (до маркеров "Применять по запросам" / "Use when").
- Fallback-скилы `harness-core` и `task-core` всегда идут в конце таблицы с пометкой `**Fallback/ядро.**`.
- Циклические ссылки в `children` вызывают `RuntimeError`.

## Связи
- Вызывается: `sync-agent-views.sh` (внутри переноса/обновления зеркал), `new-project` миграция, ручной запуск при изменении дерева скилов.
- Зависит от: `skill.json` всех скилов, `SKILL.md` всех скилов (frontmatter).
- Описывает результат: карта харнеса в `.doc/harnes/skills/{router}.md`, зеркало в `.agents/rules`, `.codex/rules`, `.kilo/rules`, `.qoder/rules`, `.qwen/rules`.
