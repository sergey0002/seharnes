## Суть

Скрипт создает unit пользовательского systemd для одного проекта CodePrism.
Имя unit содержит SHA-256 канонического пути проекта. Скрипт не запускает службу.

## Когда запускать

Запускайте после установки окружения CodePrism, перед подключением клиентов проекта.
Все старые stdio-серверы проекта нужно остановить до запуска общей службы.

## Аргументы

| Аргумент | Алиас | Тип | Обязателен | По умолчанию | Что делает |
|---|---|---|---|---|---|
| `project` | нет | string | да | нет | существующий корень проекта, символьные ссылки разрешаются |
| `port` | нет | int | да | нет | свободный TCP-порт от 1 до 65535 для HTTP на localhost |
| `--output-dir` | нет | string | да | нет | существующий каталог для сохранения unit-файла |
| `--help` | нет | flag | нет | выключен | показать справку |

## Коды выхода

| Код | Значение | Действие вызывающего |
|---|---|---|
| 0 | unit-файл успешно создан | выполнить daemon-reload и запустить службу |
| 1 | ошибка файлов или конфликт unit | проверить права и существующие файлы в каталоге |
| 2 | ошибка синтаксиса аргументов | исправить параметры вызова |

## Что читает и что пишет

Скрипт проверяет окружение `.cursor/tools/codeprism-ai/venv`, серверную обертку,
существующие unit-файлы в выходном каталоге и доступность локального порта.
Скрипт атомарно создает unit-файл; отличающийся файл не перезаписывается.
Повторный запуск с теми же параметрами сохраняет существующий файл.
Служба запускается отдельно через systemd.

## Побочные эффекты

Создает unit-файл в указанном выходном каталоге systemd. Не запускает и не перезагружает службы.

## Окружение и зависимости

Требует Python 3.8+, установленное окружение CodePrism и права на запись в каталог unit-файлов.

## Примеры

```bash
python3 .cursor/mcp-stack/add-codeprism.py "$PWD" 9201 --output-dir "$HOME/.config/systemd/user"
systemctl --user daemon-reload
```

Имя созданного unit и команда запуска выводятся скриптом. До запуска убедитесь,
что порт в `.cursor/mcp.json` совпадает с портом службы.

## Ограничения

Проверка порта не резервирует его до запуска. Конфликты unit проверяются только
в указанном каталоге. Сервер на localhost не аутентифицирует локальные процессы.
Старые stdio-серверы не соблюдают блокировку общего HTTP-сервера.
