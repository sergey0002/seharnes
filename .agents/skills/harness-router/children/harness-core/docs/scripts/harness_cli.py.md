## Суть
Единый CLI управления харнесом проекта. Объединяет команды диагностики состояния
(`doctor`), синхронизации представлений (`sync`), экспорта конфигурации (`export`),
первичной настройки проекта (`setup`), аудита MCP (`mcp-audit`) и валидации (`verify`).

## Когда запускать
Запускать для комплексной проверки готовности среды (`doctor`), после синхронизации,
при переносе настроек харнеса в новый репозиторий (`export`) или при настройке портов
и сервисов (`setup`).
Не запускать команду `export` без явного указания целевой директории `--target`.

## Коды выхода
| Код | Значение | Действие вызывающего |
|---|---|---|
| 0 | операция успешно завершена, все проверки пройдены | перейти к следующему шагу workflow |
| 1 | сбой гейта проверки или валидации | изучить `failed_gates` и `gate_details` в JSON |
| 2 | ошибка конфигурации среды или неверные аргументы | проверить файлы конфигурации и параметры CLI |

## Что читает и что пишет
Читает `.cursor/`, `.agents/skills/`, манифесты и адаптеры сред.
В командах `export` и `setup-hooks` создает и копирует файлы в целевые директории.
Выводит сводный отчет и структурированный JSON со статусом и деталями в stdout.

## Побочные эффекты
Команда `setup-hooks` записывает pre-commit хук в `.git/hooks/pre-commit`.
Команда `export` выполняет копирование файлов харнеса в указанный каталог.
Команда `sync` обновляет сгенерированные представления сред.

## Окружение и зависимости
Требует `python3` (версии 3.8+). Использует встроенные модули `argparse`, `json`,
`pathlib`, `subprocess`, `shutil`.

## Ограничения
Запуск должен производиться из корня проекта либо с явным указанием `--root`.
Выполнение внешних гейтов ограничено внутренними таймаутами.
`strict` проверяет признаки junk существующим валидатором структуры, но пока не сравнивает состав с релизным manifest. `--checks` ограничивает область проверки и не подтверждает прохождение остальных гейтов. Чтение и удаление найденных файлов не выполняется.
При `--junk` или `--mode strict` результаты структуры включаются в итоговый JSON целиком, в `gate_details.structure.findings`; результат задания панели показывает только доступный хвост лога.
