## Суть
Пакетный поиск нескольких паттернов одним проходом ripgrep. Скрипт принимает
несколько `--pattern` и `--include`, печатает по одной JSON-строке на совпадение и
строку `_meta` в конце. Заменяет серию отдельных вызовов grep.

## Когда запускать
Запускать, когда нужно найти 2+ литерала или regex в коде и документации за один
вызов. Правило `batch-calls` требует этот скрипт вместо последовательных поисков.
Не запускать для поиска по графу кода (там serena, codegraph, CBM) и для
документации до пустого ответа jdocmunch.

## Аргументы
| Аргумент | Алиас | Тип | Обязателен | По умолчанию | Что делает |
|---|---|---|---|---|---|
| `--root` | нет | путь | да | нет | каталог поиска |
| `--pattern` | нет | строка | да | нет | regex для поиска, можно повторять |
| `--include` | нет | glob | нет | все файлы | ограничение по маске, можно повторять |
| `--max-per-file` | нет | число | нет | `5` | максимум совпадений на файл |
| `--max-total` | нет | число | нет | `100` | максимум совпадений всего |
| `--context` | нет | число | нет | `0` | число строк контекста |
| `--truncate` | нет | число | нет | `300` | обрезка длинной строки |
| `--json` | нет | флаг | нет | выключен | принимается и игнорируется, вывод всегда JSON-lines |
| `-h`, `--help` | нет | флаг | нет | выключен | печатает usage и выходит с кодом 2 |

## Коды выхода
| Код | Значение | Действие вызывающего |
|---|---|---|
| 0 | совпадения есть | читать JSON-lines |
| 1 | совпадений нет | `_meta` все равно напечатана, ошибки нет |
| 2 | ошибка аргументов, нет `--root`, нет каталога, корень репозитория без `--include` | исправить вызов |

## Что читает и что пишет
Читает файлы под `--root`. На диск ничего не пишет. В stdout идет JSON-lines:
`{"file","line","match"}` и последняя строка `{"_meta":{...}}`. В stderr идут
предупреждения о переходе на grep и об ошибках аргументов.

## Побочные эффекты
Побочных эффектов не обнаружено. Скрипт не меняет файлы, git, базу и порты.
Запускает `rg` или `grep` и `python3` как дочерние процессы.

## Окружение и зависимости
Переменных окружения от вызывающего не требуется. Внутри экспортируются
`MAX_PER_FILE`, `MAX_TOTAL`, `TRUNCATE`, `NPAT`, `GREP_FALLBACK` для python-фильтра.
Зависимости: `bash`, `python3`, `rg` (при отсутствии используется `grep -rn`).

## Примеры
```bash
bash .tools/scripts/multi-search.sh --root .cursor/rules \
  --pattern "component-docs" --include "*.mdc"

bash .tools/scripts/multi-search.sh --root .doc/harnes \
  --pattern "validate_docs" --pattern "doc-script" \
  --include "*.md" --max-total 20
```

## Ограничения
Корень `.` без `--include` запрещен. В режиме `grep` разбор строк ломается на путях
с двоеточием. Бинарные файлы не читаются. Строки длиннее `--truncate` обрезаются.
Скрипт не заменяет поиск по графу кода и не индексирует документацию.

## Связи
Правило `batch-calls` требует этот скрипт для пакетных поисков. `multi-search.ps1`
это Windows-обертка, которая форвардит аргументы в этот файл. `multi-exec.sh`
закрывает пакетные чтения и команды.
