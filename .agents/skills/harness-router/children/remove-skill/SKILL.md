# remove-skill

Удаление скила из харнеса с очисткой ссылок. Скил не удаляет каталог вслепую:
сначала собирает упоминания, делает бэкап, затем удаляет канон и копии во всех
средах и обновляет документацию.

## Когда применять

- пользователь просит удалить скил из харнеса;
- скил устарел или перенесен в другой скил;
- нужно убрать локальный скил, который больше не поддерживается;
- после удаления нужно почистить карточку, индексы, реестр и роутер.

## Вход

- корень проекта;
- имя скила или относительный путь;
- подтверждение пользователя;
- решение, удалять ли MCP-сервер и связанные скрипты, если скил ими владеет.

## Шаги

1. Собрать ссылки и показать план:

```bash
python3 .agents/skills/harness-router/children/remove-skill/scripts/remove_skill.py \
  --root . --name my-skill --dry-run
```

2. Проверить категории ссылок: `router`, `docs`, `state`, `registry`, `mcp`,
   `rule`, `other`. Ссылки в правилах, MCP и произвольном тексте скрипт не
   переписывает, он показывает их для ручной правки.

3. Выполнить удаление:

```bash
python3 .agents/skills/harness-router/children/remove-skill/scripts/remove_skill.py \
  --root . --name my-skill --yes
```

4. Скрипт делает бэкап в
   `.doc/skil_data/harness-core/removed/{timestamp}/{env}/{id}`, удаляет канон и
   копии из зеркал, удаляет карточку, строки индексов, запись реестра и запись
   `children/{name}` из родительского `skill.json`. Затем пересобирает роутеры,
   запускает синхронизацию и валидаторы.

5. Для ссылок категорий `rule`, `mcp` и `other` открыть указанные файлы и
   исправить текст вручную. Удаление строки без замены смысла запрещено.

6. Проверить, что удаленный скил не появляется снова:

```bash
python3 .agents/skills/harness-router/children/add-skill/scripts/scan_local_skills.py --root .
```

Подробные правила и порядок отката: `references/remove.md`.

## Выход

- скил удален из канона и зеркал;
- карточка и строки индексов удалены;
- запись реестра удалена;
- родительский роутер пересобран;
- отчет `removed`, `references`, `unresolved`, `errors`;
- путь бэкапа.

## Ограничения

- Не удалять скил без бэкапа, если пользователь не передал `--no-backup`.
- Не удалять MCP-сервер автоматически: это отдельное решение.
- Не переписывать правила и документацию вслепую.
- Не удалять скил, который используется как зависимость, без обновления
  зависимостей. Флаг `--force` разрешает удаление, но не исправляет зависимые
  скилы автоматически.
- В неинтерактивном запуске обязателен `--yes`.
