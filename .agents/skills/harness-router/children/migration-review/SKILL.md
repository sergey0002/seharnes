# migration-review

Разбор после переноса. Скил не копирует kit и не меняет режим переноса. Он читает
`.doc/.rebase-conflicts.json` и текущий проект, показывает, что было перезаписано
и что осталось локальным, затем предлагает установку.

## Когда применять

- после `rebase_project.ps1` или `harness_cli.py export`;
- когда нужно понять, какие скилы, правила и MCP были у исходного проекта;
- когда нужно установить локальные скилы в канон без ручного поиска;
- когда нужно проверить, что конфликты сохранены в бэкапе.

## Вход

- корень нового проекта;
- файл `.doc/.rebase-conflicts.json` и каталог `.doc/.rebase-backup/`;
- решение пользователя: только отчет или применение безопасных предложений.

## Шаги

1. Показать обзор без изменений:

```bash
python3 .agents/skills/harness-router/children/migration-review/scripts/review_migration.py \
  --root . --json
```

2. В интерактивном терминале предложить применение:

```bash
python3 .agents/skills/harness-router/children/migration-review/scripts/review_migration.py \
  --root . --interactive
```

3. Применить безопасные предложения без вопросов:

```bash
python3 .agents/skills/harness-router/children/migration-review/scripts/review_migration.py \
  --root . --apply --yes
```

4. Разобрать вручную все предложения со статусом `manual`: конфликт скила с тем
   же именем, конфликт правила и конфликт MCP-сервера.

5. После проверки удалить бэкап миграции, если он больше не нужен:

```bash
python3 .agents/skills/harness-router/children/migration-review/scripts/review_migration.py \
  --root . --rm-backup --yes
```

Отчет показывает путь бэкапа, число файлов, размер и категории. Без удаления
печатается готовая команда.

6. После применения проверить синхронизацию и аудит скилов:

```bash
python3 .agents/skills/harness-router/children/skill-authoring/scripts/audit_skill.py \
  --root . --all
```

Подробные правила разбора: `references/review.md`.

## Выход

- отчет `proposals` с категориями `skill`, `rule`, `mcp`, `manual`;
- список примененных предложений;
- путь к бэкапу, число файлов, размер и категории;
- команда удаления бэкапа или факт удаления;
- ошибки, которые требуют ручного решения.

## Ограничения

- Не выбирает правильную версию конфликтующего скила.
- Не сливает два разных правила с одинаковым именем.
- Не перезаписывает существующий MCP-сервер без решения человека.
- Не копирует секреты из оригинала в новый проект.
- В режимах `clean` и `update` перенос не запускает этот скил автоматически.
