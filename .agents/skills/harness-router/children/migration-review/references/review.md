# Разбор после переноса

## Источники данных

| Источник | Что содержит |
|---|---|
| `.doc/.rebase-conflicts.json` | режим переноса, бэкап, перезаписанные файлы, target-only и added |
| `.doc/.rebase-backup/{timestamp}` | копии перезаписанных файлов |
| `.doc/.rebase-mcp-backup/cursor.mcp.json` | MCP исходного проекта до слияния |
| `.doc/.rebase-kit.json` | маркер проекта, режим и профиль kit |
| `.agents/skills` | текущий канон скилов |
| `.cursor/rules`, `.agents/rules` | текущий канон и локальные правила |

## Категории предложений

### Скилы

- `install`: скил есть в каноне или зеркале, но его нет в манифесте пакета;
- `manual`: скил был перезаписан kit или существует в нескольких версиях.

Установка идет через `add-skill`. Для версии из зеркала указывается `--from`.
Версия из бэкапа не устанавливается автоматически: сначала нужно сравнить ее с
текущим каноном.

### Правила

- `install`: локальное правило из `.agents/rules` или другой среды, которого нет
  в `.cursor/rules`;
- `manual`: правило было перезаписано kit.

Установка правила создает `.cursor/rules/{name}.mdc` из frontmatter и текста
исходного файла. Если такой файл уже существует, установка не выполняется.

### MCP

- `install`: сервер был в исходном проекте и отсутствует в текущем каноне;
- `manual`: сервер есть в обоих конфигах с разными настройками;
- `keep`: сервер пришел из kit.

Слияние MCP добавляет только отсутствующие серверы. Существующие настройки kit не
перезаписываются.

## Режимы переноса

- `migrate`: бэкап перезаписанных файлов, анализ локальных компонентов, вопросы;
- `clean`: очистка kit-компонентов Target, бэкап всех kit-файлов, установка только
  kit, без анализа;
- `update`: обновление kit поверх уже перенесенного проекта, локальные дополнения
  сохраняются, разбор конфликтов не запускается.

## Безопасность

Перед применением проверить:

1. бэкап существует и не пуст;
2. в предложениях нет `manual`;
3. MCP-конфиг не содержит секретов в открытом виде;
4. после применения синхронизация и parity проходят.

## Удаление бэкапа

После проверки скил показывает путь бэкапа, число файлов, размер и категории.
Удаление выполняется отдельной командой:

```bash
python3 .agents/skills/harness-router/children/migration-review/scripts/review_migration.py \
  --root . --rm-backup --yes
```

Удаляются `.doc/.rebase-backup/{timestamp}` и `.doc/.rebase-mcp-backup`.
Отчет `.doc/.rebase-conflicts.json` остается и получает `backup_removed: true`.
Маркер `.doc/.rebase-kit.json` и отчеты переноса не удаляются.

В интерактивном режиме после разбора появляется вопрос `Удалить бэкап миграции?`.
В панели и другом запуске без TTY удаление требует `--yes`.

## Проверка

```bash
python3 .agents/skills/harness-router/children/migration-review/scripts/review_migration.py --root . --json
bash .agents/skills/harness-router/children/environment-sync/scripts/sync-agent-views.sh

```
