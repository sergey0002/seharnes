# Doc MCP

Документ MCP лежит в скиле этого сервера:
`{mcp-skill}/docs/mcp/{server}.md`. Если скила нет, сервер считается незакрытым,
а документ временно остается в `.doc/harnes/mcp/{server}.md`.

## Правило

| Состояние | Где документ |
|---|---|
| активный сервер, скил есть | `{mcp-skill}/docs/mcp/{server}.md` |
| активный сервер, скила нет | `.doc/harnes/mcp/{server}.md` временно, это ошибка аудита |
| отключенный сервер | `.doc/harnes/mcp/{server}.md` с причиной отключения |

## Шаги

1. `--list` показывает каждый сервер, его скил и путь документа.
2. Для сервера без скила создай скил через `skill-authoring`, затем перенеси
   документ командой `--move`.
3. `--audit` проверяет: активный сервер имеет скил, документ лежит в скиле,
   отключенный сервер имеет документ с причиной отключения.

## Команды

```bash
python3 .agents/skills/harness-router/children/doc-mcp/scripts/doc_mcp.py --list
python3 .agents/skills/harness-router/children/doc-mcp/scripts/doc_mcp.py --move
python3 .agents/skills/harness-router/children/doc-mcp/scripts/doc_mcp.py --audit
```

`--move` переносит `.doc/harnes/mcp/{server}.md` в
`{mcp-skill}/docs/mcp/{server}.md` только если скил уже существует и целевой файл
еще не создан.

## Аудит

1. Активный сервер из `.cursor/mcp.json` имеет скил.
2. Документ лежит в `docs/mcp/` этого скила.
3. Отключенный сервер имеет документ с причиной отключения.
4. Нет дубля: документ не лежит одновременно в `.doc` и в скиле.
5. Скил содержит `README.md` и `skill.json`.
6. Локальные Markdown-ссылки и пути `meta.related` в документе существуют.

Аудит не запускает сервер и не подтверждает правильность всех эксплуатационных
утверждений. При переносе агент сохраняет аудит и историю, пересчитывает ссылки
внутри документа и обновляет входящие ссылки из правил и индексов.

## Связи

- Список серверов: `.cursor/mcp.json`.
- Шаблон MCP-документа: `.doc/harnes/mcp/README.md`.
- Стандарт: `.doc/harnes/component-docs.md` §5.
