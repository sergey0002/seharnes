# mcp-audit

Проверяет, что каждый MCP-сервер из канона задокументирован, имеет правило вызова,
строки в картах и отдельное место для данных. Сервер не считается установленным,
пока эти артефакты не созданы.

## Когда применять

- нужно проверить, что все серверы из `.cursor/mcp.json` описаны и имеют правило;
- добавлен или изменен MCP-сервер;
- синхронизация сред сообщила о расхождении MCP-конфигов;
- нужно проверить, что данные сервера не лежат в папке скила.

## Вход

- `.cursor/mcp.json` и `.cursor/mcp.env`;
- `.cursor/rules/mcp/{server}.mdc` и `.cursor/rules/mcp.mdc`;
- `.doc/harnes/mcp/{server}.md`, `.doc/harnes/mcp/README.md`;
- `.doc/harnes/state/04-mcp.md`;
- клиентские конфиги `.codex`, `.kilo`, `.agents`, `.qoder`, `.qwen`, `.dsh`.

## Обязательная документация и хранение

Наличие записи в `.cursor/mcp.json` не завершает установку. Для каждого сервера
обязательны:

- правило `.cursor/rules/mcp/{server}.mdc`: когда вызывать, инструменты,
  аргументы, ошибки и проверка;
- документ `.doc/harnes/mcp/{server}.md` по шаблону `.doc/harnes/mcp/README.md`;
- строка в `.cursor/rules/mcp.mdc`;
- строка в `.doc/harnes/mcp/README.md`;
- строка в `.doc/harnes/state/04-mcp.md`;
- строка в `.dsh/adapters/mcp-names.md`, если сервер виден в DSH.

Данные и состояние сервера хранятся в `.doc/skil_data/{server}/`, не в папке
скила. Клиентские конфиги генерируются `sync-agent-views.sh`, ручная правка зеркал
запрещена. Секреты хранятся в `.cursor/mcp.env`, в документах остаются только имена
переменных.

Порядок добавления сервера: `.doc/harnes/component-install.md`, раздел 4.

## Шаги

1. Прочитать `.cursor/mcp.json` и получить список ключей серверов.
2. Для каждого сервера проверить документ, правило, строки в двух картах и state.
3. Проверить обязательные разделы документа по шаблону `mcp/README.md`.
4. Проверить, что в документах нет значений секретов, только имена переменных.
5. Проверить, что данные и состояние лежат в `.doc/skil_data/{server}/`.
6. Запустить проверки:

```bash
node .agents/skills/harness-router/children/mcp-audit/scripts/test-mcp-servers.mjs --only={server}
python3 .agents/skills/harness-router/children/mcp-audit/scripts/verify_mcp_views.py
python3 .agents/skills/harness-router/children/improvement/scripts/validate_docs.py
```

7. Если сервер новый или изменен, выполнить раздел 4
   `.doc/harnes/component-install.md`, затем синхронизацию сред. Синк проверяет
   visibility-контракт. Для standalone-аудита запустить `harness_mirror.py visibility --summary`
   и проверить, что новое правило MCP доступно в средах.

## Выход

- отчет по составу серверов, документации и правилам;
- список отсутствующих файлов и строк;
- результат smoke-проверки и проверки представлений.

## Ограничения

- Не добавлять сервер в конфиг вместо `component-install.md`.
- Не печатать значения секретов.
- Не править клиентские конфиги и зеркала вручную.
- Не считать наличие файла доказательством runtime-доступности сервера.
