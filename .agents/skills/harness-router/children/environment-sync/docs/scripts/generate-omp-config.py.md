## Суть

Пишет единственный файл `.omp/mcp.json`. Всё остальное omp читает из канона сам:
`.cursor/rules/*.mdc`, `.agents/skills/<name>/SKILL.md`, `AGENTS.md`. Вложенные
правила и вложенные скилы он не сканирует намеренно: корневые файлы это
роутеры, они ссылаются на детей, и агент читает ребёнка по пути из ссылки. Так
контекст не раздувается телами и описаниями всех детей.

Отдельный файл нужен только для MCP: провайдер Cursor у omp игнорирует
`disabled`, `envFile`, `${workspaceFolder}` и `${env:VAR}`, а сервер с именем
`playwright` omp отбрасывает, пока работает его встроенный браузер.

Скрипт пишет `.omp/mcp.json` в формате omp: `type` (`stdio`/`http`/`sse`),
`enabled`, `command`, `args`, `env`, `url`, `headers`, `cwd`, `timeout`.

Скрипт удаляет зеркала `.omp/rules` и `.omp/skills`, которые выпускали прошлые
версии: они дублировали корневые правила и скилы. Если они остались, `--check`
сообщает `stale mirror`.

Файл `.omp/AGENTS.md` не создаётся: нативный проектный файл перекрыл бы корневой
`AGENTS.md`, который omp уже загружает.

## Когда запускать

- После правки `.cursor/mcp.json` или `.cursor/mcp.env`.
- В составе `sync-agent-views.sh` при включённой среде `omp`.
- В режиме `--check` как гейт в `harness doctor`.

Если не запускать: выключенные серверы попробуют стартовать, `envFile` не
загрузится, `${workspaceFolder}` останется литералом.

## Аргументы

| Аргумент | Тип | Обязателен | По умолчанию | Что делает |
|---|---|---|---|---|
| `--root` | string | нет | `.` | Корень проекта, где лежат `.cursor/` и `.agents/skills/` |
| `--check` | flag | нет | | Проверить актуальность без записи, вернуть JSON со статусом |

## Коды выхода

| Код | Значение | Действие вызывающего |
|---|---|---|
| 0 | `--check` прошёл или генерация успешна | Продолжить |
| 1 | В `--check` найдены расхождения | Запустить без `--check` |
| 2 | Нет `.cursor/mcp.json` или `.cursor/rules` | Проверить `--root` |

## Что читает и что пишет

Читает:

- `.cursor/mcp.json` - серверы, состояния, заголовки, `envFile`;
- `.omp/mcp.json` - чтобы сохранить серверы, которых нет в каноне.

Пишет:

- `.omp/mcp.json` - `$schema` и `mcpServers`.

Удаляет:

- `.omp/rules` и `.omp/skills`, если они остались от прошлой версии генератора.

Правила переноса MCP:

- `disabled: true` в каноне становится `enabled: false`; включённый сервер получает
  явный `enabled: true`, это же защищает `playwright` от встроенного фильтра omp;
- `${workspaceFolder}` раскрывается по смыслу. Путь к инструменту
  (`<root>/.tools/...`, `<root>/.agents/...`) становится абсолютным: это общая
  установка харнеса, и в worktree задачи этих каталогов может не быть. Предмет
  проверки (`--repository`, `--root`, `--project-path`, `--path`, `--workspace`
  и env-ключи `MCP_WORKSPACE`, `PROJECT_ROOT`, `PROJECT_PATH`, `WORKSPACE_ROOT`,
  `REPO_PATH`) становится `.`; ключ, равный `${workspaceFolder}`, удаляется,
  чтобы сервер взял `process.cwd()`;
- `${env:VAR}` в `command`, `args`, `url` и `headers` переводится в `${VAR}`: omp
  раскрывает такую форму сам;
- значение `env`, равное `${env:VAR}`, не переносится: переменную экспортирует
  обёртка;
- при `envFile` команда оборачивается в
  `bash <root>/.tools/scripts/run-with-mcp-env.sh`; нестандартный файл передаётся
  через `MCP_ENV_FILE`;
- `alwaysAllow` и `disabledTools` не переносятся: в `mcp.json` у omp для них нет
  поля.

## Побочные эффекты

- Запись `.omp/mcp.json`.
- Удаление `.omp/rules` и `.omp/skills`, если они есть.
- В `.omp/mcp.json` серверы канона заменяются, локальные серверы разработчика
  сохраняются.
- stdout: JSON со статусом и счётчиками серверов.

## Окружение и зависимости

- Python 3 стандартной библиотеки, внешних зависимостей нет.
- Значения `.cursor/mcp.env` скрипт не читает и в файл не пишет: их
  экспортирует обёртка `run-with-mcp-env.sh`.

## Ограничения

- `alwaysAllow` и `disabledTools` не имеют эквивалента в `mcp.json` omp; права
  настраиваются в `settings.json` или через `toolApprovals`.
- Литеральный заголовок авторизации выключенного сервера копируется как есть:
  файл `.omp/mcp.json` локальный и не входит в git, но копий секрета становится
  больше. Исправление канона - отдельная задача.
- Вложенные правила и скилы остаются вне стартового контекста omp. Они доступны
  по ссылке из корневого роутера, но не попадают в каталог скилов и в список
  правил: это решение по экономии контекста, а не пробел.
- Разделение "инструмент" и "предмет" опирается на список флагов и env-ключей.
  Новый сервер, который принимает рабочую папку под другим именем, нужно
  добавить в `WORKSPACE_SUBJECT_FLAGS` или `WORKSPACE_SUBJECT_ENV`, иначе путь
  останется абсолютным.
- Серверы, которые выводят корень из своего расположения, а не из cwd
  (`codegraph-mcp.sh`, `jdocmunch-mcp.sh`), продолжают смотреть в основную
  установку: абсолютный путь к скрипту для них это и есть проект.
- `cwd` в `.omp/mcp.json` не задаётся: без него omp держит один процесс на
  проект и передаёт каталог сессии, что и нужно в worktree задачи.
- omp может отбросить MCP-сервер браузера по встроенному фильтру; явный
  `enabled: true` это отменяет, `browser.enabled: false` в настройках omp убирает
  встроенный браузер вместо сервера.
- `--check` не считает ошибкой локальные серверы в `.omp/mcp.json`.

## Связи

- Вызывается `render_agent_views.py` и `sync-agent-views.sh` при включённой среде
  `omp`; `compact_agent_views.py` использует `render_mcp` этого скрипта.
- Зависит от `.cursor/mcp.json`.
- Генерирует вход для omp: `.omp/mcp.json`.
- Документация среды: `.doc/harnes/state/13-agent-migration.md`,
  `.doc/harnes/state/01-canon-envs.md`.
