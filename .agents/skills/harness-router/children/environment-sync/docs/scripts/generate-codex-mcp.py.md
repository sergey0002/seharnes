## Суть

Отдельный генератор заменяет MCP-секции Codex данными из `.cursor/mcp.json` и сохраняет остальные настройки TOML. Общая синхронизация и перенос проекта запускают генератор после подготовки канона.

## Когда запускать

Запускать вручную после проверки источника и резервной копии целевого TOML. Выходной файл задается явно и должен существовать.

## Аргументы

| Аргумент | Тип | Обязателен | По умолчанию | Что делает |
|---|---|---|---|---|
| `--root PATH` | string | да | | корень проекта, содержащий `.cursor/mcp.json` |
| `--config PATH` | string | да, кроме `--audit-canon` | | существующий TOML Codex; символические ссылки запрещены |
| `--check` | флаг | нет | | сравнить результат с файлом без записи |
| `--audit-canon` | флаг | нет | | проверить все серверы источника, включая отключенные, вывести JSON со счетчиками блокеров без имен серверов и значений |
| `--help` | флаг | нет | | показать справку |

## Коды выхода

- `0`: успех или совпадение при `--check`.
- `1`: результат отличается при `--check` или аудит обнаружил блокеры.
- `2`: ошибка аргументов, формата, неподдерживаемое поле или ошибка доступа.

## Что читает и что пишет

Скрипт читает JSON и TOML. При изменениях атомарно заменяет TOML, сохраняя права доступа; перед заменой проверяет, что содержимое файла не изменилось. Значения ошибок не выводятся. Скрипт не читает `envFile` при генерации и не записывает его значения в TOML.

## Побочные эффекты

Создает временный файл в каталоге TOML и удаляет его после ошибки. При запуске MCP-сервера shell читает указанный `envFile` и выполняет команду сервера.

## Окружение и зависимости

Python 3.11 или новее, стандартная библиотека и `/bin/sh` для stdio с `envFile` или переменными окружения. `envFile` должен быть доверенным shell-скриптом с присваиваниями: его содержимое выполняется при запуске сервера.

## Примеры

```sh
python3 .agents/skills/harness-router/children/environment-sync/scripts/generate-codex-mcp.py --root /path/to/project --config /path/to/config.toml --check
python3 .agents/skills/harness-router/children/environment-sync/scripts/generate-codex-mcp.py --root /path/to/project --config /path/to/config.toml
python3 .agents/skills/harness-router/children/environment-sync/scripts/generate-codex-mcp.py --root /path/to/project --audit-canon
```

## Ограничения

- Удаляются серверы, отсутствующие в каноне. Отключенные серверы создаются с `enabled = false`. Отключённый HTTP-сервер с буквальным секретным заголовком заменяется неработающей заглушкой без секрета.
- Обычные таблицы `[mcp_servers.*]` поддерживаются, inline и dotted MCP-ключи вызывают ошибку без записи. Содержимое остальных настроек проверяется TOML-парсером.
- `disabledTools` превращается в `disabled_tools`. `alwaysAllow` не переносится автоматически: генератор сохраняет существующие настройки подтверждения Codex и выдаёт предупреждение. Фактические разрешения зависят от всех слоёв конфигурации Codex.
- Неизвестные поля, SSE и несовместимые комбинации вызывают ошибку. `--audit-canon` отдельно подсчитывает предупреждения и проверяет остальные поля каждого сервера.
- HTTP-заголовки принимают `${env:NAME}`; `Authorization: Bearer ${env:NAME}` использует `bearer_token_env_var`. Буквальные значения разрешены только для `Accept` и `Content-Type`. URL с query, fragment или учетными данными запрещен.
- Значения переменных с именами, похожими на секреты, принимаются только как `${env:NAME}`. Другие литералы считаются несекретными; нельзя помещать секреты в обычные аргументы, имена, пути, URL, `Accept` или `Content-Type`.
- Переменные `${env:NAME}` внутри stdio вычисляются при запуске через shell; отсутствующая переменная или `envFile` останавливает запуск. `envFile` перезаписывает одноименные переменные окружения, затем применяются `env`. Циклические ссылки не разрешаются.
- Сохранение и проверка изменений не защищают от гонки между последней проверкой и заменой файла. Одновременные запуски для одного TOML не поддерживаются.
