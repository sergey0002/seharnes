# Создание скила

## Что создает скрипт

- каталог скила в `.agents/skills` или в `children` родителя;
- `SKILL.md` с frontmatter и обязательными разделами;
- `README.md` без ссылок;
- `skill.json` со schema 1 и пустыми ресурсами;
- необязательный тест `tests/test_{name}.py`;
- карточку, индексы, реестр и запись родителя через `add-skill`.

## Имя

Имя папки и поле `name` совпадают. Допустимы только строчные латинские буквы,
цифры и дефис. Примеры: `skill-authoring`, `my-tool`, `report-v2`.

## Описание

`--description` попадает в frontmatter и в README. Описание должно отвечать на
два вопроса: что делает скил и когда его применять. Триггеры перечисляются в
описании через запятую или в тексте.

## Родитель

Флаг `--parent` создает скил в `children` указанного родителя. Скрипт добавляет
запись в `skill.json` родителя, а `add-skill` пересобирает таблицу роутера.

## Тест

Флаг `--with-test` создает проходящий placeholder-тест. Его нужно заменить на
проверку поведения скила. Без флага `tests` в манифесте пустой.

## После создания

1. Заменить шаблонные шаги в `SKILL.md`.
2. Описать вход, выход и ограничения.
3. Проверить карточку и связи.
4. Поставить карточке `status: actual` после проверки.
5. Выполнить аудит и синхронизацию.

## Проверка

```bash
python3 .agents/skills/harness-router/children/skill-authoring/scripts/audit_skill.py \
  --root . --name my-skill
```

## Ограничения

- Скрипт не придумывает бизнес-логику.
- Скрипт не создает пустые каталоги.
- Скрипт не перезаписывает существующий скил без `--force`.
