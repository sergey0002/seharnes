# skill-authoring

Создание и аудит скилов. Скил не устанавливает чужой локальный скил и не удаляет
его: для этого есть add-skill и remove-skill. Здесь создается новый каркас и
проверяется соответствие уже существующего скила правилам харнеса.

## Когда применять

- нужно создать новый скил с правильной структурой и документацией;
- нужно проверить существующий скил перед установкой или удалением;
- нужно найти расхождения в карточке, реестре, роутере или зависимостях;
- нужно оценить качество скила по единым правилам.

## Вход

- корень проекта;
- имя нового скила или имя существующего;
- для создания: описание, родительский роутер, нужен ли тест;
- для аудита: имя скила или режим всех скилов.

## Шаги

1. Для создания сначала проверить, что такого скила нет:

```bash
python3 .agents/skills/harness-router/children/skill-authoring/scripts/audit_skill.py \
  --root . --name my-skill
```

2. Создать каркас:

```bash
python3 .agents/skills/harness-router/children/skill-authoring/scripts/create_skill.py \
  --root . --name my-skill --description "Что делает скил и когда применяется"
```

Для дочернего скила:

```bash
python3 .agents/skills/harness-router/children/skill-authoring/scripts/create_skill.py \
  --root . --name my-child --parent harness-router \
  --description "Что делает дочерний скил"
```

3. Заполнить `SKILL.md` реальными шагами и ограничениями. Каркас содержит
   шаблонные шаги и не считается готовым скилом.

4. Проверить скил:

```bash
python3 .agents/skills/harness-router/children/skill-authoring/scripts/audit_skill.py \
  --root . --name my-skill
```

5. Проверить все скилы перед синхронизацией:

```bash
python3 .agents/skills/harness-router/children/skill-authoring/scripts/audit_skill.py \
  --root . --all
```

6. Передать новый скил в `add-skill`: родительский роутер, индексы и синхронизация
   обязательны для discoverability. После синка проверить `runtime_registration.py`
   для целевых сред; его результат показывает наличие конфигурации и не доказывает
   обнаружение скила в UI. Если вместе со скилом добавляется правило, использовать
   `gate: true` только для компактного inline-гейта; для path-trigger указать
   `attach: glob` вместе с `globs` и проверить `harness_mirror.py visibility --summary`.

Подробные правила создания: `references/create.md`.
Подробные правила аудита: `references/audit.md`.

## Выход

- новый скил в `.agents/skills`;
- SKILL.md, README.md, skill.json;
- карточка, индексы и запись реестра через add-skill;
- отчет аудита: `score`, `status`, `errors`, `warnings` по каждому скилу.

## Ограничения

- Каркас создания не пишет бизнес-логику скила.
- Аудит не исправляет файлы автоматически.
- Аудит проверяет проектную документацию и реестр, но не runtime-регистрацию
  скила в конкретном редакторе.
- Созданный скил получает `status: draft` в карточке до ручной проверки.
- В неинтерактивном режиме создание и установка выполняются с `--yes`.
