# add-skill

Установка локального скила в канон харнеса. Скил находит скилы, которых нет в
пакете, проверяет их по формату харнеса, добавляет документацию и запускает
синхронизацию сред.

## Когда применять

- после миграции проекта появились скилы, которых не было в пакете;
- пользователь просит установить локальный скил в харнес;
- синхронизация зеркал сообщила о скилах вне пакета;
- нужно принять скил из одной среды в канон со всей документацией.

## Вход

- корень проекта;
- имя скила или относительный путь, либо режим `--all`;
- для конфликта версий: среда-источник `codex`, `qoder`, `qwen`, `kilo` или `agents`;
- подтверждение пользователя на запись.

## Обязательная документация и хранение

Скил или MCP не считается установленным, пока не созданы все артефакты. Копирование
файлов и запись в конфиг это только начало установки.

Для скила обязательны:

- `SKILL.md`, `README.md` и `skill.json` в папке скила;
- документация скила в его `README.md`;
- документы скриптов в `{skill}/docs/scripts/`, проверяемые `doc-script`;
- запись в `component_registry.json` и строка в `state/02-skills.md`;
- обновленный родительский `skill.json` и таблица `## Маршрутизация`;
- данные и состояние только в `.doc/skil_data/{name}/`, не в папке скила.

Для MCP обязательны:

- сервер в `.cursor/mcp.json`, секреты только в `.cursor/mcp.env`;
- правило `.cursor/rules/mcp/{server}.mdc` и строка в `.cursor/rules/mcp.mdc`;
- документ активного MCP в `{skill}/docs/mcp/{server}.md`;
- строки в `.doc/harnes/state/04-mcp.md` и `.doc/harnes/mcp/README.md`;
- данные и состояние только в `.doc/skil_data/{server}/`, если они есть;
- клиентские конфиги генерируются синком, вручную не правятся.

Порядок установки MCP: `.doc/harnes/component-install.md`, раздел 4. Скрипт
`add_skill.py` устанавливает только скилы и не добавляет MCP автоматически.

## Шаги

1. Получить список скилов вне пакета:

```bash
python3 .agents/skills/harness-router/children/add-skill/scripts/scan_local_skills.py --root .
```

2. Проверить, что манифест пакета существует. Если его нет, создать базовую
   линию по текущему канону:

```bash
python3 .agents/skills/harness-router/children/add-skill/scripts/scan_local_skills.py --root . --write-baseline
```

3. Выбрать скилы для установки. Сначала показать пользователю список и источник.
   Конфликт версий без `--from` не устанавливать.

4. Выполнить установку:

```bash
python3 .agents/skills/harness-router/children/add-skill/scripts/add_skill.py \
  --root . --name my-skill --yes
```

Для всех однозначных скилов:

```bash
python3 .agents/skills/harness-router/children/add-skill/scripts/add_skill.py \
  --root . --all --yes
```

5. Скрипт выполняет детерминированную часть: проверка структуры, копирование в
   канон, создание `README.md`, `skill.json`, запись в реестр,
   обновление родительского `skill.json`, пересборка роутеров, синхронизация и
   валидаторы. Смысл README и триггеры нужно проверить агентом. Sync включает проверку visibility-контракта правил; новое gate-правило должно иметь `gate: true`, path-правило - `attach: glob`.

6. Проверить описание, состав и ограничения в README установленного скила.

7. Для каждого скрипта установленного скила создать документ в
   `{skill}/docs/scripts/` по правилам скила `doc-script`.
   Документ содержит аргументы, коды выхода, чтение, запись и побочные эффекты.

8. Если установка затрагивает MCP, выполнить раздел 4
   `.doc/harnes/component-install.md`: правило, документ, главная карта, state,
   README, DSH и smoke. Без этих файлов сервер не считается установленным.

9. Повторно запустить проверки:

```bash
python3 .agents/skills/harness-router/children/improvement/scripts/validate_skills.py
python3 .agents/skills/harness-router/children/improvement/scripts/validate_registry.py
python3 .agents/skills/harness-router/children/improvement/scripts/validate_docs.py
python3 .agents/skills/harness-router/children/harness-core/scripts/rebuild-routers.py --root . --check
```

Подробные правила установки и разбор конфликтов: `references/install.md`.

## Выход

- скил в `.agents/skills`;
- `README.md` и `skill.json` внутри скила;
- ссылки на README в индексах, если индексы существуют;
- документы скриптов в `{skill}/docs/scripts/`, подготовленные отдельно;
- запись в `component_registry.json`;
- обновленный родительский роутер;
- для MCP: правило, документ, строки в картах и state;
- каталог данных `.doc/skil_data/{name}/`, если скил или MCP хранит состояние;
- отчет `actions`, `warnings`, `errors`, `next_steps`.

## Ограничения

- Не устанавливать скил с секретами, симлинками или абсолютными путями.
- Не перезаписывать существующий канон без `--force`.
- Не выбирать версию при конфликте автоматически.
- Не считать автоматически созданный README проверенной документацией.
- Не считать установку завершенной без документов скриптов, README, реестра и
  прохождения `validate_docs.py`.
- Не хранить данные и состояние в папке скила: только `.doc/skil_data/{name}/`.
- Не добавлять MCP без правила, документа, строк в картах и state. Скрипт
  `add_skill.py` этого не делает.
- Не запускать синхронизацию с `--allow-drift`: после установки проверки должны
  проходить без исключений.
- В неинтерактивном запуске обязателен `--yes`.
