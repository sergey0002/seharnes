# git

## Шаги

1. Определи корень текущего репозитория. Передавай его как `repo_path` во все вызовы.
2. Начни с `git_status`. Для локальных правок используй `git_diff_unstaged`
   и `git_diff_staged`; для истории `git_log` и `git_show`.
3. Для происхождения строк используй доступный `git_blame` или скил
   `git-task-blame`. Проверяй фактическую поверхность инструментов клиента.
4. В отчете разделяй committed, staged и unstaged изменения. Не приписывай
   чужие правки текущей работе.
5. Переход к задаче выполняй через `gototask`, ее diff через `task-diff`,
   commit и push через `send-to-git` после требуемого подтверждения.

## Границы

- Этот скил не дает разрешения на commit, push, reset, checkout или создание ветки.
- Не отменяй чужие правки и не используй destructive git-команды.
- Push не входит в MCP git. Перед публикацией соблюдай отдельный workflow проекта.
- Не включай секреты и локальную конфигурацию агента в commit.
