# code

Родительский скил для расследований по коду. Сам выбирает дочерний скил и
требует доказательств по каждому шагу рассуждения.

## Когда применять

- нужно найти истинную причину бага, а не симптом;
- нужно понять путь по бизнес-логике и путь по коду до места ошибки;
- нужно проверить, какой диф или задача изменили поведение;
- нужно восстановить цепочку вызовов, ветвей и данных через граф кода;
- нужно отличить причину от сопутствующих факторов.

## Вход

| Параметр | Обязателен | Значение |
|---|---|---|
| Симптом | да | что видит пользователь или QA, текст ошибки, статус, скриншот |
| Ожидание | да | как должно работать по задаче |
| Номер задачи | нет | Jira `2077`, если баг связан с задачей |
| Окружение | нет | локальный стенд, d-стенд, версия, роль, clientId |
| Воспроизведение | нет | шаги, заказ, UIN, время, логи |

## Маршрутизация

| Запрос | Дочерний скил |
|---|---|
| найди причину бага, почему так работает, root cause, разбери баг по коду, исследуй диф, восстанови путь вызовов, граф вызовов, бизнес-путь бага, что сломало поведение | `bug-cause`: `.agents/skills/code/children/bug-cause/SKILL.md` |

## Шаги

1. Зафиксировать симптом, ожидание и окружение.
2. Если запрос про конкретную задачу, открыть её пакет.
3. Прочитать `children/bug-cause/SKILL.md` по полному пути.
4. Выполнить расследование и вернуть отчёт с доказательствами.

## Выход

- отчёт о причине бага: путь по бизнес-логике, путь по коду, доказательства;
- список проверенных и отклонённых гипотез;
- точное место и условие возникновения ошибки;
- предложение по исправлению без самого исправления, если пользователь не просил чинить.

## Ограничения

- Расследование только читает код, документацию, логи и данные. Правки только
  после отдельной просьбы.
- Каждое утверждение подкрепляется файлом, строкой, логом, запросом или дифом.
  Неподтверждённое помечается как неподтверждённое.
- Сниппет из графа не заменяет чтение файла целиком перед выводом.
- Прод не использовать.
