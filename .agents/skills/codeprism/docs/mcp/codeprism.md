## Суть

CodePrism - граф знаний по репозиторию с MCP-сервером. Держит постоянный индекс
файлов, символов, импортов и вызовов, отвечает на структурные вопросы и
проверяет код на секреты и уязвимости перед записью.

В харнесе используется пакет `codeprism-ai` от knight22-21/CodePrism версии
0.1.11. Он поддерживает PHP, сохраняет индекс между запусками и идет в комплекте
с готовым агентом [скилом codeprism](../../SKILL.md).

Раньше в харнесе стоял бинарник rustic-ai/codeprism v0.3.5. Он не поддерживал
PHP, терял индекс при выходе и не имел скила. Бинарник удален, откат описан в
разделе "Установка и перенос".

---

## Когда вызывать

- нужен структурный контекст символа до чтения файла;
- нужны вызывающие, вызываемые, зависимые файлы и влияние правки;
- нужен поток данных или зависимости между файлами;
- нужна проверка предложенного кода на секреты и уязвимости перед записью;
- нужен учет прочитанного и записанного на длинной задаче.

Не вызывать:

- за полным телом функции, граф дает структуру;
- для Smarty `.tpl`, Markdown и файлов из `.gitignore`, они не индексируются;
- для правок PHP, это Serena;
- для точного исходника и blast radius по вызовам, это codegraph и CBM.

Порядок в задачах: после codegraph, когда нужен граф, влияние или security gate.

## Конфигурация

| Что | Значение |
|---|---|
| Ключ в каноне | `codeprism` |
| Транспорт | Streamable HTTP, `http://127.0.0.1:9201/mcp` для этого проекта |
| Запуск | пользовательская служба systemd запускает `.agents/skills/codeprism/scripts/codeprism_serve.py`; stdio-клиенты используют `.agents/skills/codeprism/scripts/codeprism-mcp.sh` как мост |
| Пакет | `codeprism-ai==0.1.11` |
| Python | 3.12.13 в локальном окружении |
| Каталог окружения | `.cursor/tools/codeprism-ai/venv`, 112 МБ |
| Цель | корень проекта, переданный серверу позиционным аргументом |
| Индекс | SQLite в `$XDG_DATA_HOME/codeprism/<hash>.db`, по умолчанию `~/.local/share/codeprism/` |
| Фоновый индекс и наблюдатель | включены в текущей конфигурации; `CODEPRISM_NO_AUTO_INDEX=1` в окружении сервера отключает оба |
| Секреты | не требуются |
| Статус | включен |

Переменные сервера и моста:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CODEPRISM_TARGET` | корень проекта моста | необязательная проверка совпадения с корнем конфигурации моста; цель сервера не выбирает |
| `CODEPRISM_NO_AUTO_INDEX` | `0` | `1` в окружении сервера отключает фоновую индексацию и запуск наблюдателя |

`alwaysAllow` в каноне перечисляет 14 read-only и проверочных инструментов.
`update_file`, `check_dependencies_cve`, `record_read`, `record_write`,
`get_session_context` и `undo_write` отсутствуют в `alwaysAllow`. Запрос
подтверждения зависит от политики конкретного клиента.
`index_project` отключен на общем HTTP-сервере, чтобы не переключить граф всех клиентов.
Проверки клиента не заменяют авторизацию: локальный HTTP-сервер предназначен для доверенных процессов.

## Настройка под проект

Проект настраивается файлом `.codeprism.toml` в корне. Файл читает сервер при
старте, поэтому область индексации и security-исключения применяются сразу.
Файл локальный: он добавлен в `.git/info/exclude` и не коммитится.

| Ключ | Значение в проекте | Зачем |
|---|---|---|
| `languages` | `php`, `javascript`, `typescript` | убрать Go, Rust, Java, C, C++, Ruby, которых в проекте нет |
| `respect_gitignore` | `true` | исключить `vendor`, `node_modules`, `.doc`, `templates_c`, `frontend/dist` |
| `auto_index` | `true` | обновлять граф при старте |
| `enable_security_gate` | `true` | оставить проверку перед записью |
| `watch_debounce_ms` | `800` | реже перестраивать граф при пачке правок |
| `enable_embeddings` | `false` | семантический индекс не нужен, он стоит около 1 ГБ, замедляет сборку и в 0.1.11 падает на дублях ID |

`[codeprism.security].ignore_paths` работает в двух местах: исключает файлы из
индекса и исключает их из security-сканов. Используется как список шума:

```
*/vendor/*              сторонние PHP-библиотеки
*/node_modules/*        JS-зависимости
*/templates_c/*         кеш Smarty
*/frontend/dist/*       собранные бандлы
*/scripts/plugins/*     сторонний JS, включая videojs и vue
*/scripts/jscalendar-1.0/*
*/scripts/ui/minified/*
*/scripts/ui/i18n/*     переводы интерфейса
*/resources/lang/*      языковые массивы
*/sql/migrations/*      исторические миграции Doctrine, 307 файлов
*/tests/fixtures/*      фикстуры тестов
*/*.min.js
```

Эффект на этом репозитории: индекс уменьшился с 2625 до 1934 файлов, исключено
691 файл (26 процентов). Символы: 13507 вместо 16771, ребра: 22789 вместо 25890,
покрытие выросло с 65.2 до 71.7 процента. Поиск перестал находить классы
миграций и сторонних плагинов, продуктовые классы находятся.

Важно: инструмент `index_project` в версии 0.1.11 собирает конфиг заново и не
читает `.codeprism.toml`. Его вызов вернет исключенные файлы в индекс. Для
пересборки перезапускать сервер, для одной правки использовать `update_file`.

## Инструменты и аргументы

| Инструмент | Обязательные аргументы | Основные необязательные | Что возвращает |
|---|---|---|---|
| `update_file` | `path` | - | обновление одного файла |
| `get_graph_stats` | `path` | - | готовность, файлы, символы, ребра |
| `get_context` | `file`, `symbol` | `depth` 1-3 | подпись, вызывающие, вызываемые, типы |
| `get_module_summary` | `file` | - | назначение файла, публичный API |
| `get_file_map` | - | `project_path` | роли файлов в каталоге |
| `get_impact` | `file`, `symbol` | - | серьезность, зависимые, затронутые тесты |
| `get_callers` | `file`, `function` | - | все места вызова с номерами строк |
| `get_callees` | `file`, `function` | - | все вызовы из функции |
| `get_data_flow` | `file`, `symbol` | - | поток значения |
| `search_symbol` | `query` | `project_path`, `kind` | найденные символы |
| `get_dependencies` | `file` | - | импорты, внутренние и внешние |
| `get_dependents` | `file` | - | файлы, зависящие от этого |
| `scan_file` | `file` | `content` | статус PASS, WARN или BLOCK |
| `scan_diff` | `original`, `proposed` | `file` | статус проверки правки |
| `check_secret_exposure` | `content` | - | найденные секреты |
| `check_dependencies_cve` | `requirements` | - | CVE в зависимостях |
| `record_read` | `session_id`, `file`, `symbol` | - | учет прочитанного |
| `record_write` | `session_id`, `file`, `content_before`, `content_after` | - | учет записи |
| `get_session_context` | `session_id` | - | сводка сессии |
| `undo_write` | `session_id` | `steps` | откат записей |

Пути `file` и `path` даются относительно корня проекта. `kind` в
`search_symbol`: `function`, `class`, `variable`, `import`.
`index_project` отсутствует в HTTP `tools/list`: обертка отключает инструмент.
В режиме stdio обертки это ограничение HTTP не применяется.

## Правила использования

1. Начать с `get_graph_stats` с `path="."`: он подтверждает готовность индекса.
2. Перед чтением файла вызвать `get_context` с `depth=2`.
3. Влияние правки: `get_impact`, затем `get_callers` и `get_callees`.
4. Перед записью: `scan_diff` для правки, `scan_file` для нового файла.
   `BLOCK` запрещает запись, `WARN` требует сообщить о находке.
5. Длинная задача: `record_read`, `record_write`, в конце
   `get_session_context`, при необходимости `undo_write`.
6. При включенной фоновой индексации наблюдатель запускается после первичного
   индекса и обновляет сохраненные файлы за 1-2 с. Для мгновенного результата
   вызывать `update_file`. `CODEPRISM_NO_AUTO_INDEX=1` отключает и наблюдатель.
   Изменение `.codeprism.toml` применяется после перезапуска сервера.
7. Полное тело функции читать только когда граф не дал ответа.

## Установка и перенос

Установка на этой машине:

```bash
mkdir -p .cursor/tools/codeprism-ai
uv venv .cursor/tools/codeprism-ai/venv
uv pip install --python .cursor/tools/codeprism-ai/venv/bin/python codeprism-ai==0.1.11
```

При включенной фоновой индексации первый запуск сервера строит индекс с учетом
`.codeprism.toml`. Команду
`codeprism index .` для первичной сборки не использовать: она не читает конфиг.

Компоненты текущей установки, которые нужно учитывать при исследовании переноса:

| Файл | Роль |
|---|---|
| `.cursor/mcp.json` | запись `codeprism`, локальный адрес службы проекта |
| `.agents/skills/codeprism/scripts/codeprism-mcp.sh` | stdio-мост к общей службе проекта |
| `.agents/skills/codeprism/scripts/codeprism_serve.py` | обертка сервера, живой наблюдатель |
| `.cursor/tools/codeprism-ai/venv` | окружение 112 МБ, в git не попадает |
| `.agents/skills/codeprism/` | скил, `SKILL.md`, `README.md`, `skill.json` |

`.codeprism.toml` также не переносится: он локальный и добавлен в

## Несколько проектов

Каждый проект обслуживает один HTTP-процесс с собственным портом и индексом.
Несколько клиентов подключаются к этому процессу. CodePrism 0.1.11 хранит один
активный проект на процесс; аргумент `project_path` не переключает базу проекта.
Перенос CodePrism в другой проект еще исследуется. Автоматический перенос не
подтвержден. Существующий генератор готовит unit отдельной службы командой
`python3 .cursor/mcp-stack/add-codeprism.py <project> <port> --output-dir <unit-dir>`.
Целевой проект должен содержать `.cursor/tools/codeprism-ai/venv/bin/python` и
`.agents/skills/codeprism/scripts/codeprism_serve.py`; выходной каталог должен существовать.
Генератор не устанавливает и не запускает службу. Проверить unit, установить
его, выполнить напечатанные генератором команды reload и enable. Порт проекта
задается также в его канонической записи `.cursor/mcp.json`.
Мост `codeprism-mcp.sh` подключается к этой записи и не запускает свой сервер;
ему нужны `uvx` и доступный офлайн пакет `mcp-proxy`.
Процессы, запущенные до перехода через stdio, нужно остановить перед запуском
общего сервера: они не соблюдают блокировку HTTP-сервера и используют ту же базу.

Индекс у каждого проекта свой: SQLite в user-data, имя файла это хеш пути
проекта. Проекты не делят и не перезаписывают граф друг друга. Генератор службы
проверяет наличие окружения и серверной обертки в каждом целевом проекте.

Проверено 2026-11-03: один путь дает один файл, разные пути дают разные файлы.

| Путь | Файл индекса |
|---|---|
| `/home/newuser/projects/copytrust/testdeploydocker` | `0c7b84d86d42e7dd.db` |
| `/tmp` | `e9671acd244849c5.db` |
| `/home/newuser/projects/other` | `0472a9d7d3aac4bf.db` |

Хеш считается от абсолютного пути. Если проект переместить, хеш меняется и
строится новый индекс, старый файл остается сиротой в user-data.

## Обновление индекса

При включенной фоновой индексации индекс обновляется при сохранении файлов.
Служба запускает не `codeprism serve`, а обертку `.agents/skills/codeprism/scripts/codeprism_serve.py`.
Обертка поднимает MCP-сервер и после первичной индексации запускает наблюдатель внутри
процесса сервера. Наблюдатель использует тот же граф и то же хранилище, поэтому
результаты инструментов видят сохраненный файл без перезапуска.
При `CODEPRISM_NO_AUTO_INDEX=1` фоновая индексация и наблюдатель не запускаются.

| Что | Значение |
|---|---|
| Задержка после сохранения | около 1-2 с, debounce 800 мс |
| Что наблюдается | только индексируемые расширения: `.php`, `.phtml`, `.js`, `.jsx`, `.mjs`, `.ts`, `.tsx`, `.mts` |
| Что не наблюдается | `vendor`, `node_modules`, `templates_c`, `dist`, `plugins`, `jscalendar-1.0`, `minified`, `i18n`, `lang`, `migrations`, `fixtures`, `*.min.js` |
| Удаление файла | символы удаляются из графа |
| Правка через инструменты CodePrism | обновляет граф сразу, без ожидания |

Что остается вручную:

- изменение `.codeprism.toml` применяется после перезапуска сервера;
- команда `codeprism watch .` не используется: она не читает конфиг и смотрит
  все каталоги;
- инструмент `index_project` не используется: он не читает конфиг и возвращает
  исключенные файлы.

Проверка живой индексации: создать `lib/__CodeprismWatchProbe.php` с классом,
подождать 2 с, `search_symbol` находит класс; удалить файл, подождать 2 с,
`search_symbol` больше не находит. Проверено 2026-11-03.

## Известные проблемы и ограничения

### П-1: Граф дает структуру, не тело функции

- Симптом: `get_context` не содержит реализации.
- Причина: индекс хранит подписи и связи, а не полный исходник.
- Ограничение или решение: тело читать файлом после контекста.
- Файлы: `.agents/skills/codeprism/SKILL.md`.

### П-2: Вызовы связываются по имени, кроме Python

- Симптом: одноименная функция в другом классе попадает в вызывающие.
- Причина: импорты разбираются только для Python.
- Ограничение или решение: для PHP и JS проверять связи через CBM `trace_path`
  или `rg`.
- Файлы: `.cursor/rules/mcp/codeprism.mdc`.

### П-3: Smarty и Markdown не индексируются

- Симптом: `.tpl` и `.md` не находятся в графе.
- Причина: парсеры есть только для языков программирования.
- Ограничение или решение: шаблоны и документация через `multi-search.sh`,
  `rg` и jdocmunch.
- Файлы: `.cursor/mcp.json`.

### П-4: Задержка наблюдателя и исключенные файлы

- Симптом: только что сохраненный файл не виден первые 1-2 с; файл из
  `scripts/plugins` не попадает в граф.
- Причина: наблюдатель ждет стабильности 800 мс; исключенные каталоги не
  наблюдаются.
- Ограничение или решение: для мгновенного результата вызывать `update_file`.
  Для исключенных файлов правка в граф не попадет, это ожидаемо.
- Файлы: `.agents/skills/codeprism/scripts/codeprism_serve.py`, `.codeprism.toml`.

### П-5: Неполное покрытие индекса

- Симптом: `coverage_percent` около 65.
- Причина: часть файлов не относится к поддерживаемым языкам, часть в игноре.
- Ограничение или решение: не считать отсутствие символа в графе
  доказательством его отсутствия в проекте.
- Файлы: `docs/mcp/codeprism.md`.

### П-6: Одноименные проекты

- Симптом: под именем CodePrism на GitHub 68 репозиториев, скилы и правила
  относятся к разным серверам.
- Причина: rustic-ai это Rust-сервер без PHP и без скила, knight22-21 это
  `codeprism-ai` с PHP и скилом, kunolabs это CLI `contextopt`.
- Ограничение или решение: в харнесе закреплен `codeprism-ai`. Разбор остальных:
  `.doc/temp/skil/codeprism/analysis.md`.
- Файлы: `.agents/skills/codeprism/`, `.cursor/mcp.json`.

### П-7: Окружение не переносится через git

- Симптом: после клонирования репозитория сервер не стартует.
- Причина: `.cursor/` исключен из git, venv 112 МБ не коммитится.
- Ограничение или решение: создать окружение командами из раздела установки.
- Файлы: `.agents/skills/codeprism/scripts/codeprism-mcp.sh`.

### П-8: `get_graph_stats` требует `path` на практике

- Симптом: вызов без `path` не выполняет ожидаемую проверку графа.
- Причина: инструмент ожидает `path`, но в схеме поле помечено необязательным.
- Ограничение или решение: всегда передавать `path="."` или путь проекта.
- Файлы: `.agents/skills/codeprism/SKILL.md`, `.cursor/rules/mcp/codeprism.mdc`.

### П-9: Security gate работает по шаблонам

- Симптом: ключ формата AWS получает `BLOCK`, произвольная строка
  `sk-EXAMPLE` (не ключ) проходит как `PASS`.
- Причина: детекторы ищут известные форматы, а не доказывают безопасность.
- Ограничение или решение: `PASS` означает, что известный шаблон не найден.
  Это не доказательство безопасности, финальную проверку делать semgrep.
- Файлы: `.agents/skills/codeprism/SKILL.md`.

### П-10: `index_project` и CLI не читают `.codeprism.toml`

- Симптом: после `codeprism index .` или вызова `index_project` в графе снова
  2625 файлов, миграции и плагины вернулись.
- Причина: в версии 0.1.11 конфиг читает только `serve` при старте. CLI `index`
  и MCP-инструмент `index_project` собирают конфиг из флагов и берут значения по
  умолчанию.
- Ограничение или решение: для применения `.codeprism.toml` перезапускать
  сервер, он перестроит индекс инкрементально и удалит исключенные файлы. Для
  одной правки использовать `update_file`. `index_project` не вызывать.
- Файлы: `.codeprism.toml`, `.agents/skills/codeprism/scripts/codeprism-mcp.sh`.

### П-11: Embeddings падают на этом проекте

- Симптом: при `enable_embeddings = true` сборка завершается ошибкой
  `chromadb.errors.DuplicateIDError: Expected IDs to be unique, found 170
  duplicated IDs`. Векторный индекс остается пустым, `search_symbol` возвращает
  пустой список.
- Причина: у 170 символов совпадает `symbol_id`, а Chroma требует уникальные ID
  в одном upsert. Ошибка не перехватывается, индексация обрывается.
- Дополнительно: при включенных embeddings `search_symbol` перестает искать по
  подстроке и работает только семантически, поэтому точное имя класса может не
  найтись.
- Ограничение или решение: оставить `enable_embeddings = false`. Включать только
  после исправления в новой версии пакета и повторной проверки.
- Файлы: `.codeprism.toml`, `.agents/skills/codeprism/SKILL.md`.
