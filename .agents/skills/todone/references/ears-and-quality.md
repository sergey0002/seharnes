# Качество формулировки

Пиши наблюдаемое условие и проверяемый результат. Разделяй проблему, цель,
изменение, границы, критерий и способ проверки.

Хороший `AC-N` отвечает на три вопроса:

1. какое поведение должно быть видно;
2. чем его проверить (команда, файл, наблюдение);
3. что считается `met`, `not_met` или `blocked`.

Не заменяй смысл числовой квотой текста. Код проверяет только наличие, тип,
enum, pattern и объявленные гейты; достаточность формулировки решает человек.

```bash
ttask set T-001 \
  --acceptance «python3 -m unittest discover возвращает 0» \
  --acceptance «в docs/ описан новый режим» \
  --verify «python3 -m unittest discover todone/tests» --by lead
```

Перед закрытием свяжи каждый `AC-N` с `report.acceptance_status` и evidence.
