# Документация `todone`

**Срез:** реализованное ядро v0.7. **Язык:** русский. **Источник поведения:**
`../scripts/tdcore/`, три точки входа и их приёмочные тесты. Этот каталог описывает
только то, что уже есть в поставке; планы и сравнительный материал находятся
вне runtime-документации. Имена `v6` в путях примера и тестов — внутренние имена
репозитория, а не отдельный legacy-режим или дополнительный CLI.

## Как читать

1. Для установки и требований открой [Установку](00-installation.md).
2. Для первого запуска используй [Быстрый старт](00-quick-start.md).
3. Если нужно понять идею — начни с [обзора](01-overview.md).
4. Если нужно пройти полный рабочий путь — открой [жизненный цикл](02-lifecycle.md)
   и [рецепты](15-cookbook.md).
5. Если нужно знать, где лежат данные, — читай [модель данных](03-data-model.md),
   [очереди](08-queues.md) и [папки проекта](17-project-folders.md).
6. Если нужен конкретный вызов — смотри [CLI](04-cli.md) и
   `python3 todone/scripts/<точка> --help`.
7. Для documentation workspace и локального catalog/resolver смотри
   [агрегацию](18-aggregation.md); для recursive aggregate — тот же документ.
8. Для conversational task intake и аудита смотри [постановку задачи](19-task-intake.md).
9. Если нужно проверить проект — смотри [валидацию](05-validation.md) и
   [doctor](12-doctor.md).
10. Если нужен deterministic bundle, offline HTML, Markdown preservation, parity или reconstruction — читай [autodoc](20-autodoc.md).
11. Если нужно найти любой файл — используй [полную карту файлов](13-file-map.md).

## Три правила, которые нельзя нарушать

- **Одна запись — один дом.** Источник правды —
  `data/T-NNN-тип/task.json`; `index.json` содержит только ссылки, мета и состояние
  потока.
- **Поток — не второе хранилище.** В `flows/<имя>/flow.json` лежит определение
  шагов; фактические записи остаются обычными записями очереди, а `flow`,
  `flow_step`, `flow_run`, `flow_item` и `flow_revision` живут в строках индекса.
- **Зеркало — только импорт.** Внешний вход хранится дословно в `source.raw` записи
  типа `mirror`. Служебная работа идёт в дочерней `intake`, а не редактированием
  зеркала.

## Область поставки

Реализованы: JSON-записи, производный индекс, реестр очередей, 14 типов, 4 потока,
локальный импорт из файла, Jira-MIRROR-1 projection, комментарии, указатели,
артефакты, evidence, digest, отчёты закрытия, роли, привязки capabilities,
проверки, массовые операции, древовидные связи, общий контракт ошибок,
documentation workspace/catalog/resolver с policy, stale/render checks и
настраиваемым `DOC-PATH-1` root pointer, а также read-only recursive aggregate
с namespace/provenance/snapshots. Не реализованы
намеренно: сетевые Jira API-клиенты, export/import внешних bundle-профилей,
миграция старой task-раскладки и `todoc_scan`.
