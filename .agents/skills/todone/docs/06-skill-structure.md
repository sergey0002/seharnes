# Структура поставки

Папка `todone/` — самодостаточный навык: маршрутизатор, процедуры,
справочники, JSON-плагины, код, шаблоны, пример и тесты. Данные конкретного
проекта не смешиваются с кодом поставки.

```text
todone/
├── SKILL.md                 # короткий маршрутизатор для агента
├── docs/                    # подробное объяснение реализованной архитектуры
├── references/              # справочники полей, схем, ролей, ловушек
│   └── child-skills/        # процедуры по одному рабочему намерению
├── assets/                  # данные поставки (типы, потоки, схемы, шаблоны, примеры, фикстуры)
│   ├── types/               # типы-записи: type.json + instruction + agents
│   ├── flows/               # потоки: flow.json + instruction.md
│   ├── schemas/             # версионированные машинные схемы
│   ├── templates/           # стартовые JSON-формы
│   ├── examples/            # примеры проектов
│   │   └── v6-project/      # чистый fixture-проект для doctor и тестов
│   └── fixtures/            # валидные/негативные фикстуры для тестов
├── scripts/
│   ├── tqueue.py            # точка входа очереди
│   ├── ttask.py             # точка входа записи
│   ├── tcheck.py            # точка входа контроля
│   └── tdcore/              # объектное ядро по ответственностям
└── tests/                   # приёмочные тесты новой раскладки
```

> **Важно:** в поставке каталог данных лежит в `assets/`; в документации пути к типам, потокам, схемам, шаблонам, примерам и фикстурам указаны относительно корня данных (`assets/`). В проекте данные лежат в `<root>/.todone/` и `<root>/types|flows`.

## Точки входа и ядро

Три верхних Python-файла намеренно тонкие: они добавляют `scripts/` в путь,
выбирают класс CLI и вызывают общий `main`. Всё существенное живёт в `tdcore`.

| Модуль | Ответственность | Когда читать |
|---|---|---|
| `schema.py` | ключи, enum, regex, настройки, пороги | при изменении JSON-контракта |
| `errors.py` | коды возврата, `Issue`, подсказки | при добавлении новой находки |
| `record.py` | объект записи, комментарии, refs, artifacts, размеры, TASK-6 | при работе с телом записи |
| `store.py` | папка data, id, чтение и атомарная запись | при изменении файлов записи |
| `index.py` | INDEX-1, строки, сортировка, sync и flow state | при изменении очереди/индекса |
| `queue.py` | реестр, разрешение очереди, paths, settings | при изменении project/queue layout |
| `typedefs.py` | загрузка 14 типов и их объявлений | при добавлении типа или гейта |
| `profile.py` | универсальный профиль и контракт дочернего профиля | когда нужен исполняемый профиль типа |
| `validate.py` | схема записи, extra и гейты фактов | при изменении validate |
| `gates.py` | закрытие по tests/refs/docs/handoff/report | при изменении условий close |
| `checks.py` | CheckPlugin, загрузка и контракт процедурных проверок | при добавлении checks |
| `doctor.py` | сводная диагностика, prose lint, coverage actions | при добавлении диагностического правила |
| `flow.py` | FLOW-1/STEP-1, создание черновиков, state/next | при изменении потоков |
| `link.py` | queue refs, дерево, битые связи | при изменении связей |
| `digest.py` | digest.md, части, stale | при изменении большого чтения |
| `documentation.py` | workspace, DOC-1 modules, catalog/resolver, policy и capture | при изменении документационного домена |
| `brief.py` | sealed packet и AGENT-1 | при изменении субагентов |
| `report.py` | режимы show, строки, размеры, дерево | при изменении вывода |
| `roles.py` | ROLE-1, модели, weakest | при изменении ролей |
| `tools.py` | TOOLS-1 и CAPABILITY_UNBOUND | при изменении привязок среды |
| `cli.py` | общие флаги, parser, вывод, ошибки, paths | при изменении протокола CLI |
| `queue_cli.py` | обработчики `tqueue` | при изменении очереди как порядка |
| `task_cli.py` | обработчики `ttask` | при изменении работы с записью |
| `check_cli.py` | обработчики `tcheck`, SCHEMAS и nested flags | при изменении контроля |

Подробная строка для каждого файла поставки находится в
[13-file-map.md](13-file-map.md). Она не заменяет исходный код: это карта
назначения, причины существования и способа использования.

## Тип как плагин

Тип — папка `types/<type-id>/`:

```text
type.json                 # данные: gates, fields, capabilities, editor…
instruction.md            # процедура типа и запасной путь
agents/*.json             # optional AGENT-1 sealed return contracts
checks/*.py               # optional CheckPlugin modules
profile.py                # optional profile, если объявлен
references/*.md           # optional длинные справочники типа
```

Загрузка типа сначала знает встроенное объявление ядра, затем читает JSON-плагин;
`TypeIndex` и `tcheck types show` дают разрешённое состояние. Новую форму не
нужно зашивать в `task_cli.py`: добавляется JSON, инструкция и при необходимости
проверка с контрактом.

## Поток как плагин

Поток — папка `flows/<flow-id>/` с `flow.json` и `instruction.md`. JSON описывает
вход, порядок/зависимости шагов, тип каждой записи, исполнителя, параллельность,
опциональность, выход и гейт. Markdown объясняет одинаковые правила исполнения.

Во время работы `FlowState` создаёт обычные `task.json`; `index.set_flow` добавляет
`flow`, `flow_step`, `flow_run`, `flow_item` и `flow_revision` в строку индекса.
Никакого `state.json` потока нет.

## Шаблоны

`templates/` не является runtime-хранилищем. Он нужен для ознакомления и
старта проекта: `task.json`, `index.json`, `queues.json`, `report.json`,
`roles.json`, `tools.json`, `flow.json`, `type.json`. Реальные изменения выполняют
CLI, поэтому шаблон не заменяет валидацию.

## Пример и тесты

`examples/v6-project` — внутренне именованный fixture-проект; он содержит только project-level `roles.json` и `tools.json`,
достаточные для строгого doctor. Он специально не содержит задач: тесты создают
временные очереди сами, не загрязняя поставку.

`tests/test_v6_core.py` проверяет объектные классы, `test_v6_cli.py` — три CLI и
сквозные сценарии, `test_v6_matrix.py` — таблицу схем, типов, потоков, режимов и
кодов. Имена `v6` — внутреннее имя набора тестов/раскладки в репозитории,
а не отдельная точка входа или режим CLI.
