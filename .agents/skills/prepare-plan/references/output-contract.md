# Output contract

План это авторский Markdown. Единый скелет: [plan.template.md](../assets/plan.template.md).
Метаданные: [plan.meta.schema.json](../assets/plan.meta.schema.json). Блок meta
следует стандарту документации проекта: `type`, `status`, `updated`, `related`,
`tags`, затем ключи плана. Проверку и правку выполняет `audit-plan`, отдельного
файла аудита нет.

## Required sections (plan.md)

- Context, Diff principle (N равно числу файлов патчей), `scope_size`;
- Problem;
- **Sources of truth** — T-id таблица (`brief|comment|user|arch|schema|code|db|test-canon`),
  относительные ссылки, `file:line` для кода;
- **Acceptance criteria** — AC-ID, источник T, закрывает R, тест S;
- **Related tasks** — ссылка на `task.md` у каждого упомянутого номера;
  `none: not exported`, если файла нет;
- As-is: инвентарь точек входа P2.7, IN/OUT для общего кода, инварианты,
  `docs != code`, доменные документы и связанные задачи, история правок;
- **Research audit (MCP)** — таблица уровней 0-8 с инструментом, находкой или
  явной компенсацией;
- To-be;
- Options и **Architecture check (P4.1)**; для Trivial только вариант A;
- **Decomposition** — R и S с литеральным результатом;
- **`## Правки по файлам`** — Before/After, у каждого файла `R` и `Verified by`;
- Files summary и намеренно не тронутые файлы;
- Coverage matrix с теми же AC-ID;
- Verification checklist: успех, отмена, ошибка, недоступность, OUT-вызывающие;
- Risks and rollback;
- **`## Самопроверка (P5)`** — результат `self-check.md`, без выдуманных галочек;
- **`## Аудит плана`** — журнал проходов; появляется после первого аудита;
- History: при повторной правке что изменилось и что пропустил прошлый проход.

Пустая необязательная секция: одна строка `N/A`, без выдуманного содержания.

## Handoff to audit-plan

Автор оставляет:

```text
status: draft
audit_status: pending
plan_rev: 1
audit_passes: 0
last_audit: none
```

Аудит правит план и выставляет по итогу прохода:

```text
status: ready | draft
audit_status: passed | failed | blocked
plan_rev: <не меняет>
audit_passes: <число проходов>
last_audit: YYYY-MM-DD
```

Метки правок и журнал живут внутри `plan.md`. Отдельный `plan-audit.md`,
`plan_hash` и таблицы хешей источников не создаются.

## Quality bar

- каждое изменение опирается на чтение файла целиком;
- каждое допущение помечено;
- у рискованного шага есть откат;
- Diff principle N не врет;
- общий код имеет IN/OUT и предпочитает opt-in, а не смену поведения по умолчанию;
- у каждой причины R есть сценарий S с литеральным результатом;
- каждый AC, R и S ссылается на существующий T-id;
- каждый связанный номер задачи имеет ссылку на `task.md` или `none: not exported`;
- двусмысленность исполнителя равна нулю: Before уникален, After вставляется,
  решения не оставлены исполнителю;
- форма плана соответствует размеру задачи, без ритуальной декомпозиции;
- `test.md` с матрицей требований и веток существует или помечен `N/A` с причиной;
- каждая правка аудита помечена номером прохода и датой.

## Text style

Простой русский язык, короткие предложения. Без длинных тире, французских
кавычек и эмодзи в прозе плана. Код, логи и цитаты `task.md` остаются как в
источнике. Правило проекта задается через `ADAPTERS.local.md`.
