# Quality criteria

Критерии автора плана. Независимый аудит, правки и журнал проходов выполняет
`audit-plan` по своим критериям C1-C6, этот файл их не дублирует.

| # | Критерий | Как проверить |
|---|-----------|----------------|
| Q1 | Конкретные патчи | реальные блоки Before/After |
| Q2 | Свежие строки | Before из чтения файла целиком в этой сессии |
| Q3 | Минимальный дифф | клоны и вторые точки входа не выброшены |
| Q4 | Полное покрытие | To-be, точки входа P2.7 и все AC брифа |
| Q5 | Доказанная причина | as-is `file:line` из чтения, не из документации |
| Q6 | Согласованность | смежные файлы прочитаны целиком |
| Q7 | Радиус | лестница `blast-radius.md`, вызывающие прочитаны, ключи общего кода в IN/OUT |
| Q8 | Проверяемость | у каждой R есть S с литеральным результатом, синтаксис не считается |
| Q9 | Откат | риски и способ отмены записаны |
| Q10 | Границы | не тронутые файлы обоснованы чтением |
| Q11 | Регрессии | Before/After для каждой точки входа P2.7 |
| Q12 | Повторное использование | похожее решение в репозитории найдено и названо |
| Q13 | Конец файла | поздние чтения измененной переменной учтены |
| Q14 | Документация | домен через индекс, связанные задачи через скрипт |
| Q15 | Документация не равна коду | расхождение записано, as-is из кода |
| Q16 | Общий код | opt-in или принятое влияние на OUT, таблица IN/OUT |
| Q17 | Инварианты | контракты прошлых задач сохранены в After |
| Q18 | Метаданные | Diff principle N равно числу файлов патчей |
| Q19 | UI отмена и ошибка | успех, отмена, ошибка и недоступность разобраны |
| Q20 | Ноль двусмысленности | Before уникален, After вставляется, решений исполнителю не осталось |
| Q21 | Тестируемая декомпозиция | у каждой R есть S с предусловием, действием и литеральным результатом |
| Q22 | Git-история | git-task-blame пройден по каждому файлу с историей |
| Q23 | Архитектура | P4.1 записан для варианта, повторное использование обосновано |
| Q24 | Классификация риска | уровень P1.2 записан рядом с каждым файлом |
| Q25 | Закрытие задачи | все in-scope AC связаны с патчем и шагом проверки |
| Q26 | Пропорциональность | `scope_size` записан, R считает причины, а не шаги редактора |
| Q27 | Источники истины | таблица T-id, все ссылки открываются |
| Q28 | Идентификаторы AC | совпадают в Acceptance criteria и Coverage matrix |
| Q29 | Документы связанных задач | каждый номер имеет ссылку на `task.md` или `none: not exported` |

## Матрица требований и веток

До передачи в аудит автор обновляет соседний `test.md`. Матрица включает:

- критерии брифа и последние комментарии;
- Verification checklist плана и случаи OUT;
- явные условия пользователя, включая переданные от тимлида или QA; такие строки
  помечаются источником `user-extra` и не сливаются молча с текстом брифа.

Те же AC-ID, R и S из плана используются в матрице. Каждая строка имеет AC-ID,
литеральный ожидаемый результат, слой теста и метод или явное ручное ограничение.

Для UI и общего кода план называет будущий метод `@group task-{N}` и затронутые
соседние потоки. Для расчетов, SQL, статусов, прав и интеграций называется
PHPUnit или интеграционная проверка раньше браузерной.

Нарушения, неизвестная свежесть комментариев, отсутствие ожидаемого результата и
непокрытые строки не дают передавать план как готовый.

## Порядок проверки

1. Автор проходит `self-check.md`.
2. Пользователь или автор запускает `audit-plan`.
3. `audit-plan` правит план на месте, ставит метки прохода и журнал.
   `status: ready` появляется после вердикта `pass`.
4. Исполнение сценариев после реализации выполняет `test-task`, а не этот скил.
