## Step P2 — Research: tools → Read whole files (required)

### 2.0 Hard order

```
1. Docs: домен через индекс, затем jdocmunch по корпусу
2. Tools: граф, вызовы, символы, полный текст
3. Read: файл целиком, не окно ±30 строк
4. Только затем as-is, причина, Before
```

Запрещено:

- брать Before из сниппета MCP или удаленного просмотра без чтения файла целиком;
- планировать по окну ±30 или ±50 строк;
- считать радиус закрытым без чтения вызывающих;
- искать документацию обходом `.doc` вместо `jdocmunch`.

### 2.1 Документация

1. Определить корпус вопроса: задача, архитектура, харнес, MCP, панель.
2. Вызвать `search_sections` с `repo=local/testdeploy-arch` и `path_glob`.
3. Открыть найденный раздел через `get_section_context` или `get_section`.
4. Перед большим документом взять `get_document_outline`.
5. Прямое чтение известного пути допустимо после поиска по тому же корпусу или
   когда путь уже известен из `task.md`.
6. Пустой поиск проверить через `get_index_overview` и `get_recent_changes`.
   Обновление индекса требует разрешения пользователя.

Корпуса и точные команды: `ADAPTERS.local.md`.

### 2.2 MCP navigation

| Вопрос | Инструмент | Что берет |
|---|---|---|
| Кто вызывает символ | codebase-memory-mcp | `search_graph`, `trace_path` |
| Исходник и связи в PHP, JS, TS | codegraph, codeprism | `codegraph_explore`; `get_context`, `get_callers`, `get_impact` |
| Реальный граф вызовов PHP | php-deps-mcp | `phpda_analyze`, `phpcallgraph_generate` |
| Определение и ссылки символа | serena | `find_symbol`, `find_referencing_symbols` |
| Шаблоны, строки, клоны, `.tpl` | multi-search, полный текст | `rg` по glob |
| Схема данных | mysql | `describe_table` |
| Внешний SDK или API | context7 | `resolve-library-id`, затем `query-docs` |

Codegraph и codeprism не индексируют Markdown, `.doc` и Smarty. Для этих файлов
работает только поиск по тексту.

### 2.3 Code reading (whole file)

Для каждого файла патчей, цепочки as-is и вызывающих из радиуса:

1. Читать файл целиком. Если файл больше примерно 800 строк, читать
   последовательными кусками без пропусков, покрывая модуль или класс.
2. Записать реальные номера строк для Before.
3. Если After меняет локальную переменную, найти все поздние чтения этого имени
   в том же файле.
4. Для UI читать целиком шаблон и связанный скрипт.

**Политика размера:**

- до 300 строк включительно читать целиком всегда, и на первом проходе, и при
  повторном;
- больше 300 строк читать целиком на первом проходе, затем хранить digest:
  контур символов, диапазоны as-is и выводы;
- при повторной проверке сверять `content_hash`: совпал, digest переиспользуется;
  изменился, файл читается заново;
- digest не заменяет первое чтение целиком и не покрывает файл с устаревшим хешем.

Минимум до P5: все файлы патчей, все точки входа P2.7 и все вызывающие из
радиуса прочитаны целиком.

### 2.4 Data

Если затронута БД, сначала описать схему через `describe_table` или чтение DDL.
Колонки не выдумывать.

### 2.5 History

Для stage2 и регрессии: `git show`, `git blame`, затем чтение текущего файла.
Историю строк ведет скил `git-task-blame`, а не свободный пересказ.

### 2.6 External docs

Документация сторонних SDK нужна только для внешних API. Сначала проверить факт
версии на месте: `class_exists`, `method_exists`, вызов фабрики. Читать исходник
зависимости только если проверка не дала ответа. Записать команду и вывод.

### 2.7 Entry-point inventory

Для HTTP, задач, вебхуков и многопровайдерных потоков собрать полный набор
точек входа, а не только счастливый путь из брифа.

```
□ Документация: маршруты, модули, legacy-пути
□ Поиск: одноименные обработчики у разных провайдеров
□ Роутер и реестр задач: все слаги и идентификаторы контура, включая legacy
□ Общий помощник: кто еще его вызывает, какие ключи различают смысл
□ Явно исключить чужие ключи общего помощника
□ Каждый найденный файл прочитать целиком
```

Инвентарь записывается в план, одна строка на точку входа:

```
entry: POST /api/v2/resource → ControllerV2::create
entry: POST /legacy/resource → LegacyController::create
entry: webhook ProviderX → Service::onSuccess → SharedCommand::execute (key=A)
shared: Helper::calculate() ← feature A AND feature B (разный смысл)
```

Без списка для HTTP, задач и вебхуков план не передается в аудит.

### 2.8 Shared mutation gate

Общий модуль это компонент, помощник, базовый класс, middleware или шаблон,
который включают две и более точки входа разных функций.

Перед предложением изменить поведение по умолчанию:

```
□ Найти всех вызывающих через ссылки и поиск
□ Каждого вызывающего прочитать целиком или прочитать его файл связки
□ Таблица в плане: вызывающий, функция, IN (поведение меняется), OUT (должно остаться)
□ Критерии брифа покрывают только набор F?
    → предпочесть opt-in через параметр, флаг или ветку для F
    → смена поведения по умолчанию требует покрытия OUT в брифе или согласия пользователя
□ Проверка: хотя бы один шаг регрессии на каждого OUT или явное N/A с причиной
□ Двухшаговые потоки: назвать, какой шаг меняет деньги или состояние
```

План без таблицы IN/OUT для общего кода не готов. Молчаливая смена поведения
OUT-вызывающих запрещена.

Если инструменты ссылок недоступны, поиск по имени символа и шаблонам обязателен
до передачи плана.

### 2.9 UI control and cancel path

Для каждого интерактивного элемента в рампах задачи:

```
□ Прочитать шаблон и скрипт целиком: привязки, disabled, preventDefault
□ Смоделировать успех, отмену, ошибку, недоступность
□ После отмены понять, нужен ли явный откат или состояние выводится из источника
□ Записать в план, отмена уже безопасна или After должен ее сбрасывать
```
